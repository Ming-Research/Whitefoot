Fresh-element placement: append ordering trial

Purpose: reproduce the registered fresh-element placement discriminator; retire
with superseding append qualification. Sole API: Vector append, concrete i64 and
{[32 x i64]} integral payloads. No production compiler/library/specification change,
pointer-bearing relocation rule, effectful-constructor rule or policy is selected.
Dependencies: full-growth-route.patch and ecosystem-append-growth-full-route-timing.txt
reconstruct B and its frozen compiler/object inputs. The compiler executable stays
transient; production compiler output is not interchangeable with that overlay.

Control and change
B's raw timed/account modules first undergo the recorded extra -O3 LLVM-emission
pass. Both optimized controls are compiled and linked, separately from candidates.
The patch changes exactly two reached append definitions per optimized module;
all other definitions remain byte-identical. Within each changed definition,
copy the existing integral construction/stores into both full-positive success
blocks (doubling and saturated capacity), after successful allocation and before
prefix memcpy. Their target is fresh + old_length*stride, disjoint from the old
prefix. Both routes bypass the common construction block and join final length
publication. Empty/spare paths keep the common block. Three static construction
copies therefore produce exactly one runtime new-element write per taken path;
this is code duplication, not double construction of a value. Existing proof/alias
metadata is transported with the existing operations; no new runtime comparison,
allocator/copy call or separate source rule is introduced.

stores now precede memcpy; neither width adds q-register stack payload spills,
helper/library calls or executed conditionals. The ordinary 80-byte frame remains.
Extra construction code and optimizer consequences belong to the experiment.
