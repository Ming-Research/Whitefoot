Decision: A counted loop admits at most one accumulator from a fixed associative set and enclosing accesses through one proved constant-coefficient affine element map per resolved root, an access being any write, read or borrowed argument whose place is at or below the mapped element through fields, payloads, cell contents, further subscripts and ranges, or through disjoint subranges of an adjacent stride partition with invariant runtime stride and base, consuming retained source proofs, because reductions and [range helpers](https://github.com/mbbill/Whitefoot/blob/b3341e32ab8d69e2974227aee7146ac16eb2fe00/research/investigations/range-loans/DESIGN.md#counted-loop-permission) expose useful independence without depending on worker count, and everything below one element is storage that element alone owns, aggregates holding only owned values and a cell having one owner, so a loop that writes a field of its own item, hands its item to a writing helper or fills a buffer its item owns is as independent as one that replaces the whole item ([segmented storage](../../../research/investigations/segmented-storage/DESIGN.md#selected-design)), instead of unproved scatter, unbounded multi-accumulator reductions, restricting writes to element maps, or an element family of direct subscripts only. Whole-source access to mapped or assigned storage and incompatible maps on overlapping storage deny permission.

Decision: A counted loop may also carry an `apart(i, j) { use ...; }` certificate, which the range judgment checks by executing the body for two distinct iterations from the loop's entry state and proving every element write of one disjoint from every element access of the other; a holding certificate makes those writes a further admitted family of the counted judgment, whose reads of the written storage must be the certificate's own, because a scatter through a proved left inverse or a proved level, as a cascade writing each element of one tree level at its document index, is independent although no affine map describes it ([derivation](../../../research/investigations/unique-keys/POINTWISE.md)), instead of extending the affine family by an injectivity search or leaving scatter loops sequential.

Decision: A certificate that does not hold rejects the program, while one that holds grants nothing beyond its family, so the loop's permission is still the counted judgment's verdict, because the writer asked for a proof explicitly and a certificate that silently fails hides a wrong proof, as a failing local invariant would, whereas a permission refused for another reason, such as an exit edge, is the ledger's report as for every loop, instead of falling back to sequential execution when the certificate fails or making the certificate a checked assertion of permission, which the refused `mustpar` was.

Decision: An iteration passes its storage partition as an ordinary range-reference argument and uses the shared path-overlap judgment for cross-iteration separation, because the same half-open range proof can serve calls, adjacent statements and iterations, instead of a loop-specific exclusive view and loan mechanism.

Rejected:
- Exclusive view descriptors for iteration partitions: rejected because ordinary range references carry the same partition and use the common separation judgment without another permission or lifetime mechanism.
- An element family of direct subscripts only: rejected because a loop that writes one field of its own element, `set a^[i].n = i`, or passes its element to a writing helper was denied although it writes only element i, which made Snowghost's layout prototype keep per-item results in separate arrays.
- Admitting field paths and element borrows but not paths through an element's cells: rejected because buffers owned by their items are common in a renderer, and a cell's single owner already separates them.
- Falling back to sequential execution when a certificate fails: rejected because the writer wrote the certificate to have its proof checked, and a fallback would leave a wrong proof unreported.
