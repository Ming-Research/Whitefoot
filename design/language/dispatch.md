Decision: The kernel has no function values and no dynamic call dispatch; exhaustive match selects source arms by a closed sum's variant or an integer's constant value, and every call in an arm still has a statically known callee, because selecting a data value does not obscure the callee's exact effect row, ownership discipline or per-call proof obligations, instead of trait objects, vtables, or closures with captured environments.

Decision: Integer constant dispatch uses match for all eight signed and unsigned integer types, including concrete instances of an Int-bound parameter, while Bool keeps if, because an integer command code has a finite exact equality domain and Firn's command dispatcher needs that selection without a chain of roughly 130 equality tests, instead of an enum conversion, a u64-only command special case, or a new switch spelling that names a lowering mechanism rather than the checked selection.

Decision: An integer arm label is an existing typed integer literal, character literals and generic zero and one included, or an IDENT resolving to a named const item of the exact scrutinee type; labels are distinct by decoded mathematical value, because the existing lexical classes distinguish these labels from a TYPEID variant with parentheses without name-dependent parsing and aliases must not select the same value twice, instead of arbitrary expressions, runtime bindings, symbolic const-generic labels, implicit conversions or duplicate labels resolved by source order.

Decision: Every integer match contains a value arm, and a partial listing ends in exactly one else arm while a listing of the whole integer type has none, because else already names a remaining alternative, a fallback has a selectable value exactly when the listing is partial, and an else-only match performs no selection, instead of a wildcard spelling, an optional partial fallback, a fallback in the middle, or an unreachable fallback after complete coverage. Completeness counts distinct well-typed values against the type's exact cardinality, independently of incoming proof facts, so a guarded subset does not silently change which source arms must be written.

Decision: The first integer-match amendment admits one constant value per arm and no ranges or grouped labels, because this is the complete selection needed by the chosen command-dispatch witness and leaves no overlap, precedence or multiple-entry meaning to resolve, instead of range labels or a | union whose additional expressiveness has no witness in this task; reopen when a real dispatch requires those forms.

Decision: Statement match and value-initializer match share the integer arms and coverage judgment, with value delivery governed by the existing give rule, because the selection is independent of whether the selected block transfers control or delivers a value, instead of a statement-only feature that forces value-producing dispatch into mutable temporaries.

Decision: An integer scrutinee is evaluated once and its arms are selected by equality without sequential guard evaluation; the language does not prescribe a backend instruction, because this gives an LLVM switch a direct semantics-preserving implementation without making a backend strategy observable or requiring a particular jump-table density, instead of defining integer match as an if-chain or promising a measured speedup before implementation.

Rejected:
- Keeping match enum-only: rejected because a numeric command code already carries the dispatch identity, and wrapping it in an enum or repeating equality guards conceals the missing integer selection rather than addressing it.
- Giving Bool integer arms or a second enum match spelling: rejected because Bool already has its complete conditional form in if and this task supplies no distinct Boolean selection requirement.
- A bare variant label sharing the IDENT form: rejected because the existing TYPEID-with-parentheses form separates variant labels from constant names lexically and keeps payload binding explicit.
- Accepting an exhaustive listing plus else: rejected because its fallback can select no integer value and would provide two source forms for complete coverage.
- Exhaustiveness relative to the entering proof interval: rejected because coverage would then depend on unrelated proof edits rather than the scrutinee's declared type.
