Decision: The kernel owns the storage shapes together with exactly those operations that move a window boundary, relocate the slots below one, exchange the value held in an owned place, or change a runtime capacity, namely appending and taking at an end, inserting and removing at an index, moving all of one window into another or splitting one into two, growing a heap-resident contiguous or paged prefix window, setting at a subscript, swapping two places, and the in-place update that hands a place's value to a function and commits the result, while growth policy, pools, arenas, keyed tables, clearing, truncation, replacing while keeping the old value, swap-remove, deques, and strings begin as source libraries whose costs are checked against the same native operation contract, because those kernel operations provide the authority source needs to preserve initialized storage but composition alone does not establish equal cost, as the [ordered Vector consumption comparison](https://github.com/mbbill/Whitefoot/blob/34ede1dedd278652ce153452fc305caf241c45c0/research/experiments/container-representation/vector-library/RESULTS.md#lowering-attribution) distinguishes extra source-required movement from lowering costs, instead of a kernel container per policy or a blanket claim that every library composition has no extra runtime cost.

Decision: The kernel owns Paged and grow_paged because source page storage cannot supply one-level element places to the shared bounds, range, overlap and parallel-permission rules, as the [flat-slot probe](../../../research/investigations/paged-storage/DESIGN.md#evidence-from-snowghosts-probes) demonstrates, instead of assigning page storage to a library and adding quotient-and-remainder separation to every place consumer. Occupancy, deletion markers and growth policy remain source responsibilities.

Rejected:
- A source-library swap, insertion, or middle removal written over the same storage: rejected because each requires moving a value out of a slot, which the language does not admit, so each must be one kernel relocation that leaves no slot empty at any program point.
- A kernel container per policy, such as a growable vector, a pool, a keyed table, or a string: rejected because the storage operations supply the authority needed for memory safety while growth, recycling and occupancy policy belong to the program; a measured gap can reopen a particular operation or representation without requiring a kernel container for each policy.
- Treating the kernel's storage transitions as ordinary source functions: rejected because their contracts relate measures that only the storage itself can change, so a source body could neither establish them nor be checked against them.
- Treating safe source composition as proof of equal runtime cost: rejected because ordered prefix-window consumption needs additional element transfers with the current operations; a measured gap can reopen the relevant representation or operation without adding a kernel container per policy.
