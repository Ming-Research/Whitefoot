Decision: The owning HashMap stores each pair in an enum slot and inserts or replaces it through the shared exchange helper, because the [matched comparison](https://github.com/mbbill/Whitefoot/blob/20f3b4d618fd64eff245a5b5e7a5162483f94c0b/research/experiments/container-representation/map-library/RESULTS.md#constant-interface-comparison-and-selected-helper-body) preserves must-consume pairs without enlarging every slot, instead of per-slot windows. The occupancy-only migration into a fresh backing that the same comparison selected for linear probing is retired with linear probing: growth now extends the slot array in place and moves no owner.

Decision: HashMap insertion returns either a payload-free success or one shared pair payload with a replacement/refusal reason, because the [source comparison](https://github.com/mbbill/Whitefoot/blob/20f3b4d618fd64eff245a5b5e7a5162483f94c0b/research/experiments/container-representation/map-library/RESULTS.md#compact-result-boundary-control) establishes a smaller wide result and lower replacement/churn cost, instead of reserving separate storage for mutually exclusive returned pairs. This accepts a second match and a larger zero-sized result; it selects neither compiler union layout nor fewer transfers on every path.

Decision: HashMap keeps its pairs in a slot array with a free list and reaches them through chains: a power-of-two array of chain heads is indexed by the top bits of the key's hash after one odd multiplication, so a key's chain depends only on its own hash and the bucket count, and a resumable scan whose cursor is a position in that hash space reports every pair present throughout a pass across insertions, removals, growth and rehash, because the [hash-scan study](../../../research/investigations/hash-scan/DESIGN.md#why-a-physical-bucket-cursor-is-insufficient-for-todays-linear-probing) shows that linear probing, whose rebuild repositions keys relative to any physical cursor, loses such pairs, instead of linear probing with a physical cursor or a stable-identifier directory. Capacity now counts slots for pairs, a pair stays in its slot while it stays in the map, growth appends slots and rebuilds only the head array, and a rebuild moves words, never owners. This accepts one link word per slot, up to two head words per slot, and two more backings per map, and no twin-controlled timing against the linear-probing table exists yet: it is provisional until the idle-machine comparison, and the stable-identifier directory stays the fallback for any measured regression.

Decision: An insertion into a map whose slots are all taken first doubles its capacity, from none to one, saturating at the ceiling, because a chain needs only a free slot, so the filled-and-vacated count that linear probing needed no longer bounds a walk, instead of rebuilding at three quarters; removal returns its slot to the free list, so removal and insertion at a stable size never grow the map. A map at its ceiling refuses an insertion that finds no slot and returns the offered pair.

Decision: A scan's limit counts home buckets and a call lends each visited bucket's whole chain, so one call can lend more than limit pairs when keys share a home, because Redis 7.2.16's COUNT is the same hint and the [study](../../../research/investigations/hash-scan/DESIGN.md#redis-7216-compatibility-and-the-meaning-of-bounded-work) found its scan tests ask no stricter bound, instead of a cap on pairs, which needs the stable-identifier directory or per-scan state. The [hold criterion](../../../research/investigations/hash-scan/DESIGN.md#hold-criterion-set-before-measurement), set before measurement, decides whether the hint suffices; failing it reopens the cap.

Rejected:
- Migrating every owner into a fresh backing on growth, the linear-probing rebuild: rejected because a key's chain depends only on its hash and the bucket count, not on its slot, so relinking words reaches the same chains without a second live backing or a transfer per owner.
- A physical bucket cursor over linear probing: rejected because a same-capacity rebuild can move an unreported pair behind the cursor.
- Indexing buckets by the low bits of the hash with a reverse-binary cursor, as Valkey does: rejected because the cursor then needs bit-reversal arithmetic across bucket-count changes and hashes whose low bits agree all share one bucket, while the top bits after one odd multiplication depend on every hash bit and leave the cursor a plain position in hash space.
- Restricting capacity itself to powers of two: rejected because it changes the capacity contract, rounding every reservation and every initial capacity given as a member count up to a power of two, while counting slots apart from buckets keeps capacity and ceiling arbitrary.
- Planning destinations and permuting the old backing as the default rebuild: rejected because the direct ordinary protocol preserves must-consume owners with fewer requests and lower measured growth cost; its smaller same-capacity peak remains a reason to reconsider it for a memory-constrained consumer.
- One inline one-slot window in every bucket: rejected because it increases bucket stride without a consistent advantage over the compact enum protocol in the matched rebuild comparison.
- Selecting dense payloads as the universal representation from wide-growth timings: rejected because the separate index and dependent access have different measured costs, and there is no measured application distribution that makes wide growth the governing operation. A concrete consumer can select that tradeoff later.
- Duplicating the exchange inside migration solely to remove its intermediate result: rejected because the constant-interface source control removes that result but does not establish a stable independent timing benefit after accounting for the unchanged C controls; the registered performance criterion was not fully met.
- Keeping separate payload-bearing Replaced and Full variants as the library interface: rejected because their repeated pair storage and inactive-result initialization have a measured wide-value cost that an ordinary shared-payload form avoids without losing an ownership outcome.
- Inferring a compiler-known sparse representation or a universal compact-enum ABI from the result experiment: rejected because changing the public result alone separates this cost from bucket layout, and zero-sized pairs and retained replacement paths still expose tradeoffs.
