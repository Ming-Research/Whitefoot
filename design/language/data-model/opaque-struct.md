Decision: A struct declaration may carry the modifier `opaque`, written before the capability modifier `nocopy` or `nodrop` (`language/ownership/copy-classification`) when a declaration carries both, and an opaque struct has ordinary fields and no usable constructor, a constructor call naming it and a destructuring binding naming it both being rejected, while reading a field, writing a field and moving a field out follow the ordinary struct rules, because a type whose representation belongs to the host or to the compiler should still be declared in the form a writer reads and writes, as the prelude's function rows are written in the contract form a source function uses, and the only thing such a type must withhold is the pair of operations that would make a value or take one apart without the function that knows how, instead of a table of built-in nominal types carried in the specification's prose as declaration notation that no source item could state.

Decision: Every built-in nominal is an opaque struct with a declaration the writer can read: the prelude declares the heap cell `Box<T>` with its single field `inner` and the three storage shapes `Array`, `Slots` and `Ring`, each written with a const capacity parameter and carrying its measures as readonly fields (`language/data-model/readonly-field`), an array a length, a prefix window a length and a capacity, and a ring window a length, a capacity and a head, and the standard library module that owns each host handle declares it with no fields (`language/system-interface/declaration-home`), while the form written by omitting the capacity argument is a rule of the type system over that one declaration rather than a second declaration, because an opaque struct's fields state the interface its holder may read and not the layout the compiler chose, as the cell's field `inner` already names content that lives in a separate heap object, so elements that are slots rather than fields were never an obstacle to declaring a shape, instead of leaving the three shapes as nominal types that no source item declares, listed as built-in notation in the specification's prose.

Decision: A program may write `opaque struct`, and because only a definition the build supplies forms a value of an opaque struct, a construction row forming the prelude's cell and storage shapes and a host function forming a host handle, no value of an opaque struct a program declares is ever formed, an emptiness admitted rather than refused, because a modifier the prelude and the standard library may write and a program may not would restore by the back door the separate system declaration domain the prelude is deliberately not (`language/system-interface/declaration-home`), instead of restricting the modifier to library declarations and reading a declaration's origin to decide whether it is accepted.

Decision: The modifier is admitted on a struct alone and there is no opaque enum, because the types that need it, the cell and the host handles, are products of fields and nothing else in the language asks for the modifier, instead of admitting it on both declaration forms for symmetry.

Rejected:
- Replaced decision, that `Array`, `Slots` and `Ring` stay nominal types no source item declares because no struct head states both capacity forms of one shape or elements that are slots rather than fields: rejected because an opaque struct's fields describe the visible interface and not the layout, the cell's own field `inner` already standing for content held in a separate heap object, so elements outside the field list obstructed nothing, and the constant-capacity and omitted-capacity spellings are two type-system readings of one declaration rather than two declarations a single head would have to carry; its successor is the prelude-declaration decision above.
- Refusing the constructor call while admitting the destructuring binding: rejected because a host handle has no fields, so `let TcpSend() = move s;` would bind nothing and still discharge the must-consume obligation of a linear resource without closing it.
- The spellings `sealed`, `abstract` and `builtin` for the modifier: rejected because the specification already calls these types opaque, so a second word would name a property the reader can already name.
- Replaced clause, that a constructor call and a destructuring binding naming an opaque struct are both rejected with the same instruction to build the value with a construction function: rejected because a construction function forms only the prelude's storage shapes and cell, so the instruction cannot be carried out for a host handle, which only a host function of its module forms, for an opaque struct a program declares, which never has a value, or for any value being taken apart, while the specification asks of every repair that each alternative succeed when carried out and leaves its words to the compiler, which chooses them by where the struct comes from and, for a cell, by its content.
- Replaced clause, that the prelude declares the fourteen host handle types: rejected because the owner's ruling that moved the host declarations into the standard library places each host handle in the module interface that owns it (`language/system-interface/declaration-home`), which this node had not followed.
- Replaced clause, that no function can return a value of a type whose construction the language withholds: rejected because the standard library's host functions return host handles its modules declare as opaque structs, so what leaves a program's own opaque struct without a value is that the build supplies no function a program declares.
