Decision: Retain a fanout-16 B-tree of boxed nodes, with one leading child link and each entry owning its following zero-or-one link, as the reusable ordered-map baseline because the [complete source protocol](https://github.com/mbbill/Whitefoot/blob/1811f2d01a1171312c5acfd5cca634f48927bb90/research/investigations/containers-and-resources/X1-LIBRARY.md#ordered-map-trial-at-v068) handles arbitrary owners through balancing and root consumption without a separate child-count premise. This is a [measured baseline](https://github.com/mbbill/Whitefoot/blob/1811f2d01a1171312c5acfd5cca634f48927bb90/research/experiments/container-representation/ordered-library/RESULTS.md), not a default representation or an optimum over tree shapes.

Decision: The map's tree is private to its module, the root a private field and the node and entry types module-private, with only the logical length published because the public length contract reads it, because the tree is a measured baseline that may change and a published node shape makes every client walk depend on it, instead of publishing the node fields readonly for clients to walk.

Decision: Positioned traversal is an owned cursor holding the path of child and entry indices from the root and the map's version, which each insertion and removal advances, made at the first or last pair or by a seek to the first pair at or after or after a probe or the last at or before or before it under a caller-supplied monotone placement, moved one pair in either direction and read by lending its pair to a callback, because a value cannot hold a reference to the map and a caller-held position keeps the loop in the caller, where one step can lend its pair to callbacks with different environments and two maps can be walked together ([ordered-map cursor](../../../research/investigations/containers-and-resources/X1-LIBRARY.md#ordered-map-cursor)), instead of a callback walk that stops on a returned flag or successor queries by key. A cursor made before an insertion or removal reads no pair and does not step, since those can move pairs between nodes; an edit or a replacement of a present key keeps it.

Rejected:
- Separate entry and child prefix windows for this bounded comparison: rejected because entry occupancy alone does not supply the child merge-capacity premise; the alternative remains open if its ordinary proof and transfer costs justify the layout.
- A growing indexed pool for this initial comparison: rejected because node ID lookup and backing relocation add another representation change to the balancing experiment; allocation or locality requirements can reopen it.
- Selecting a default ordered tree from allocation count or native AVL alone: rejected because fewer B-tree allocations do not ensure lower reserved bytes or elapsed cost, and the measured native AVL floor does not establish the cost of a complete ordinary WF AVL.
- The tested single-descent insertion with a borrowed pair carrier and aggregate promotion returns: rejected because its [replacement regressions](../../../research/experiments/container-representation/ordered-library/RESULTS.md#single-descent-insertion-candidate) fail the registered criterion despite build gains; aggregate clearing is observed but is not an established dominant cause.
- The tested follow-up borrowing both pair and promotion slots: rejected because its [replacement regressions](../../../research/experiments/container-representation/ordered-library/RESULTS.md#borrowed-promotion-follow-up) persist after recursive aggregate returns are removed; reopening needs attribution of remaining per-put storage, owner movement and frame costs, without rejecting every single-descent design.
- Publishing the node fields readonly as the traversal interface: rejected because every client walk would then be written against the fanout-16 node shape this baseline leaves open to change.
- A callback walk that stops on a returned flag: rejected because its callback has one environment, so a caller that writes two places per pair, such as a range reply that also updates its walk state, must copy each pair out, and it cannot walk two maps together.
- Successor queries by key: rejected because every step compares keys from the root and the caller must copy a key per step to remember its place.
- A cursor that resumes at whatever pair sits at its old path after an insertion or removal: rejected because it can skip or repeat pairs without telling the caller.
