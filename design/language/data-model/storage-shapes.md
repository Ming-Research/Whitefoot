Decision: The storage shapes are a full array, a filled prefix, a ring window and a run of segments; the first three have an inline constant-capacity form and a runtime-capacity form confined to heap-cell content, and a run of segments exists only as heap-cell content, because only a shape needing a length, a head or segment boundaries should store that metadata, instead of one growable representation imposed on fixed arrays.

Decision: A run of segments is one contiguous run of elements with the boundaries of its segments, fixed when a prelude function builds it from a range of lengths and a fill value and returning nothing when the total passes the element type's limit; its one measure is its segment count, a subscript selects one segment as a run of elements like the referent of a range reference, and the run of every element in segment order is reachable as a whole, because variable-length per-item output belongs in one contiguous buffer written in parallel, which ran five to eleven times faster than a buffer per item in the [measured scatter](../../../research/investigations/segmented-storage/DESIGN.md#measurement-where-the-outputs-go), and boundaries that only the storage can set make distinct segments distinct storage for every judgment that treats distinct array elements so, instead of an offsets witness type with a permission clause of its own, a proved fact that an array does not decrease, or a buffer per item.

Decision: A storage stores exactly the measure words its shape needs and no word derived from the others, an array its length, a prefix window its length and its capacity, and a ring window its length, its capacity and its head, each one a readonly field of the shape's declaration (`language/data-model/readonly-field`) that a program reads the way it reads any field and can never assign, changed only by the operations that own it, so an operation needing free space states in its contract that the length is below the capacity, because the boundary is an ordinary runtime number stored with the block and every proof about the storage is a relation over those numbers, while a remaining-room word is the capacity minus the length and gives a proof nothing the two words it is built from do not already give, at the price of a special rule tying every write of the length to the facts about it, instead of a family of measure-reader operations spelled unlike every other read, or a fourth stored word for the remaining room whose identity with the other two rides along as a standing fact.

Decision: Each stored measure word stands on its own in the fact system, so an effect row entry that names one word, a window's length, kills the facts about that word alone and leaves the facts about the capacity and the head standing, while an entry naming the whole storage kills the facts about all of its words, because an operation that moves only the boundary must not cost its caller a capacity fact the caller proved before the call, instead of treating any write inside a storage as a write of its whole descriptor.

Decision: Besides its slots, a window has four named parts, the append slot at its length, the last filled slot below its length, all filled slots, and all free slots, and these exist only as vocabulary for effect rows and for the overlap judgment, no program forming a reference to a part or reading or writing one, because a row that names only the append slot and the length is what lets an appending call be proved not to disturb a live reference to a filled slot, while two neighbouring questions are deliberately outside this node, when a reference into a window stays valid across an operation and how two indexed positions are judged to overlap, both of which belong to the reference and ownership subtree, where validity is a fact and the overlap relation lives, instead of appending counting as a write of the whole storage that invalidates every reference into it.

Decision: A value leaves a slot only through an operation that moves a window boundary or exchanges the value in the place, taking from either end, removing at an index, or swapping two places, and a move out of a slot is rejected, because no slot may ever be observable as empty and none carries a tag that could report it as empty, while what the kernel implements against what a source library composes is deliberately outside this node and belongs to `language/data-model/kernel-minimality`, instead of a take that leaves a hole, or a vacancy type state for a partially emptied storage.

Decision: An operation that moves the boundary of a runtime-capacity window takes a reference to the cell's content, `place_back(&b.inner, move v)`, while the two operations that act on the cell itself take the cell, the growth that replaces it keeping the parameter `&Box<Slots<T>>` and the release of an emptied window consuming it as `free_empty(move b)` under a contract that requires `window.inner.len == 0`, because a boundary move touches the content and nothing else, so its declared row names the window's parts below one field step, while an operation that reallocates or frees the heap object must name the owner it replaces or consumes, instead of handing every operation on a boxed window the cell and re-deriving the content inside it.

Decision: The content of a cell holding a runtime-capacity window is never moved out of that cell, such a window being reclaimed by the cell's ordinary release when its owner's scope ends or, earlier, by emptying the window and consuming the cell, because a runtime-capacity window exists only as a cell's content, so a move out would have to land in a local binding that no placement admits, instead of admitting the unbox for such a content and inventing a home for a window whose capacity is not known until it is built.

Decision: A subscript admits the four storage shapes in their admitted forms, admitted range references, and constant tables, because a range names part of existing storage for a callee rather than adding another owning storage shape, instead of a first-class slice value beside the shapes. Range admission and reference escape belong to `language/ownership/range-reference` and `language/ownership/no-stored-references`.

Rejected:
- A built-in growth operation for Ring: rejected because allocation, ordinary window transfers and consumption of the emptied backing already express an order-preserving source rebase with checked result contracts. The current library uses a counted transfer loop to publish exact length because append's contract supplies only lower bounds. This establishes expressibility, not one native copy or automatic growth through a reference; the matched comparison in research/experiments/container-representation/deque-library separates the remaining costs, which can reopen this boundary under language/data-model/kernel-minimality.
- Per-slot tags so that a window could report an individual slot as empty: rejected because no program point can observe a live slot as empty, so the tag would cost storage and a test in every program that never asks the question.
- A single storage type parameterized by whether it has a length and a head: rejected because the metadata a shape stores is the whole difference between the three, and collapsing them would make a full array carry a length it can never change.
- An offsets witness type with its own permission clause: rejected because it adds a type whose only purpose is to carry a proof and a parallel-permission clause specific to it, where segmented storage gets disjointness from the storage shape the element rule already trusts.
- A proved fact that an array of offsets does not decrease: rejected because it needs quantified facts in automatic derivation, whose cost and termination the specification fixes, for a property only segment boundaries need.
- A buffer per item: rejected because its allocations ran five to eleven times slower than one contiguous buffer in the measured scatter and slowed down with more workers.
