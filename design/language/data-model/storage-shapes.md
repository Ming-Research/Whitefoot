Decision: The storage shapes are a full array, a contiguous filled prefix, a ring window, a run of segments and a paged filled prefix; the first three have an inline constant-capacity form and a runtime-capacity form confined to heap-cell content, and runs of segments and paged prefixes exist only as heap-cell content, because only a shape needing a length, a head, segment boundaries or a page directory should store that metadata, instead of one growable representation imposed on fixed arrays.

Decision: A run of segments is one contiguous run of elements with the boundaries of its segments, fixed when a prelude function builds it from a range of lengths and a fill value; its one measure is its segment count, a subscript selects one segment as a run of elements like the referent of a range reference, and the run of every element in segment order is reachable as a whole, because variable-length per-item output belongs in one contiguous buffer written in parallel, which ran five to eleven times faster than a buffer per item in the [measured scatter](../../../research/investigations/segmented-storage/DESIGN.md#measurement-where-the-outputs-go), and boundaries that only the storage can set make distinct segments distinct storage for every judgment that treats distinct array elements so, instead of an offsets witness type with a permission clause of its own, a proved fact that an array does not decrease, or a buffer per item.

Decision: A storage stores exactly the measure words its shape needs and no word derived from the others, an array its length, a contiguous or paged prefix window its length and its capacity, and a ring window its length, its capacity and its head, each one a readonly field of the shape's declaration (`language/data-model/readonly-field`) that a program reads the way it reads any field and can never assign, changed only by the operations that own it, so an operation needing free space states in its contract that the length is below the capacity, because the boundary is an ordinary runtime number stored with the block and every proof about the storage is a relation over those numbers, while a remaining-room word is the capacity minus the length and gives a proof nothing the two words it is built from do not already give, at the price of a special rule tying every write of the length to the facts about it, instead of a family of measure-reader operations spelled unlike every other read, or a fourth stored word for the remaining room whose identity with the other two rides along as a standing fact.

Decision: Each stored measure word stands on its own in the fact system, so an effect row entry that names one word, a window's length, kills the facts about that word alone and leaves the facts about the capacity and the head standing, while an entry naming the whole storage kills the facts about all of its words, because an operation that moves only the boundary must not cost its caller a capacity fact the caller proved before the call, instead of treating any write inside a storage as a write of its whole descriptor.

Decision: Besides its slots, a window has four named parts, the append slot at its length, the last filled slot below its length, all filled slots, and all free slots, and these exist only as vocabulary for effect rows and for the overlap judgment, no program forming a reference to a part or reading or writing one, because a row that names only the append slot and the length is what lets an appending call be proved not to disturb a live reference to a filled slot, while two neighbouring questions are deliberately outside this node, when a reference into a window stays valid across an operation and how two indexed positions are judged to overlap, both of which belong to the reference and ownership subtree, where validity is a fact and the overlap relation lives, instead of appending counting as a write of the whole storage that invalidates every reference into it.

Decision: A value leaves a slot only through an operation that moves a window boundary or exchanges the value in the place, taking from either end, removing at an index, or swapping two places, and a move out of a slot is rejected, because no slot may ever be observable as empty and none carries a tag that could report it as empty, while what the kernel implements against what a source library composes is deliberately outside this node and belongs to `language/data-model/kernel-minimality`, instead of a take that leaves a hole, or a vacancy type state for a partially emptied storage.

Decision: An operation that moves the boundary of a runtime-capacity window takes a reference to the cell's content, `place_back(window: &b.inner, value: move v)`, while operations that act on the cell itself take the cell, growth taking `&Box<Slots<T>>` or `&Box<Paged<T>>` and the release of an emptied window consuming it as `free_empty(window: move b)` under a contract that requires `window.inner.len == 0_u64`, because a boundary move touches the content and nothing else, so its declared row names the window's parts below one field step, while an operation that reallocates or frees the heap object must name the owner it replaces or consumes, instead of handing every operation on a boxed window the cell and re-deriving the content inside it.

Decision: The content of a cell holding a runtime-capacity window or a run of segments is never moved out of that cell, the cell's ordinary scope-end release requiring its content to have drop [PROV-6], while a window can also be reclaimed by taking every element out and consuming it, then consuming the proved-empty cell [OP-14], because each exists only as a cell's content, so a move out would have to land in a local binding that no placement admits, instead of admitting the unbox for such a content and inventing a home for a window whose capacity is not known until it is built.

Decision: A subscript admits the five storage shapes in their admitted forms, admitted range references, and constant tables, because a range names part of existing storage for a callee rather than adding another owning storage shape, instead of a first-class slice value beside the shapes. Range admission and reference escape belong to `language/ownership/range-reference` and `language/ownership/no-stored-references`.

Decision: Paged is a separate runtime-capacity prefix window with stable page storage and one-level logical element indices, the ordinary Slots proofs, back placement and removal, and growth that copies the cell's header and page pointers but never an element, invalidating references through its whole-cell effect, because Snowghost needs insertion that copies no earlier payload together with dense flat-index loop permission ([requirements and probes](../../../research/investigations/paged-storage/DESIGN.md#language-surface)), instead of changing the contiguous Slots representation or adding a second separation argument for source page arithmetic.

Rejected:
- A built-in growth operation for Ring: rejected because allocation, ordinary window transfers and consumption of the emptied backing already express an order-preserving source rebase with checked result contracts. The current library uses a counted transfer loop to publish exact length because append's contract supplies only lower bounds. This establishes expressibility, not one native copy or automatic growth through a reference; the matched comparison in research/experiments/container-representation/deque-library separates the remaining costs, which can reopen this boundary under language/data-model/kernel-minimality.
- Per-slot tags so that a window could report an individual slot as empty: rejected because no program point can observe a live slot as empty, so the tag would cost storage and a test in every program that never asks the question.
- A single storage type parameterized by whether it has a length and a head: rejected because the metadata a shape stores is the whole difference between the first three, and collapsing them would make a full array carry a length it can never change.
- An offsets witness type with its own permission clause: rejected because it adds a type whose only purpose is to carry a proof and a parallel-permission clause specific to it, where segmented storage gets disjointness from the storage shape the element rule already trusts.
- A proved fact that an array of offsets does not decrease: rejected because a segment is handed to a callee as a range reference, whose separation the affine families prove, while a range fact separates only single element accesses in a counted loop's certificate, and the storage shape already gives segments their disjointness.
- A source-library two-level page table: rejected because a flat logical index becomes quotient and remainder steps, and the probe in the [paged-storage investigation](../../../research/investigations/paged-storage/DESIGN.md#evidence-from-snowghosts-probes) loses the required flat-index loop permission.
- Stable page growth inside Slots: rejected because it removes contiguous ranges and charges every existing Slots access for a page-directory load, where callers need to choose between the two storage intents.
- Slots<Box<T>> with growth that preserves content references: rejected because it requires one allocation per element and scattered payloads while growth still copies all element pointers.
- A radix directory with references surviving growth: rejected because every address formation would need a separate directory effect part and its overlap rules, beyond the selected requirement of stable elements whose references are re-formed after growth.
- A buffer per item: rejected because its allocations ran five to eleven times slower than one contiguous buffer in the measured scatter and slowed down with more workers.
