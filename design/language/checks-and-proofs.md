Decision: Automatic derivation uses fixed terminating families that run to completion, and a harder proof is a finite explicit certificate checked without rediscovery, because acceptance must not depend on solver state, time, machine speed or a work budget, instead of SMT-backed acceptance.

Decision: Required partial-operation domains are established by the specification's deterministic proof system from admitted types and declarations, selected control-flow edges, verified contracts and checked invariants, because an unproved domain cannot authorize a partial operation, instead of writer assertions or runtime traps.

Decision: A nonempty explicit certificate is rejected when automatic derivation already proves its target, because the boundary between automatic and written proof must be decidable from the language rules, instead of tolerating redundant certificates.

Decision: A proof_use certificate holds at most 4096 entries and one invariant's affine formation at most 4096 scheduled expression nodes, input terms and result terms, because the specification must fix these structural source ceilings independently of machine capacity; the chosen number is arbitrary, instead of a time or work budget or no structural ceiling.

Decision: Beside the affine fact language, a function's requirements and postconditions and a loop's header invariants may state bounded range facts over integer element reads, which a separate range judgment proves and which serve only other range facts and counted-loop certificates, because a structure built by scattering indices, such as a renderer's per-level element lists, is parallel only through facts over many elements that no per-term relation states ([derivation](../../research/investigations/unique-keys/POINTWISE.md)), and binding each fact to the storage version it was stated over lets a fixed derivation re-establish it after a write, instead of keeping no quantified storage facts, a ghost model of the structure, or quantifiers decided by search; data-dependent occupancy is still stored as ordinary tags or options and checked through a bounded index.

Decision: A place reached through one or more subscripts is a term of the fact language exactly when its last step selects a readonly integer field, prelude measure or writer-declared alike, and each offset is itself a tracked place or a constant, because such a field changes only through a write to a place containing it and such an offset only through a write to its own support, so the ordinary overlap kill ends every fact about the term, instead of admitting every subscripted integer place, whose facts die at almost every element write not proved distinct, or only the prelude's measures. The [readonly-field term investigation](../../research/investigations/readonly-field-terms/DESIGN.md#soundness-every-change-is-an-overlapping-write) lists the killing events, the offset rule and the evidence.

Decision: Required index and range separation is discharged by the ordinary fixed automatic families and written proof steps, with an undischarged pair remaining overlapping under the [shared path judgment](https://github.com/mbbill/Whitefoot/blob/main/design/language/ownership.md), because access and parallel permission must consume the same proved distinctness, instead of a separate alias solver or checker-dependent separation; the one other source is a counted loop's `apart` certificate, which proves two iterations' element accesses distinct for the counted permission alone, because no access judgment asks about two iterations, and the elements it separates are distinct by the same path relation.

Decision: An ensures clause may name a fragment-integer field or a measure reached from a result place, or from a routed success payload, through an owned descendant projection of struct fields and Box contents; a selected return reads it from the returned place, from the field operand of a returned construction or from a forwarded value's conditional payload, the caller instantiates it at the destination place projected the same way, and MSR-3's placements carry such a field's value wherever they carry measures, minting a value only for a field whose source place is already a term of the state, because a constructor must be able to state its returned value's measures, as a queue factory stating that its ring is empty, and a validated identifier or header returned inside a struct otherwise made every caller repeat the check the callee had just made, as the [aggregate-postcondition probes](../../research/investigations/aggregate-postconditions/DESIGN.md#case-1-an-identifiers-validity) show, while a field changes only by events that already kill the facts over it, so no new kill rule is needed, instead of admitting only the bare result or its measures, a new projected-datum family, hidden identity fields, or integer-tuple results; enum-payload steps, subscripts and steps below a value of type-parameter type stay excluded because no route selects a variant of an unrouted result and the others leave the owned descendants.

Decision: A widening conversion, a bare cvt whose integer pair is whole-type total, denotes its operand's value in a relation term and in a comparison's L0 projection, because relations are over mathematical values and a u32 identifier otherwise has no way to relate to a u64 length, as the [cross-width probes](../../research/investigations/aggregate-postconditions/DESIGN.md#case-1-an-identifiers-validity) show, instead of storing every identifier as u64 or adding a conversion term family; a value-dependent conversion stays outside the fragment.

Decision: When a module's bodies call an instance of another module's generic callable, recursive-component formation treats that instance as calling every function-kind actual and bundle member supplied to it, whether or not the callee's body calls them, because a module's proof availability must follow from its own bodies and its dependencies' interfaces so that an implementer's body edit cannot withdraw a postcondition another module's proof used, and enlarging components only withholds summaries and never admits a circular proof, instead of forming cross-module components from the callee body's concrete call edges.

Decision: When a recursive component contains members of several modules, the members that one module's own check verifies publish their summaries for that module's verdict once all of them verify, same-component summaries stay unavailable during checking, and composition still requires every member to verify, because no member's proof uses a same-component summary, so publishing one module's verified members admits no circular proof, while waiting for another module's instance, which only composition checks, would make the module's verdict depend on that module's body, contrary to the [module-verdict rule](../../research/investigations/modular-compilation/LANGUAGE.md#module-verdicts-and-proof-availability), instead of publishing a component's summaries only after every member, including another module's instance, verifies.

Decision: Contracts, invariants and proof premises name only accessible paths and establish no fact by naming them, ordinary getters retain runtime calls and written normal-return postconditions while calls remain excluded from contract expressions, and privacy adds no implicit type invariant, because published readonly fields give callers the state their proofs need and verified written guarantees, a callable's own contract and the invariants its parameter and result types declare, are the only facts crossing a call, instead of observe modifiers, generated getter equations, use view expansion, an added termination checker or treating private representation as a proved invariant.

Decision: A struct may declare difference-bound invariants over its own fields, owed at every construction and wherever the value is handed on and assumed at every function's entry, with each field private or public readonly so that only the declaring module writes one, because one owner per value, references that never leave the function holding them and no global mutable state leave the moments between two field writes unobservable, the boundary SPARK's Type_Invariant draws at a package, and a relation such as a cursor below its window's length otherwise has to be restated on every function that takes the value ([TYPE-11], [investigation](../../research/investigations/io-model/CONCURRENCY-MODEL.md#56-an-invariant-for-the-whole-life-of-a-value)), instead of no type invariant or one owed at every field write.

Decision: A type invariant is written `invariant name(binder): left op right;` after its struct's fields, naming the value it constrains with an explicit binder that only its relation sees, and the relation is judged as the requirement clause of a function whose one parameter is that binder, because Whitefoot has no receiver and every other clause names its values by declared names, so the binder is an ordinary declared name and the relation reuses the requirement clause's checked forms, diagnostics and repairs unchanged, while the name, as a local invariant's name does, identifies the invariant in each obligation and diagnostic ([TYPE-11], [investigation](../../research/investigations/io-model/CONCURRENCY-MODEL.md#56-an-invariant-for-the-whole-life-of-a-value)), instead of an implicit `self` or bare field names.

Rejected:
- Tolerating an unused explicit certificate as advice rather than an error: rejected because the redundancy rule ties the writer's choice to the exact language version instead of to compiler behavior.
- Limiting the explicit certificate language to what the automatic families can already prove: rejected because a certificate that can only restate an automatic proof adds no proof, so the certificate language must reach beyond the automatic families.
- Quantified invariants over the elements of a storage that the affine judgment instantiates at each read and re-establishes at each write: rejected because every element write would owe each such fact again through the ordinary obligations, and the flow-sensitive fact domain has no element-read terms to carry it; range facts take a separate judgment and feed no ordinary obligation.
- Keeping no quantified storage facts, with level-ordered results copied back into document order: rejected because the copy costs a pass over every element on every style pass and the document-order write it avoids is the one the renderer needs.
- A ghost model of the whole document as a forest, proved through library contracts: rejected because it proves acyclicity of the live structure, which the parallel passes never need once each pass derives its own numbering, and it would add ghost types, recursive models, induction and existential witnesses to the language where range facts add bounded clauses and one certificate ([research](../../research/investigations/unique-keys/DESIGN.md)).
- Admitting only the prelude's measures below a subscript: rejected because a writer's readonly field changes by exactly the events that change a measure, so the restriction is a special case with no soundness difference, and an index-based structure such as an arena tree could state no relation about one element's field in a requirement and could not bound a loop by it.
- Relying on a let-bound copy of the field instead of a term: rejected because a copy is detached from the storage it was read from, so a requirement cannot relate an element's field to another storage and a caller's fact about the element cannot reach the callee.
- Admitting any offset and reporting an unrepresentable one as a compiler limit: rejected because an offset whose changes no term records as support, such as an element read, lets the place come to select another element with no kill, so the restriction is a language rule, while an admitted offset a compiler cannot capture remains a compiler capability.
- The finite observe and use view proposal: rejected because published fields give external contracts and proofs direct names for the state they need, with no logical function kind or termination requirement.
- Checker-only private terms with no external annotation spelling: rejected because an external wrapper, loop invariant or explicit certificate must be able to state its required condition, so hidden terms alone are not a complete authoring interface.
- Annotation-only access to private fields: rejected because contracts would then depend on fields the interface does not publish; the field a contract needs is published instead.
- General mathematical functions as a prerequisite for modules: rejected because direct structural contracts cover the selected witnesses; reconsider abstraction for a concrete representation-evolution or algorithmic-contract consumer.
- Replacing operations with one setter per private field: rejected because separate setters do not establish a relation between fields or a checked invariant protocol.
- Forming cross-module components from the callee body's concrete call edges: rejected because a callee body edit that starts calling a supplied actual would change the caller's verdict without any interface change.
- Integer-tuple results in place of a struct result: rejected because an unrouted clause must hold on the error exit too, so the callee invents dummy values, a Result routes only one integer, and the caller's reassembled struct would drop the facts again at construction.
- An invariant owed at every construction and field write: rejected because a relation between two fields cannot be kept while they are written one at a time, and no code but the body writing them can observe the value between the two writes.
- Type invariants relating a value to another value, such as an arena node's index into another table: rejected because a type cannot name the other value, so such relations stay contracts.
- An implicit `self` or `this` binder: rejected because no other construct has a receiver, so `self` would be a reserved word that names a value in this one clause.
- Bare field names in the relation: rejected because a field name alone is a place in no other clause, so judging the relation would need a second name-resolution rule beside the requirement clause's.
- Admitting result fields without placement transport: rejected because a body that builds its result by construction could not prove the clause, and the caller's first rebinding of the struct would drop the fact.
- Carrying every integer field at every placement: rejected because carrying only fields whose source place is already a term carries the same provable facts at less cost and adds no term to a program that names no field in a relation.
- Getters with postconditions: rejected because a getter's ensures constrains its call's result, not the field at later reads, and calls stay excluded from contract expressions.
- Field atoms in loop invariants: rejected because a loop can carry the fields as scalars and construct the value after it; reopen when a program needs a loop-carried struct field in an invariant.
