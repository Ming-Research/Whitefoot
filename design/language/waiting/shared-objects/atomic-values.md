Decision: An atomic value is a separate opaque `AtomicValue` state holding one bounded unsigned 64-bit integer, reached through the ordinary shared-handle target and used for a load, saturating add returning the old value, or raise to a maximum, because the [sequence witness](../../../../research/investigations/sequence-take/DESIGN.md#56-v-a-shared-atomic-value-held-by-an-atomic-statement-without-exclusion-recommended) needs its number to take effect with the write it labels and the same state serves exact maxima and identifiers, instead of a sequence-specific target or independent operations outside the statement.

Decision: On every path through an atomic statement at most one atomic-value operation executes across all its atomic-value bindings, each binding occurring only as that operation's direct state argument and outside loops and guards, because two operations can expose an interleaving that no single statement effect point represents, while guards would require a watcher protocol on every atomic-value write, instead of general lock-free fields, helper-hidden operations or one operation per binding ([argument](../../../../research/investigations/sequence-take/DESIGN.md#56-v-a-shared-atomic-value-held-by-an-atomic-statement-without-exclusion-recommended)).

Decision: Atomic values saturate at 2^63 and an add reaching the bound reports full, construction and raise require values at most 2^63 and an add requires an amount at most 2^32, because bounded additions leave room for the finite executor population's in-flight increments without wrapping the representation while full is an ordinary result, instead of wrapping identifiers or a runtime trap ([overflow argument](../../../../research/investigations/sequence-take/DESIGN.md#56-v-a-shared-atomic-value-held-by-an-atomic-statement-without-exclusion-recommended)).

Decision: The proposed surface name is non-generic `AtomicValue`, because it names the checked single-effect invariant without promising an instruction or unused value domains, instead of borrowing C's or Rust's broader atomic-type API or naming only sequences and counters ([name comparison](../../../../research/investigations/sequence-take/DESIGN.md#naming-comparison)).
