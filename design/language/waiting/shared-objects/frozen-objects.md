Decision: Data that several contexts read and none writes is a frozen object held through `Frozen<T>` handles: `frozen_new` moves an owned value into it and `frozen_share` makes another handle, its value is read through the handle's readonly field `inner` without an atomic statement, in any statement including another atomic statement's block, its handles counted as a shared object's are, because a library that keeps persistent versions of a dataset must read a node it reached from inside an atomic statement on its registry, which the rule against nested atomic statements forbids, and only a value no writable handle ever named is provably unchanging ([the two refused programs of Firn-wf's frozen-dataset prototype](https://github.com/Ming-Research/Firn-wf/tree/0958448784cb4f42f05e238728dacf00efb7b2b2/research/experiments/frozen-dataset-prototype)), instead of relaxing that rule for `SharedRead` targets, a new storage domain for snapshots, or relaxing the reserve's service-first abort.

Decision: A frozen object's type has no part, at any depth, that is a `Shared`, a `SharedRead` or a host handle, because a snapshot read through a frozen object must not see a later write, and those are the only parts through which a value reached from it could change, instead of a shallow freeze that leaves nested shared state writable.

Rejected:
- Relaxing the rule against nested atomic statements for a `SharedRead` target whose object has no writer left: rejected because `shared_share` duplicates writable handles at run time, so whether any writer remains is recorded by no type or binding and cannot be decided where the program is checked.
- A conversion `freeze(Shared<T>) -> Frozen<T>` of an existing shared object: rejected because it needs a run-time check that no other handle and no atomic statement on the object remain, which no consumer needs while a frozen object can be built from an owned value.
- A new storage domain for snapshots: rejected because a frozen object expresses the operation the prototype could not, within the shared-object release machinery the language already has.
- Relaxing the service-first abort of a snapshot's reserve: rejected because the abort is the owner's policy for keeping service ahead of persistence, and revoking readers is a library protocol over handles, not a language rule.
