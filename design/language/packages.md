Decision: A module program's graph binds another package with `package name = "location";`, the location a relative path from the binding graph's own directory with `..` allowed and no absolute form, the host resolving its components as it resolves any path, and the name chosen by the binding graph, bound once per graph as each package is, and visible only in its own package's graph and records, while the bound package's records keep naming themselves `pkg`, because the graph is already the program's single dependency authority, a relative location keeps a checked-out tree buildable wherever it is placed with no search path or environment input, and a binder-chosen name leaves a library's own source unchanged whatever its users call it, instead of a separate manifest file, command-line or environment package roots, absolute paths, or a name the library declares for itself ([packages](../../research/investigations/packages/DESIGN.md#the-rules)).

Decision: A package is its directory: bindings from any graphs that reach one directory bind one package, whose modules and types are the same under every name, because a library that returns a value of a package its user also binds, as Halo returns JSON values to firn, must return the type its user names, and identity by location needs no version rule, instead of identity by a declared name and version ([the diamond](../../research/investigations/packages/DESIGN.md#the-diamond-decides-identity)).

Decision: A binding exposes every module the bound graph registers, each through its public declarations only, and is not transitive, so a package names only the packages its own graph binds, because a module's `module.wfm` is already its public boundary and a graph row already the per-module permission, instead of a package-level export list as a second visibility mechanism or visibility of a dependency's dependencies.

Decision: A package has no version: a binding reads whatever its directory holds, and caches key on its records' bytes, as a provisional choice because no consumer needs two versions of one library and a pinned checkout fixes a version without a language rule; reopen when a library is split into its own repository and two of its consumers need different versions, instead of version constraints in the binding now.

Decision: A bound name means its package only in the package whose graph binds it, so two graphs of one program may bind one name to different packages, and the compiler labels each bound package by the name of its first binding in binding order, every graph's bindings in package order and then written order so the program's own names are taken first, suffixed `.2`, `.3` and on when a package labeled before it holds that name, for its records' logical paths `package/<label>/`, its symbols and diagnostics, because the binding graph chooses the name as a file chooses an alias, two independently written libraries must not have to agree on their dependencies' names to share one program, and a label is never written in source, instead of requiring one name to mean one package across a program, which only made the compiler's labels unique without a suffix ([labels](../../research/investigations/packages/DESIGN.md#labels)).

Decision: The package order is the program's own package followed by each bound package in the order a depth-first walk of the bindings, each graph's in written order, first reaches it, every graph's syntax, location forms and repeated names are judged when it is read, each binding's directory, cycle and repeated package as the walk reaches it, and then every graph's rows and entries in package order, and a binding that reaches its own package or one the walk is still visiting is refused as a cycle, because a binding graph's rows name modules its bound graphs register, so those graphs must be read first, an acyclic package graph lets each package be checked before the packages that bind it, and a fixed walk makes diagnostics, the bound unit's module order and labels independent of the host, instead of package cycles whose module edges stay acyclic or an order taken from directory names.

Decision: A bound name is a module prefix only and joins no declaration domain, so a local binder or module declaration may share its spelling (`let json = json::make(n: 1_i32);`), while a lowercase alias of that spelling is refused, because a qualified path's root and a value position are told apart by the grammar, as they are for `pkg` and `std`, and a package-wide reservation would make every record of a library avoid its dependencies' names, instead of placing bound names in the lexical-identifier domain beside module aliases.

Decision: A bound package's graph is judged by the module graph rules, its entries only for their form, and every module it registers is checked with the program's own modules, because a library's defects should surface when its user checks the program rather than only when an entry happens to select the broken module, while the library's entries name functions of its own builds, instead of checking only the modules an entry's composition selects or judging a library's entries as the program's.

Rejected:
- Placing Halo and its codec libraries inside firn's package until bindings exist: rejected because they are meant to become separate projects and would be written against firn's package root instead of their own.
- One name meaning one package across a whole program: rejected because it refuses a program for two libraries' private naming choices, a cost no reader benefits from since each bound name is visible only in its own package, while its only gain was a label without a suffix.
- Shipping reusable third-party libraries in the standard library: rejected because the standard library ships with the compiler and is selected by every program that names it, so it would carry a Lua engine for programs that never run Lua.
