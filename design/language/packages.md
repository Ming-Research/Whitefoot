Decision: A module program's graph binds another package with `package name = "location";`, the location a relative path from the binding graph's own directory with `..` allowed and no absolute form, and the name chosen by the binding graph and visible only in its own package's graph and records, while the bound package's records keep naming themselves `pkg`, because the graph is already the program's single dependency authority, a relative location keeps a checked-out tree buildable wherever it is placed with no search path or environment input, and a binder-chosen name leaves a library's own source unchanged whatever its users call it, instead of a separate manifest file, command-line or environment package roots, absolute paths, or a name the library declares for itself ([packages](../../research/investigations/packages/DESIGN.md#the-rules)).

Decision: A package is its directory: bindings from any graphs that reach one directory bind one package, whose modules and types are the same under every name, because a library that returns a value of a package its user also binds, as Halo returns JSON values to firn, must return the type its user names, and identity by location needs no version rule, instead of identity by a declared name and version ([the diamond](../../research/investigations/packages/DESIGN.md#the-diamond-decides-identity)).

Decision: A binding exposes every module the bound graph registers, each through its public declarations only, and is not transitive, so a package names only the packages its own graph binds, because a module's `module.wfm` is already its public boundary and a graph row already the per-module permission, instead of a package-level export list as a second visibility mechanism or visibility of a dependency's dependencies.

Decision: A package has no version: a binding reads whatever its directory holds, and caches key on its records' bytes, as a provisional choice because no consumer needs two versions of one library and a pinned checkout fixes a version without a language rule; reopen when a library is split into its own repository and two of its consumers need different versions, instead of version constraints in the binding now.

Decision: A bound name means its package only in the package whose graph binds it, so two graphs of one program may bind one name to different packages, and the compiler labels each bound package by its first binding's name, suffixed `.2`, `.3` and on when an earlier package already holds that label, for its records' logical paths `package/<label>/`, its symbols and diagnostics, because the binding graph chooses the name as a file chooses an alias, two independently written libraries must not have to agree on their dependencies' names to share one program, and a label is never written in source, instead of requiring one name to mean one package across a program, which only made the compiler's labels unique without a suffix ([labels](../../research/investigations/packages/DESIGN.md#labels)).

Rejected:
- Placing Halo and its codec libraries inside firn's package until bindings exist: rejected because they are meant to become separate projects and would be written against firn's package root instead of their own.
- One name meaning one package across a whole program: rejected because it refuses a program for two libraries' private naming choices, a cost no reader benefits from since each bound name is visible only in its own package, while its only gain was a label without a suffix.
- Shipping reusable third-party libraries in the standard library: rejected because the standard library ships with the compiler and is selected by every program that names it, so it would carry a Lua engine for programs that never run Lua.
