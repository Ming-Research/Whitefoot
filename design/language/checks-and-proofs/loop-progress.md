Decision: Every ordinary loop that can reach its header again makes checked progress, by a rank that falls on every backedge or by waiting on every path back to the header, and the rule is mandatory, because an optional proof can be left out and the default shape should be the best one, and because the waiting premise that the concurrency model's fairness rests on is then a theorem between waits instead of an assumption ([census](../../../research/investigations/termination/DESIGN.md#verdict-against-the-criteria)), instead of an optional termination annotation or no progress check.

Decision: A loop's rank is derived from the body's leading exit tests when their form gives one, `a < b` or `a <= b` continuing giving `b - a`, `a > b` or `a >= b` giving `a - b`, and `x != 0` over an unsigned x giving x, and is written as `decreases R` in the header only outside those forms, because the common cursor loop then carries no annotation while every derivation stays syntactic and search-free, instead of a written rank on every loop.

Decision: Every leading exit test derives a rank when its condition is a comparison of the table, the leading statements running up to the first that is neither a `let` whose initializer is not a call of a function nor an exit test whose condition is not one, or to the first exit test whose continuing block is not empty, and the loop progresses when one of those ranks falls on every backedge, because operations and constructions write nothing, so no statement before a leading test writes its operands, so each test's rank at the test is its value at the header, and a loop that checks an unchanging guard before its real bound, such as a merge or a nested break, otherwise has to be rewritten ([migration](../../../research/investigations/termination/runs/migration.md#derivation)), instead of reading only the first test.

Decision: An exit-test operand may be an exact or `.defined` sum or difference of operands or an operand times an integer literal, read through the leading `let`s, because those operations denote the mathematical value once their domain is proved, so a bound such as `2 * at + 1 >= count` is a rank as it stands, instead of requiring the writer to restate the rank in a header.

Decision: An equality exit derives no rank, because the continuing disequality does not bound the cursor, so a cursor that starts past the limit wraps forever, and the fixed families do not combine a disequality with an order to recover the bound; a writer writes `>=`, instead of deriving a rank from `==` together with a separately proved order ([migration](../../../research/investigations/termination/runs/migration.md#equality-exits)).

Decision: The waits that let a loop owe no rank are [WAIT-1]'s waits other than a spawn written as a statement: a call of a `must_wait` function, a guarded atomic statement and the join of a spawn a `let` binds, because a `must_wait` signature states at its boundary that every call waits, so a loop may wait through any number of helpers, while an unguarded atomic statement waits only for its own point of effect [SHARE-3], a `may_wait` call can return without waiting, and a spawn written as a statement is joined only when its activation leaves, so a spin on any of those never waits and is a rank obligation like any other loop ([rulings Q16 and Q34](../../../research/investigations/termination/DESIGN.md#owner-rulings)), instead of every atomic statement or every call of a waiting function.

Decision: A loop also progresses when every backedge rebinds a reference cursor to a place that extends, through owned field, payload, `Box` and subscript steps with at least one `Box` step, the place it named when the iteration began, and the body adds no `Box` anywhere, which the checker reads as no commit of a non-scalar value other than a reference rebinding and no call whose row writes, because owned values are finite trees, so the number of `Box` cells below the cursor falls each iteration, and owned-list and tree walks are the language's own reference-cursor pattern ([REF-1] conformance), and it is tried before a derived rank, because it owes no proof, so a leading test that happens to derive a rank does not turn a structural walk into a rank obligation, instead of requiring a counter or recursion for every owned walk; a removal that leaves the cursor in place and shrinks its referent stays outside the form ([migration](../../../research/investigations/termination/runs/migration.md#owned-structure)).

Decision: A rank's descent is decided at the edge back to the header after the body, like a header invariant's step, and a failure is reported there, because the descent reads the whole body's facts, so a header invariant the same backedge fails is its cause and is reported first, instead of reporting at the loop statement's source position.

Decision: At a join inside a loop's body each relation the loop owes at its backedge, its header invariants and its rank's relations with the two-term relations that imply the descent, is kept in the joined state when every joined state proves it, and so is each header invariant of an ordinary loop at the join of its break edges, because each input proves the relation of its own values and the joined value is one of them, and a bisection whose arms narrow the interval from different sides otherwise loses both its rank and its bounds ([migration](../../../research/investigations/termination/runs/migration.md#joins)), instead of the unit-coefficient projection of proved invariants into L0 alone or written join relations; the candidate set is fixed by the loop's header, so no path is enumerated and nothing is searched.

Rejected:
- Counted walks for link structures: rejected because a counted walk adds a runtime branch and an unprovable outcome to every walk, and ranked storage proves the order statically (ruling Q16).
- Deriving a rank from an equality exit with an order activated beside it: rejected because the order at the backedge is not provable from the disequality the test continues with, as the reverted prototype showed.
- Treating an unguarded atomic statement as a wait: rejected because it waits only for its own point of effect, never for another context's step, so a spin on one never yields progress (ruling Q16).
- Counting only direct calls of host waiting functions: rejected because a loop that waits through a helper, which is the common shape, would owe a rank it cannot have (ruling Q34).
- Counting a call of a source function that waits on every path, found by a least fixpoint over the module's functions: rejected because it infers the property from callee bodies across the call boundary, where `must_wait` states it at the boundary and is checked at the definition (ruling Q34).
- Re-proving every fact at every join: rejected because it enumerates candidates the source did not name, as the [join investigation](../../../research/investigations/branch-join-relations/DESIGN.md#rejected-alternatives) found; only the relations a loop already owes are candidates.
