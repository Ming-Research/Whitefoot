Rejected:
- A rule only for the fill constructors, their elements taken as copies of the value: rejected because a user's generic function stating `result[k] == value` would still say nothing for a struct, a rule of the prelude's own instead of the language's.
- Live storage carrying no range fact across passes, each pass re-establishing what it uses: rejected because a structure kept by a module's writers could then not state its invariant where it is used, and the experiment compiler refused every caller of Snowghost's sibling move ([range type invariants](../../../research/investigations/range-type-invariants/DESIGN.md#question)).
- Range facts inside ordinary entailment, with an element-read term, a fact source for requirements, header invariants and callee postconditions, and overlap kills: rejected because every element write would kill a whole fact, the source would duplicate the range judgment's activation, routing and copy model, and every goal of a function with range facts would pay for it, while deferral leaves ordinary entailment unchanged and costs nothing where it already succeeds.
- Struct fields and `Box` content first, with enum payloads later: rejected because the reported stored inverse, Snowghost's sibling move, reads its order through an enum payload, so the narrower scope would leave the gap open.
- Ceilings on the branches one derivation opens and the inequalities one elimination holds: rejected because both count work that depends on the split and elimination order, so two checkers following the specification could accept differently at the ceiling.
- Three or more bound variables, such as distinctness within each segment of a `Segments` as `(d, a, b)`: rejected because a left inverse over two variables states the same distinctness, `positions[s[d][k]] == k`, at a fraction of the instances.

- Range facts that cross a call only as requirements, with the fill constructors' contents as a separate fact source: rejected because a producer's facts then never leave the function that establishes them, so the validating walk and the grouping had to sit in the function that consumes their facts, and the constructors' contents were an exception that a postcondition of their rows states as an ordinary clause.
