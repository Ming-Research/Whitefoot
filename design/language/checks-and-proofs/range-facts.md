Decision: A range fact binds one or two variables and states guarded affine relations over literals, consts, bound variables, live integer values, measures, segment lengths and integer element reads, because the facts the level cascade and the scatter producers need are pointwise or pairwise, as a left inverse `positions[order[k]] == k` or `depth[parent[e]] + 1 == depth[e]`, and every further binder multiplies the instances a derivation forms ([derivation](../../../research/investigations/unique-keys/POINTWISE.md)), instead of arbitrary nesting or alternation of quantifiers.

Decision: A range fact is proved at every call of a function requiring it, at its loop's entry and on every backedge, by one fixed derivation: active facts are instantiated at the values the problem's own element reads select through the fact's reads, a read of a written version splits into the written element and the old one, a joined value into the arm taken, and two reads of one version into the same element and different ones, over solved equalities, read congruence and Fourier-Motzkin elimination of integer-tightened inequalities, because those are the steps a pointwise invariant's preservation takes after one element write, a frontier element's case and a certificate's separation, and each is bounded by what the problem already holds, so the judgment searches nothing and always terminates, instead of an SMT solver with quantifier instantiation or written instances for every obligation.

Decision: The derivation runs every branch to completion over exact arithmetic, and only the problem's size is bounded: a problem of more than 4096 atoms, or more than 256 formed instances of one fact, rejects the site naming the ceiling, because acceptance must not depend on a work budget, and a ceiling on branches or on one elimination's inequalities counts work whose amount depends on the order the derivation splits and eliminates, which the specification does not fix, while the problem's atoms and instances are the same in every order; the numbers are provisional, chosen above what the measured programs reach, instead of branch and elimination ceilings, an unproved verdict at a ceiling, or no size ceiling.

Decision: The theory tightens each inequality a literal forms over the integers and then asks only for a rational solution, because Fourier-Motzkin elimination that also tightens what it derives refutes some integer-infeasible sets in one elimination order and not in another, so its verdict would depend on an order the specification does not state, instead of tightening at every elimination step or fixing an elimination order in the specification.

Decision: A fill constructor's result carries its contents as facts, `box_array_filled(count, v)` every element v and `box_segments_filled(lengths, v)` under `Some` each segment's length and every element v, because a producer that fills storage with a sentinel and then writes some elements needs the sentinel's meaning for the unwritten ones, as the level grouping's `absent` slots and the children array's do, and the constructor already guarantees it, instead of a loop that restates the fill before the producer may use it.

Decision: Range facts cross a call only as the callee's requirements, so a consumer establishes them over storage it receives by a validating loop whose invariants state them, and live storage carries no range fact across passes, because a renderer's document is changed by scripts between passes, so a fact kept with it would be owed again by every mutation while a pass already walks what it styles in O(n) and can check the structure it reads ([plan](../../../research/investigations/unique-keys/POINTWISE.md#the-architecture-rule-each-pass-derives-its-facts)), instead of range postconditions or facts maintained by every document mutation; reopen when one producer must hand facts to several consumers that cannot afford a validating pass.

Rejected:
- Ceilings on the branches one derivation opens and the inequalities one elimination holds: rejected because both count work that depends on the split and elimination order, so two checkers following the specification could accept differently at the ceiling.
- Three or more bound variables, such as distinctness within each segment of a `Segments` as `(d, a, b)`: rejected because a left inverse over two variables states the same distinctness, `positions[s[d][k]] == k`, at a fraction of the instances.
- Written instances for every obligation, as a certificate gives a loop: rejected because a preservation proof would then restate, at every write, instances the problem's own reads already select.
