Decision: A place written through a reference variable is identified, as a term and as a Goal datum, by the one path that variable names where that path is exact, and by its spelling through the variable otherwise; a path is exact when it is one `&T` path with no descendant cover and no loop-header offset identity, starting at owned or constant storage, an atomic statement's state, or a reference parameter that no `set` of the body rebinds, because a guard read through a payload binder or a local alias and the requirement of a call through it are instantiated over the same storage and must meet whichever name reaches it, which `fn8-pos-payload-guard-append-grow` and `fn8-pos-guard-through-local-alias` exercise, while a path that may name different storage at different evaluations, or a rebound parameter's own binding, which names the storage it received and later another, would let a fact about one place discharge a requirement about another, instead of identifying every place by its canonical spelling alone.

Rejected:
- Spelling-only identity for every place: rejected because a guard read through a reference variable proves nothing about a call through that variable once growth or an append loop kills the placement equalities connecting the two spellings, and because the resolved referent a call substitutes for an actual formed from a later-rebound parameter carried that parameter's own spelling, so a guard on the rebound parameter discharged a requirement on the caller's storage (`fn8-neg-guard-through-rebound-parameter`, accepted before this decision).
- Identifying only reference variables that are never rebound: rejected because whether one path names one place is a property of the path where the place is read, not of the variable's history; a rebinding changes which place the variable names without making its new path ambiguous, so the restriction refused `fn8-pos-guard-through-rebound-local-holder` without protecting any fact.
- Entry referents for rebound parameters, with rebinding kills and capture-to-source associations: rejected because it adds identities and kill events whose only use is a path rooted at a rebound parameter, which keeping such paths apart already makes sound.
