Decision: An ordinary function may carry one erased contract block after its signature, with shared definitions and individually checked requires and ensures clauses, because separate executable-looking blocks hid their proof-only role, duplicated shared abbreviations, and left the result unnamed, instead of a single final requirement block ending in one Boolean check or an entry-only contract exclusion.

Decision: A define is a proof-only abbreviation that is substituted textually into every clause using it before that clause's range terms are checked, and never runs, stores a value, or takes a snapshot, because the same abbreviation is read at two different moments, before the call for requires and at the callee's return for ensures, and no single stored value could be right at both; checking the expanded term preserves the range-term restriction independently of abbreviation spelling, admitting a linear index and refusing a product of two parameters on both sides of a contract, instead of evaluating it once into a hidden slot or forbidding a range term merely because it uses a define name.

Decision: Every function names its result in the signature so that ensures can refer to it, and a postcondition about a Result's or an Option's success value writes `Ok(value: name)` or `Some(value: name)` to bind the payload, which supplies exactly the data an unrouted result of the payload's type would, because the result name stands for the whole value while the arithmetic facts the checker tracks live on the integer payload inside it or on the integer fields and measures of a struct payload, and an Option helper could otherwise state its payload bound only after becoming `Result<T, unit>`, as the [writer-lost-facts probes](../../../research/investigations/writer-lost-facts/DESIGN.md#shape-4-option-results) show, instead of an unnamed result, a payload-only convention, or an Ok-only route over integer payloads.

Decision: Each requires clause is proved on its own at the call site in the caller's state just before the call, with no fallback runtime check and no callee prologue, and two clauses are the same goal when they name the same operations, types, constants, parameters, and literals after definitions expand, because a goal proved once must be recognized wherever it appears again, and a callee prologue let a helper hide a protected leaf behind a runtime trap, instead of matching goals by spelling or by an algebraic normal form, or checking requirements in a callee-entry prologue.

Decision: A function instance whose requirements contradict each other is legal and simply uncallable: the compiler still checks its structure, ownership, effects, and return shape, lowers an unreachable stub with the right calling convention in place of its body, and publishes no postcondition, because such an instance is harmless dead code that no call site can ever reach, while rejecting it would require the checker to detect every contradiction, which a deterministic no-search checker cannot promise, instead of rejecting such an instance as a source error.

Decision: An exclusive parameter's bare measure or fragment-integer place in ensures denotes its exit state and entry(parameter) selects its entry state, using ordinary dereference and field projections, because a mutating helper must relate the caller's unchanged storage location before and after the call without equating both sides of an increment to the same moment, and a count field kept beside the run it counts could otherwise be neither proved after the body's own write nor kept by the caller across the call's projected write, as the [aggregate-postcondition probe](../../../research/investigations/aggregate-postconditions/DESIGN.md#case-3-parallel-arrays) shows, instead of an owned run round trip, a separate kernel-only spelling, or an entry image for integer places that the body's first write ends.

Decision: An unrouted postcondition, and so a type invariant over a written reference parameter, holds at every exit its caller continues from, every explicit return and every propagated error exit, because the caller receives such a relation on its normal continuation, which a call returning `Err` reaches, instead of leaving the propagated exit unselected, which let a caller hold an exit-state relation the callee never proved, or giving a caller exit-state relations only on the success arm, which would take from every caller facts that a body restoring its state before propagating can prove.

Decision: A normal-return relation may add the one bare own integer parameter chosen for reservation accounting to a side's datum and constant, while window movement still publishes an empty source and a destination length at least its entry length, window splitting publishes the split index as the source length and the same destination lower bound, and a caller needing the exact total reads the destination's length after the call, because an exact window-transfer sum adds two entry measures rather than the scalar-parameter addend admitted by the [retained-byte choice](automatic-facts.md), instead of treating that restricted extension as admission of every two-datum side or publishing an exact window sum outside its declared fragment.

Decision: Linked declarations and source definitions have the same call-site requirement boundary, including a build-selected entry, because native linkage cannot justify a proof the ordinary caller lacks, instead of a launcher exception or an executable requirement check.

Decision: A requirement's places are formed at the callee's body entry, in the state holding the requirements written before its clause, and a definition's places in the first requirement whose expansion reaches them, so every subscript in such a place owes its bounds obligation there, because the callee establishes the requirement as a fact in its own entry state and a subscripted place is a term only where its subscripts are discharged, instead of forming the place in each caller's instantiated goal or leaving clause subscripts unjudged. The [readonly-field term investigation](../../../research/investigations/readonly-field-terms/DESIGN.md#soundness-every-change-is-an-overlapping-write) records the probe that exposed the gap and the cases that pin the rule.

Decision: A postcondition's places are formed at each of its selected returns, in the context that return proves the clause in, so every subscript in such a place owes its bounds obligation at each of them, judged over what the place denotes: a parameter written as a subscript offset is its entry value even after the body rebinds it, and a subscript of a base the place reads at function entry, a by-value parameter's, a reference parameter's whose row declares no write rooted at it, or one written through `entry(p)`, is judged against that base's length at entry, while a base of a written reference parameter's exit state is judged against its length at the return, and below a rebound offset against an element no term names; the relation reads such an offset at a return only while nothing has rebound it, and each caller replaces it by the call's actual, a literal or named const included, because the relation is claimed only at the returns that select it, where a routed clause's subscript may hold only on the success path the body guards, the clause names the entry element, and the caller receives the relation in place of the callee's proof, instead of forming the places at body entry, leaving their subscripts unjudged, judging them on the offset's current binding and the base's exit length, or leaving a formal offset unsubstituted, which made two different elements one term.

Decision: A requirement whose complete goal is one integer comparison establishes that exact two-term relation at the callee's body entry when each side reduces to at most one term plus a folded constant through term-free sums, differences and products and widening conversions, such as `i + 1_u32 <= b` or a definition `d = i + 1_u32` compared as `cvt::<u32, u64>(d) <= cvt::<u32, u64>(b)`, a symbolic const-generic parameter counting as a term so that `i + n <= b` has no entry projection, and the entry rule alone defines that projection and uses it for the root, for the members of the signed decomposition and for the ordering leaves that take no affine premise, because widening conversions and constant displacement preserve the mathematical value, the postcondition side already admits a datum displaced by a constant, and a writer's natural chained bounds `i + 1 <= b`, `b + 1 <= c` otherwise need explicit proof steps the checker already avoids, instead of admitting only bare terms, constants and measure terms, which made acceptance of the displaced form rest on the implementation rather than the specification.

Rejected:
- Narrowing the checker's entry projection to bare terms, constants and measure terms: rejected because the displaced form is sound under mathematical-value comparison and writers' natural `i + 1 <= b` chains would need explicit proof steps.
- Widening the L0 projection that ENT-2 defines to the same sides: rejected because the derivation of every goal, not only a requirement at body entry, reads that projection, so the change would reach goals outside the requirement-entry registration this decision covers and needs its own choice.
- A single final requirement block with local bindings and one Boolean check: rejected because it was spelled like executable code so its erased status was invisible, an abbreviation used by both requires and ensures had to be written twice, and the result had no name.
- Adding two entry measures on one normal-return relation side so that moving or splitting a window could publish their exact sum: rejected because the chosen extension admits one bare scalar parameter as the addend, not a second measure, and the window caller can observe the destination's exact length after the call; admitting a second entry measure requires a separate choice rather than following from the reservation-accounting choice.
- Callee-entry prologue evaluating the requirement on every invocation: rejected because it let a helper hide a protected leaf behind a runtime trap and added the prologue's reads to the callee effect row.
- Forming a requirement's places in each caller's instantiated goal: rejected because the fact is established in the callee's entry state, where the caller's proof of the subscript is not available, so the callee would hold a fact over a place that is no term in its own state.
- Leaving clause subscripts unjudged: rejected because a requirement could then name an element that does not exist yet, and its fact survived the append that creates that element, which let a loop bounded by the element's field read past another storage's length.
- Forming a postcondition's places at body entry: rejected because a routed clause's subscript can then not rely on the guard that selects its success return, so a function bounding its index only on the success path is refused.
- Leaving a postcondition place's subscripts unjudged: rejected because the relation then names an element that need not exist, and a function with an unbounded index was accepted.
- Judging a postcondition place's subscript on the offset's current binding and the base's length at the return: rejected because the clause names the entry element, so an index equal to the entry length was discharged once the body appended an element, and a rebound offset in bounds hid an entry offset that was not.
- Reading the relation over a rebound offset parameter through an entry datum of the offset: rejected because a place's offset must be a tracked place or a constant so that the place's term is killed through the offset's support, and an entry datum is neither; only the bound of the subscript is judged on the entry value.
