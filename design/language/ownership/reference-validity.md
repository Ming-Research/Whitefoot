Decision: A reference names a path that starts at a local variable, a parameter, or a named constant and continues through fields (a heap cell's content being its field `inner`), the referent of a reference through postfix `^`, an index, a range, or the payload of an enum variant, and the reference variable is not storage of its own, so forming a reference to a reference variable is refused and extending a reference names the longer path rather than pointing at the reference, because a name for a path holds no address a program could copy or alias and can always be formed again, instead of a pointer value with an identity of its own.

Decision: Ordinary and proof places use one explicit postfix `^` step for whole referents and projections, because it composes paths in reading order with one punctuation byte and no collision with arithmetic tokens, instead of prefix wrapping, automatic projection, or separate whole-access and selector forms; the [caret comparison](../../../research/investigations/contract-surface/OWNERSHIP.md#selected-postfix-caret) records the alternatives and limits.

Decision: A checked reference to an existing payload retains that selected place after the selecting match ends, while any newly written payload selection still requires a current variant fact, because ending a lexical proof scope does not change the selected storage and iterative descent must carry its selected address across the backedge, instead of invalidating an unchanged address solely when its selecting arm ends.

Decision: An index inside a path is evaluated once when the reference is formed and the path records that value, because a later assignment to the variable that supplied the index must not silently retarget a live reference, instead of rereading the index bindings at every use.

Decision: A reference loses validity when its target or an ancestor is moved or released, when a proper ancestor is structurally written, when its root ends scope, or when a window operation destroys its selection, with unknown ancestry judged conservatively and primitive leaf stores preserving the pointer but killing overlapping value facts, because validity describes continued existence of one captured place while facts describe its current contents, instead of tying captured-reference validity to an arm-scoped refinement or extending pointer preservation to value proofs.

Decision: A reference passed to a call is protected only from content writes at or below its own captured target, and is still invalidated by another actual's destructive ancestor write, because argument membership cannot keep removed storage alive, instead of exempting every actual reference from post-call invalidation.

Decision: A move never re-roots an existing reference: after a value is moved to a new owner, references formed through the old place are invalid rather than reinterpreted as references into the new one, because the path they name has ceased to exist even when the bytes did not move, instead of silently retargeting them at the move.

Rejected:
- Keeping a reference usable across a write to a proper prefix of its path when the storage it names is provably untouched: rejected because the prefix write is exactly the event that may replace, reallocate, or release what the rest of the path was interpreted against, and deciding it otherwise would need the contents of the operation that wrote the prefix.
- Invalidating a reference when the storage at its path is written: rejected because changing the value a reference names is the ordinary use of a reference, and a check that ended validity there would leave no writes at all.
- Invalidating a payload reference when its selecting test ends: rejected because the ownership witness preserves only the already selected place and publishes no variant fact for a new selection; enum replacement and owner destruction still invalidate it.
- Exempting every actual reference from call invalidation: rejected because a permitted call can replace an ancestor through one actual while a different unused actual names its destroyed descendant.
