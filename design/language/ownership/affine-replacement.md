Decision: The only exchange the language provides is the built-in two-place swap, and replacing the value in a place while keeping the old one is library code that swaps the place with a local holding the new value and returns that local, so no program point observes a vacant place, because a swap with a local performs exactly the moves a dedicated replace would and the language should not carry an operation source code writes at no cost, instead of a dedicated replace operation, a let-only replace statement, or a take that leaves a hole to be refilled later.

Decision: A move out of a field, a heap cell's content field `inner` included except when that content is a runtime-capacity shape or a run of segments (`language/data-model/storage-shapes`), consumes the whole owner: the owner ceases to exist, its other affine parts are released, and a remaining linear part refuses the move unless it is taken in the same destructuring, because a partially moved owner is a hole under another name, and a whole-owner consume keeps every place a program can name either wholly present or gone, instead of a partial move that leaves the owner alive with one component missing.

Decision: A move out of a slot of a window or an element of an array is refused, the ways out being the removing operations, the place exchange, and the two-place exchange, because those slots are covered by a length or by an always-filled invariant and nothing records that one of them is empty, instead of an element take carrying a later refill obligation.

Decision: Assigning to a place the result of a function applied to that place's own value is one atomic update with no program point between the read and the commit, admitted when that function returns the place's type through every exit with no failure exit and neither writes, moves out of, nor releases any prefix of the place, because termination is not a checked property of any function and a function that diverges commits nothing while the program never continues, so the only totality the update needs is the absence of a failure exit, and because rebuilding a node in place is then written directly and a failure is expressed as an enum value stored back into the place, instead of moving the value out into a temporary and assigning it back across an observable gap.

Decision: A dead binding, one whose value has been consumed, is writable only as the complete binding, by a `set` whose target is that complete binding, and that commit reinitializes it, while a place projected, dereferenced, or subscripted from a dead root is never writable, because the loop rule already admits a body that moves a binding declared outside the loop and reinitializes it before the backedge, a fallible step inside a loop cannot use the atomic update form, whose function must have no failure exit, and a wholly dead binding is not a hole, every place the program can name still being either wholly present or gone, instead of a dead root that nothing revives, which contradicted that loop rule, or a write into a part of a dead owner, which would bring one component back beside missing ones.

Decision: Element-level vacancy is a value, an Option-shaped element checked by an ordinary match, and never a checker state, because per-place flow-sensitive type states are exactly what this ownership model excludes and vacancy would otherwise leak into every boundary signature, instead of typed holes tracked across program points.

Rejected:
- A bare take that is legal when the checker proves the hole is refilled before scope end: rejected because a hole open across statements needs per-place vacancy flow, prohibition or repair of every scope-leaving edge in the window, and a meaning for a reference whose path reaches a vacant place, buying only a use-then-refill window no consumer needs.
- Typed holes, flowing a taken slot to an Option-like vacant type state: rejected because per-place flow-sensitive type states are exactly what this model excludes, and vacancy would leak into every boundary signature.
- Refusing whole-binding exchange on slice-typed and arena-typed places: rejected because neither is a type any more: a range is a reference formed from indexable storage and an arena is ordinary storage used with an append as allocation, so no value carries the static origin set or the confinement the refusal protected.
