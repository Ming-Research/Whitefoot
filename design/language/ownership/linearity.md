Decision: A value is linear, lacking the drop capability (`language/ownership/copy-classification`), exactly when its type is a nominal whose declaration carries the `nodrop` modifier, which is written on types standing for an external resource, or when it contains such a value at any depth through a struct, an enum, an array, a window or a heap cell, and never because of the scope it happens to be in, because there is one heap that every scope can reach, so no scope can fail to hold what a release needs and a scope-relative class would vary a type's obligation without any difference in what its reclamation requires, instead of linearity read against the capabilities a scope holds.

Decision: The compiler never releases a linear value and refuses a linear binding that is live on an edge leaving its scope, the only routes out being moving it whole into a consuming operation and, for a struct that is not opaque, destructuring it whole so that each linear component is consumed (`language/data-model/opaque-struct`), because the obligation is exactly that some explicit operation consumes the value on every exit path, instead of a derived release that could discharge the obligation silently.

Decision: A window or array whose element type is linear is itself linear, and the block is finished by an explicit operation that consumes it and whose contract requires its length to be zero, because the emptiness that makes the block reclaimable is a runtime length the program can prove rather than a property of the element type, so the reclamation stays inside the ordinary proof obligation and a source-defined growable container can still reclaim an emptied old block, instead of exempting an element edge at a derived release whenever a length is statically zero.

Decision: Proposed: The prelude supplies the ordinary consuming function `release<T: drop>(value: T) -> result: unit pure`, whose parameter takes its ordinary end-of-function release, because firn wrote the equivalent `fn aof_rw_release<T: drop>(value: T) -> result: unit pure { return unit; }` three times and [the access-effects amendment map, item 46](../../../research/investigations/access-effects/SPEC-AMENDMENT-MAP.md#owner-rulings-needed-before-the-corresponding-step) proposed a shared prelude function, instead of introducing block statements or requiring each project to define an empty consuming function. This does not introduce the separate early-release mechanism rejected below.

Rejected:
- An early explicit release distinct from the scope-exit release: rejected because it was defined over release leaves that spend a store's provider, and with one heap that no value names there is no such leaf to release early and no capability for the form to name.
- An unchecked backing-only release operation: rejected because a wrong precondition could leak live elements through a second release mechanism outside the proved release walk; the admitted form is the one whose contract requires the length to be zero.
