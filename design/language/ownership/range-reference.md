Decision: A contiguous range reference is formed as the path step `&x[lo..hi]` and has parameter type `&[T]`, carrying only its length and naming an Array, Slots, or another contiguous range reference after proving `lo <= hi <= x.len`; Ring ranges remain outside this boundary even when empty or non-wrapping, because the admitted formation rule always supplies one contiguous extent without a separate head-and-wrap premise and the present Deque library uses slot visitation, instead of treating logical Ring bounds alone as sufficient for a contiguous range. This retains REF-4's current restriction; it does not claim that slot visitation meets a zero-copy two-span consumer's contract.

Decision: A range is separated only by the judgment every other pair of paths uses, different roots, another range or an index proved apart from it, or a window's append slot or free slots when the range is proved empty or to end at or below the window's length in the state where the two places are compared, as an indexed position is, and overlaps conservatively otherwise, the window's last filled slot included, since a row's `last` stands for every slot the callee's successive take-backs reach; a proved separation of a range separates everything reached below it, because a range is a step in a path and warrants no second disjointness mechanism, instead of comparing value-carried origin sets at call boundaries. The [one-argument rows investigation](../../../research/investigations/one-argument-rows/DESIGN.md#follow-up-an-index-or-a-window-part-beside-a-range) records the orderings, the window rows and their cases.

Decision: A function never returns a range reference; a helper that selects part of a storage returns indices with their bounds relation in `ensures` and the caller forms the range, and a recursive subdivision forms its sub-ranges from the range reference it received and passes them to its own calls, because the caller already holds the path the range is formed from, so one address computation replaces the whole apparatus that made a returned view's origin knowable from a signature, instead of a view result with a declared origin ceiling and a rule giving each result of one call its own formal region.

Decision: A range over Paged has its own parameter-only reference kind &Run<T>, with one captured length, element subscripts and same-kind re-slicing, while a selected initialized page supplies an ordinary &[T], because a logical run may cross allocations but a page is contiguous ([paged range requirements](../../../research/investigations/paged-storage/DESIGN.md#language-surface)), instead of making a noncontiguous run masquerade as a pointer-and-count range or allowing references to escape. Run is a prelude name, not a stored type.

Decision: A page reference is one captured page step contained in the filled window, distinct proved page indices separate their descendants, and a page conservatively overlaps every element index and range at the same Paged origin, because the selected fact language has no relation between a slot and its page, instead of inferring such separation from target-dependent page arithmetic. Its captured extent follows the same append-preserving and removal-invalidating lifetime as a Slots range; formation reads the length word so that it cannot overlap an append that changes the extent.

Rejected:
- `Slice` and `MutSlice` as first-class values that may be bound, moved, stored, or returned: rejected because a value that reaches storage it does not own is a reference in value clothing, which the closure of aggregates under owned values and the no-escape rule for references both exclude.
- A shared child view of an exclusive view, with the parent frozen against element writes while the child is live: rejected because with no permission marker on a reference a second range over the same storage is simply a second path, and the call-site and adjacent-statement checks decide every access from path overlap alone.
- Admitting a Ring range solely from its logical bounds: rejected because those bounds do not show that the physical extent is contiguous, so the pointer/count range representation would require a separate proved-contiguity rule or a different representation.
- Replaced clause, that different roots and indices or ranges proved distinct are the only separations of a range: rejected because it gave an index or a window part beside a range no family, so a row such as `reads(values[start..end]), writes(values[slot])` was compared and refused at every call, even one passing `start: 0_u64, end: 2_u64, slot: 3_u64`, and a write through a range killed every fact on the elements beside it.
- Classing an index, a window's append slot or its free slots beside a range with the step pairs that overlap at every position, so that no call compares them: rejected because some values separate such a pair, so the call would admit a row whose read range holds the written slot, and with no family to separate the pair a write beside a range would still kill every caller fact below it, where the call proving the pair apart, as it proves two indices apart, keeps those facts.
