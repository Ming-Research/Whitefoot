Decision: Exchanging the values of two places is a built-in two-place operation taking a reference to each, admitted even when the two references name the same place because exchanging a value with itself does nothing, because a partition or heap-adjustment loop then exchanges two runtime-selected slots with no distinctness proof, no index branch and no temporary hole, and the earlier objection that an exchange would be a third mutation path no longer holds now that a write through a reference is an ordinary declared effect and no loan or initialization state is keyed to a binding's death, instead of expressing the exchange as one multi-place commit that reads every target out before writing any.

Decision: Exchange admits equal captured targets and disjoint storage, but requires proof that neither target may be a proper ancestor of the other, because swapping a recursive owner with its own descendant would manufacture a cycle or lose ownership while equal array slots remain a harmless no-op, instead of extending the equality allowance to every possible overlap of unknown-depth targets.

Decision: Exchange's equality allowance covers two equal-depth slots whose containing paths are identical step for step or differ only in index steps, because the first index step at which the two paths select different elements of one array separates their storage, and when no step selects different elements the two slots are the same slot, so an exchange of two elements of two runtime-selected rows needs no proof that the rows are the same row, instead of limiting the allowance to slots under one identical array or window.

Decision: An exchange is a place in the placement table that its type parameter takes, so a runtime-capacity window, a run of segments or a paged window, whose only home is a heap cell's content, is never exchanged in place and a program exchanges the owning cells instead, while a shared map keeps its exchange of entries, because an in-place exchange moves one fixed-size value and these contents differ in size with their capacity, which let a capacity-1 block carry a capacity-64 header and write past its end (tests/conformance/cases/type9-neg-runtime-slots-content-swap.wf), and because a type parameter taking a place carries the refusal through generic bodies and function-kind actuals by the existing transitive rule, instead of exchanging the two cells' pointers when both places are cell contents or exchanging whole blocks.

Rejected:
- Express an exchange as one multi-place commit whose values are the moved bindings: rejected because such a commit must prove its two target indices distinct before it can order its writes, which puts a proof obligation or a runtime branch into every partition loop, while the built-in exchange needs neither and never names a vacant place.
- Require distinctness for every exchange: rejected because the existing same-slot allowance serves indexed partition and heap adjustment without a branch; the additional condition excludes ancestry, not equality.
- Preserve unrestricted overlap under the existing equality allowance: rejected because equality and ancestry have different ownership consequences, exposed by tests/conformance/cases/op11-neg-wildcard-ancestor-exchange.wf.
- Tighten the checker to require slots under one identical array or window: rejected because the checker's relation is sound for rows selected by unrelated indices, so the tightening would refuse an exchange that is correct and make a writer prove two rows identical or choose another form, while range separation already reads containing paths by the same relation.
- Exchange two cell contents by exchanging the cells' pointers: rejected because a content reached through a reference parameter has no cell slot to rewrite, so the same written exchange would be admitted in one place and refused in another.
- Exchange two runtime-capacity contents by exchanging whole blocks in place: rejected because blocks of different capacities cannot hold each other's contents without reallocation and rewriting both owners, which an exchange through references cannot reach.
