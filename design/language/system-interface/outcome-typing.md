Decision: Library acquisition, close and host-transfer interfaces use ordinary Result with operation-specific payload types, while the scoped runner uses the ownership-return variants selected in [scoped metering](scoped-metering.md), because ordinary operation failures then propagate without conversion from equivalent success/error variants and a runner outcome explicitly pairs the scope owner with either the uncalled argument or the returned result, instead of redundant acquisition enums or a shared outcome union coupling unrelated reading, writing and copying callers.

Decision: Every `IoError` variant a host refusal produces carries fixed-size inline error detail, a numeric native code and an ordinary origin discriminator, and `DeadlinePassed` and `Cancelled`, which the program's own bounds produce, carry none, because a heap-backed message would add an allocation obligation to every fallible library call and a deadline or cancellation has no native code, instead of an owned diagnostic string or buffer, or a native code invented for the deadline.

Rejected:
- Requiring Result for every library success-or-failure distinction: rejected because the selected scope runner names whether the body ran and returns the owner with different argument and result payloads; acquisition and close retain Result.
- Replaced decision beginning "IoError carries fixed-size inline error detail": rejected because the variant `DeadlinePassed` reports the program's own bound, which no host produces, so it has no native code or origin to carry.
