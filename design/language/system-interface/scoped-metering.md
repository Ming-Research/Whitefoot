Decision: Scoped live bytes use exact allocation-origin attribution, with one retained origin per concurrent-map table or chunk and runtime structure and with moves preserving it and free or resize charging it, because a completed transfer of an 8-byte block from allocator A to freeing context B leaves current-scope accounting at A = 8 and B = -8 instead of zero; compiler-emitted heap follows the same semantics, with the choice of a 16-byte origin prefix or per-scope arenas deferred until the prefix's memory cost is measured on firn's actual value-size distribution, instead of a transfer-dependent ledger or a sealed region that forbids returning built storage ([accounting comparison](../../../research/investigations/scoped-metering/README.md#ownership-transfer-is-a-semantic-decision)).

Decision: One nodrop MeterScope owns entry and explicit close, busy close returns that owner for polling while activity, descendants or origin-bearing storage remain, and droppable generation-checked ScopeViews retain no slot and read Option<u64> with None after close, using target-declared finite slots with typed capacity refusal and synchronized safe reuse, because sampled zero cannot establish retirement and unconditional release cannot return a busy owner, instead of waiting close, hidden deferred retirement, shared owner aliases or unbounded accounting metadata ([ownership comparison](../../../research/investigations/scoped-metering/README.md#ownership-closing-and-observation)).

Decision: The all-value pure waits scope_run consumes a MeterScope and argument, returns ScopeRun with the owner and result or the owner and refused argument, and has a checked Whitefoot body in its host module over private build-provided entry and leave primitives, because ordinary interface monomorphization preserves the supplied ScopeBody member's direct call and the linear result already restricts spawning to a let binding, instead of public setters, a new spawn operand, a borrowed-environment runner or a separately synthesized body per instance ([surface comparison](../../../research/investigations/scoped-metering/README.md#surface-alternatives)).

Decision: scope_open selects the default account as parent, scope_open_child borrows an explicit parent owner, inclusive readings count every descendant with generation-validated ancestry, and scope_run refuses entry unless the current scope is its recorded parent, because explicit fixed ancestry states which bytes a parent includes and generation validation excludes an unrelated reused slot; the remaining delimited ambient entry check is a chosen execution input and not a fact supplied by an effect row, instead of implicit parenting or innermost-only counts ([nesting comparison](../../../research/investigations/scoped-metering/README.md#nesting-ambient-state-and-execution-inputs)).

Decision: Acceptance requires all [investigation evidence](../../../research/investigations/scoped-metering/README.md#embedded-targets-and-measurements-before-acceptance), including independent exact quiescent inventories, transfer and lifecycle races, interleaved same-source comparisons with twin controls, at most 1 percent workload slowdown and 1 ns added per accounting event, overlapping firn rewrites with no refused writes or rewrite-correlated key collapse and at most 0.2 percent sampled adjusted overshoot, prefix versus arena memory cost, admission-frequency reads and a named weak embedded target with owner-selected RAM and time budgets, because desktop estimates and two counters agreeing establish neither exact attribution nor acceptable weak-target cost, instead of qualifying desktop firn alone; the weak target and budgets remain to be selected before embedded acceptance.

Rejected:
- Current-scope debit on release or resize: rejected because cross-scope transfer leaves an unbounded attribution error even after all work has completed.
- A sealed storage region or re-accounting only arguments and results: rejected because the former forbids supported returned storage and incoming buffers while the latter leaves shared-state and map transfer channels open.
- Selecting attribution through whichever meter is passed: rejected because an observation handle does not identify a delimited entry and restoration boundary.
- Public enter and restore setters: rejected because early returns and nested calls would expose an unbalanced restoration obligation to writers.
- A scope operand only on spawn: rejected because it adds syntax and still needs a separate direct-call scoping form.
- A borrowed-environment runner as the primary surface: rejected because it adds a writes(env) transfer channel and still requires an owned wrapper for spawning.
- Synthesizing a build-provided body per generic instance: rejected because a checked Whitefoot body already instantiates through the ordinary path without a second generation mechanism.
- Waiting close: rejected because a caller retaining origin storage can wait on its own obligation, requiring an additional progress protocol.
- Droppable owners with deferred retirement: rejected because hidden runtime state would decide later capacity refusal instead of an explicit successful close.
- Shared nodrop owner aliases: rejected because last-owner tracking adds lifecycle state without making the owner eligible for drop-bounded shared containers.
- Unbounded metadata or never reusing otherwise reusable slots: rejected because the former loses a target RAM bound and the latter exhausts repeated scope invocations; a generation-exhausted slot still cannot alias an old view.
- Inferring the parent from ambient state: rejected because the parent can be stated explicitly even though entry retains the selected parent check.
- Innermost-only readings: rejected because they omit a parent's explicit child scopes from its requested descendant count.
- Embedded suitability inferred from desktop timings: rejected because weak-target storage layout and allocation and read costs need a named target and its own budgets.
