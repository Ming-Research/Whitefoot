Decision: A process memory reading requires the opaque nocopy MemoryMeter in std::process, appended to Inputs and shared through meter_share, and heap_in_use and resident_bytes write their meter, because the observed resource is the process while the Clock pattern provides an ordinary capability and footprint that orders observations, instead of a time capability, an ambient observation without a parameter or a handle-factory credit.

Decision: Releasing a map's reserve is the generic host function std::process::release_map_reserve, with reads(map) and writes(meter), because its result is a decrease in the process heap reading and writing the memory meter orders it with those readings while keeping it out of atomic guards, instead of the PRE-1 function shared_map_release_reserve writing the handle, which forces callers to claim a write of an unchanged handle.

Decision: heap_in_use counts allocation requests and matching releases, with emitted storage counted by requested bytes and runtime-pool storage by granted bytes, because each allocation path and release knows its extent and eviction needs a reading that falls when storage is released, instead of querying allocator usable sizes on release, walking allocator arenas when reading or using the resident set as the heap count ([investigation](../../../research/investigations/memory-statistics/README.md)).

Decision: Allocation accounting uses 64-bit counters taken modulo 2^64, local to the calling driver or compute worker and published with single-writer atomic stores, and a pool counter under its existing lock; a read adds them modulo 2^64, which is exact because the live total is below 2^63 however far one driver's allocations and another's releases of the same blocks drive their counters apart, and clamps a total that a concurrent move made negative to zero, giving an exact quiescent reading and a non-instantaneous concurrent reading whose error is bounded by the bytes moved during that read, because allocation and release can occur on different drivers and a shared write on every allocation would contend on one cache line, instead of the one shared atomic counter Redis 7.0.15 uses ([concurrent observations](../../../research/investigations/memory-statistics/README.md#implementation-findings)).

Decision: Counted allocation wrappers live in a separate native translation unit referenced only by emitted heap code, while counter storage and readings remain allocator-free, because a program built without heap use must retain linkage with no malloc or free references, instead of putting allocator references in the always-linked completion bridge.

Decision: resident_bytes returns Option<u64>, with Some for a host-reported resident set and None when the host cannot report it, and each memory reading is an execution input, because host unavailability is recoverable and retained pages differ from live requested storage, instead of terminating for a failed observation, conflating an eviction budget with resident pages or deriving source acceptance from a host reading.

Rejected:
- Allocator usable-size queries on release: rejected because their meaning and availability depend on the platform allocator and every release would pay that lookup.
- Allocator-wide queries on reading: rejected because arena traversal and allocator locking make their cost unsuitable for the intended per-command observation, and the platforms expose different quantities.
- Resident set as heap_in_use: rejected because pages can remain resident after their live allocations are freed, so eviction would not observe its own progress.
- Signed counters that stop, saturate or are rebased at a limit: rejected because a block allocated on one driver and released on another drives two counters apart without bound while the live total stays small, so a limit on one counter would fail a program whose heap never grows.
- One shared atomic counter, as used by Redis 7.0.15: rejected because all drivers would write one cache line on every allocation and release, whereas the selected bounded concurrent observation permits per-driver writes.
- Placing MemoryMeter in std::time: rejected because it observes process memory, and following the clock's capability discipline does not make memory a clock.
