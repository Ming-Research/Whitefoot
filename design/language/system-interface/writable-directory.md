Decision: `Inputs.cwd` is a `Directory`, an ordinary struct of a `DirectoryRead` and a `DirectoryWrite` that close separately, every write operation takes the write half, and a program weakens the directory to read-only by closing the write half, because well-typed code may pair halves of different directories and each half's own close keeps cleanup correct for any pair, as for `TcpConnection`, while a function given only the read half cannot write below it (owner's rulings Q25 and Q30), instead of one handle with both authorities and a function that weakens it, write authority derived from read authority, or one directory type for both.

Decision: Files support appending, setting an open file's length, syncing its bytes, and renaming, removing and syncing entries within one directory through its write half, with open files retaining their bytes and usability after replacement or removal and sync promising only handoff to the host's durability mechanism, because a log whose end did not load must be cut before appending (owner's ruling Q40), and an AOF rewrite needs a synced temporary file atomically renamed over the log followed by directory sync and removal of obsolete names ([file-replacement proposal A](../../../research/investigations/file-replacement/README.md#proposal)), instead of positioned writes, which leave a partly rewritten log on interruption, a combined replacement operation that cannot remove obsolete parts, or a specified crash model, which no conformance case could test (owner's ruling Q26).

Decision: A program opens the write half of a directory below a write half, creating it empty when no entry has the name and keeping its entries when one does, and the open reads its root as `open_append` does, because a writable directory hierarchy, such as the directory Redis 7.0.15 keeps its append-only files in, is created when missing and reopened with its files on every start ([proposal A](../../../research/investigations/writable-subdirectories/README.md#proposal)), and an open that may create an entry asks no more of its root than `open_append` does, two creations at one name being ordered only through state both reach, such as one factory ([effects](../../../research/investigations/writable-subdirectories/README.md#effects-of-the-operations-on-their-root)), instead of a separate directory creation, which costs a second host call on Windows where one call creates or opens, to be reopened when a program needs exclusive creation, or a flat layout in the program, which leaves a directory hierarchy inexpressible.

Decision: A file moves from below one directory's write half to below another's with `rename_file`'s atomic replacement and open-handle rule, through a second operation, because Redis 7.0.15 upgrades an old single append-only file by moving it from the working directory into its directory ([proposal E](../../../research/investigations/writable-subdirectories/README.md#moving-a-file-between-directories)), and a rename writes each directory it changes so that the host orders it against the directory's other changes, while one handle passed as both written roots of a call overlaps itself ([effects](../../../research/investigations/writable-subdirectories/README.md#effects-of-the-operations-on-their-root)), instead of giving `rename_file` two roots, which a rename within one directory could not call.

Decision: A name given with a root denotes an entry directly below that root only when it is one nonempty path component other than `.` and `..`, and every operation taking such a name refuses any other with `InvalidPath`, because a name is to select an entry of its root, so that a function given a subdirectory's write half cannot obtain the write half of the directory above it, and one rule for every operation taking a name keeps the two halves' names alike ([names](../../../research/investigations/writable-subdirectories/README.md#names)), instead of passing `.` and `..` to the host, which resolves them to the directory itself and its parent; a path given to `open_read` is not such a name and follows the next decision.

Decision: A path given to `open_read` selects a file by looking its components up in order, each as the entry of that name directly below the directory the components before it reached, `relative_path` returns `PathInvalid` for a component `..` as it does for a leading separator, and a symbolic link, on Windows a reparse point, at any component, the last included, ends the open with an error, because a directory handed to a function is to bound what the function reaches whatever bytes it is given, the name operations already do, and a path read from a file or an argument is as untrusted as a name, while refusing `..` in the conversion that already refuses an absolute path leaves `open_read` no new error to report and every `RelativePath` free of a parent step, and the walk uses only the one-component opens the adapters already make, so POSIX and Windows hosts give the same answer for the same path, instead of leaving the lookup to the host, which resolves `..` and every link out of the root.

Rejected:
- One `Directory` handle with both authorities and a consuming function that weakens it: rejected because every read operation would then need a second form or a weakening first, and the handle would hide a two-count close behind one value.
- Opening a write authority from a read authority: rejected because the read-write separation would then be visible only in types, not in what a function can reach.
- A specified crash-consistency model for `sync_file`: rejected because it cannot be tested and promises more than the host interfaces give, as the owner ruled.
- Refusing only a component `..` and following links (an `open_read` that stays on the host's lookup otherwise): rejected because a link below the root still leaves it, so a function given a read half would reach what the process can through any link in the tree, which the name operations already prevent.
- Refusing only a `..` that lexically rises above the root, and folding the others away: rejected because the fold gives one file two spellings and a second rule to state and test, and a parent step names nothing a path without it cannot, since the entry it cancels is below the root already.
- Keeping the host's lookup for `open_read` and writing that fact into the specification: rejected because a root then bounds only the name operations, the multi-component route is the one a path read from untrusted bytes takes, and the only authority a function holding a read half cannot be given is one the specification promises.
