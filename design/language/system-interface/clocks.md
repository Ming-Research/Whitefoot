Decision: The entry receives two clocks in `Inputs`, a `Clock` for monotonic time and a `WallClock` for calendar time, and a monotonic reading is an `Instant`, an opaque struct of `std::time` with one private `u64` field that gives it the copy capability and that only host functions form, because a function given only a `Clock` then provably does not depend on a calendar the host may set back, a deadline computed once is passed to many calls, and an instant a program could write as an integer would let a sleep or a deadline name any time without a clock read (owner's rulings Q23, Q27 and Q28), instead of one clock with both reads, a clock reached through the handle factory, a fieldless opaque `Instant` left copy against the rule that every host handle is `nocopy` or `nodrop`, a `nocopy` `Instant` moved into every deadline, or a public integer ([design](../../../research/investigations/io-model/TIME-AND-FILES.md#stdtime)).

Decision: `now` writes its clock and every `Instant` operation is total, `instant_after` saturating at the latest instant and `nanoseconds_from` answering zero for a pair out of order, because two host operations are ordered only when their footprints overlap with a write [HOST-1] and two adjacent reads may overlap [PAR-1], so a read that only read its clock could return an instant before the previous one, and no fact source proves the clock's order, so an operation with a domain would leave its caller an obligation no proof discharges, instead of a clock read that promises no order or a subtraction that requires its operands ordered.

Decision: `sleep_until` and every deadline take an `Instant` and no clock, because an `Instant` exists only as a reading of a clock the program already holds, so waiting for one observes nothing a clock read has not, instead of a clock parameter on each waiting operation.

Rejected:
- One `Clock` with both a monotonic and a calendar read: rejected because every function that bounds a wait would then also reach the settable calendar, which the capability dossier's separation of the two sources also refused.
- A clock reached through the handle factory: rejected because the factory is the budget of host handles, and a clock is a capability of the invocation, which the entry receives as it receives its other capabilities.
- A public integer instant: rejected because it is forgeable, which turns `sleep_until` and every deadline into access to time without a clock.
