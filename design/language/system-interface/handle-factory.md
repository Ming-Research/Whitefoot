Decision: Acquisition and close take the handle factory as a reference parameter that their declared effect row names as written, spending one credit on successful acquisition, restoring it on refusal and returning it on the explicit close that releases the allocation, because the call's own comparison of its substituted effect paths already refuses any second access to that same factory within the call, so the accounting stays visible without any exclusivity marker on the reference, implicit creator links, or cancellation effects, instead of hidden global capacity or one-shot permits with implicit cancellation.

Decision: `factory_share` returns a second factory drawing on the same budget, so that a waiting call run as a context carries its own factory while the host limit stays one budget, because such a call takes only value parameters and cannot borrow its starter's factory [WAIT-2], and a refusal caused by another context's acquisitions is one more outcome of an acquisition the host may already refuse at any call, instead of splitting the credits into fixed partitions, which refuse an acquisition while another partition holds unused credits and, in a server whose contexts close their connections through their own part, move one credit per connection out of the listener's budget for good ([design](../../../research/investigations/io-model/WAITS.md#sharing-between-concurrent-activities)).

Decision: The process's open-files limit is read by `open_files_limit(factory: &HandleFactory)` and raised by `raise_open_files_limit(factory: &HandleFactory, wanted: u64)`, which writes the factory, both returning `Result<OpenFilesLimit, IoError>` with a limit the host reports as unlimited read as 2^64 - 1; on POSIX they use `getrlimit` and `setrlimit` on `RLIMIT_NOFILE`, a request above the soft limit, one above the hard limit included, goes to `setrlimit`, whose refusal (POSIX's `EINVAL` for a soft limit above the hard one) is the result, and a successful raise reports the limits `getrlimit` reads after it and adds max(0, c(m) - c(n)) credits to the factory's budget, n and m being the soft limits before and after, where the invocation budget starts at c(n) = max(0, min(n, 2^20) - 64), because a finite request may be set as unlimited or adjusted by the host, so the requested value is not the limit; every other host, Windows included, answers `Unsupported`. This is because the factory's budget is derived from that limit, so raising the limit changes the factory's state and must be ordered with acquisitions through it, and a raise that left the budget unchanged would not let the program hold more files, as Redis's startup raise to its client limit needs; Windows has no per-process limit of this kind, its C runtime's `_setmaxstdio` bounding only stdio streams. It is instead of a new limit capability in `Inputs`, a function on `StopSignals` or `MemoryMeter`, which observe other things, an ambient function with no parameter, or a raise that silently stops at the hard limit.

Decision: `HandleFactory` is a self-changing host handle, so an atomic statement's guard reaches no factory [SHARE-2], because `open_files_limit` reads through it a limit that another process (with `prlimit`, for one) or a raise through a related factory in another context changes with no write to the statement's targets, and a guard is woken only by such a write, instead of keeping factories readable in guards and waking guards on a raise.

Rejected:
- Exclusive factory loans with an early-release prohibition: rejected because the factory's declared write and ordinary pairwise call check already exclude competing access without a second endpoint rule.
- A reservation whose drop silently returns factory credit: rejected because the selected ordinary interface has empty opaque drop and explicit host-state writes; a later reservation API would need explicit consuming return and cancellation outcomes.
- Keeping factories readable in guards and waking guards on a raise: rejected because a change from outside the process has no wake source, so a guard waiting for the limit could still wait forever on a true condition.
- Available factory capacity as a promise that host acquisition succeeds: rejected because other host activity and limits can still refuse an otherwise funded attempt, so refusal remains an ordinary outcome.
