Decision: A program opens files and directories by host path, absolute or relative to a directory it holds, only through a separate host-path authority, a fieldless value the host supplies as an optional input that no program can construct, and a function given only a directory half cannot open by host path, because Firn must open a configuration file named on its command line, an included file and an existing data directory whose paths are read from configuration bytes, while a delegated directory half must keep selecting only entries below it ([option A](../../../../research/investigations/host-paths/DESIGN.md#options)), instead of widening the relative path type or giving every directory a path open (both under Rejected).

Decision: Proposed: the host-path authority offers six opens, a read file, a directory's read half and both halves of an existing directory, each from a host string or from a byte window of a buffer with a stated encoding, and never creates an entry, because an argument path arrives as a host string, a path read from configuration arrives as bytes, and a data directory that must already exist is refused when missing rather than created ([recommended interface](../../../../research/investigations/host-paths/DESIGN.md#recommended-ordinary-interface)), instead of the existing create-if-missing directory open, which hides a misconfigured path by creating an empty directory.

Decision: Proposed: host-path lookup is the host's own lookup from the given directory, following every link and resolving parent components after links, while the single-name opens used for traversal below a directory never follow a link at the name, because a path a user names should mean what the host's own tools take it to mean, and a link reached below a delegated directory must not lead outside it ([parent components](../../../../research/investigations/host-paths/DESIGN.md#parent-components-lexical-or-filesystem-resolution)), instead of lexical normalization, which opens a different file than the host when a component is a link.

Decision: Proposed: a host without host paths, Windows included until its encoding and path dialect are specified, supplies no authority, and its opens refuse with Unsupported without spending a credit, because a target without a host filesystem must still run programs that do not use one ([weak targets](../../../../research/investigations/host-paths/DESIGN.md#weak-and-embedded-targets)), instead of rejecting such targets or specifying the Windows path dialect before its adapter exists, to be reopened when the Windows adapter is built.

Decision: Proposed: the two halves of an existing directory come from one host lookup, the second half duplicating the first's descriptor, take two credits and return both when the open fails, and a byte-window path is copied into a bounded runtime block of at most the host's path limit, because two lookups could select two different directories if an entry is replaced between them, and the copy must outlive the caller's buffer while the open waits ([completion transport](../../../../research/investigations/host-paths/DESIGN.md#completion-transport-lifetime-and-acquisition)), instead of two lookups or borrowing the caller's buffer across the wait.

Rejected:
- Widening the relative path type to accept absolute paths and parents (option B): rejected because the same directory parameter would then authorize paths that ignore it, so an existing write half could reach its parents, and it still cannot express paths read from file bytes or an existing-only directory open.
- A byte-constructed path value with path opens on any directory (option C): rejected because a path is data, not permission, so either a delegated directory gains authority over absolute and escaping paths, or escaping paths are refused and the broad host-path need is not met.
