Decision: A container receives hash, equality, and comparison as explicit function-kind arguments, with formal and actual groups abbreviating their signatures and arguments hygienically, because the owning-map and priority-queue witnesses need reusable behavior without runtime representation or dispatch cost, instead of function values, dictionaries, implicit type-owned implementations, or repeating every member signature at every library layer.

Decision: A formal member's declared effect row and written contract are the authoritative callable boundary, and a supplied actual may refine that boundary, its row a subset of the formal's, its `requires` weaker, and each formal `ensures` discharged by its frame or stronger own `ensures`, while its parameter and result modes and types agree exactly, because a generic caller must retain one written boundary it can read without knowing which implementation was selected, while an implementation that touches less state or demands less of its caller can always stand in for one that demands more, instead of requiring the actual's contract to be structurally equal to the formal's, or deriving the caller's boundary from the selected body.

Decision: Binding discharges a normalized equality between the exit and entry value of one integer place or one measure of an unwritten place directly from the actual's declared row, retaining exact rows and requiring every other postcondition to follow from the actual's own contract, because Halo's Host call permits stack writes while preserving its length and a pure Stop implementation preserves that length without an admissible own entry clause, instead of requiring an explicit postcondition for state the actual cannot change.

Decision: A frame discharge leaves aliasing between the framed place and another parameter's write to each call through the formal, because the formal relation reads the framed place, so the call's contract-read footprint already requires that place to be separated from every other argument's writes, instead of treating different parameter ordinals as independent storage or adding a binding-time condition.

Decision: Member calls use the instantiated formal signature, row and contracts while the selected actual is checked independently, because a container's written boundary must not vary with which implementation is selected, instead of importing an actual body's smaller row or stronger inferred facts into its callers.

Decision: Supplied behavior carries no assumed equality, comparison, or hashing laws, because hostile behavior must still preserve ownership and proved bounds even when the container holds unexpected contents, instead of using an unchecked law as a safety premise or retaining source law declarations without a selected consumer.

Decision: A formal member relates references to its caller through ordinary substituted effect paths and optional held-observation requirements, with no quantified heap region, loan lifetime or store brand, because a coherent observation needs a finite caller-statement origin and protected paths while references remain local path names in one heap, instead of attaching runtime region identities or storage brands to reference types ([held observations](contracts/held-observations.md)).

Rejected:
- An effect row as the complete contract for a coherent held observation: rejected because reads describe accessed paths but cannot require that two arguments originate in one caller-held statement and stay unchanged throughout it; the [ordinary read-helper witness](../../research/investigations/consistent-snapshots/capture-export.md#existing-rules-and-the-missing-relation) supplies the consumer absent from the earlier effect-only decision.
- Let implementations declare wider rows than their bodies exhibit: rejected because it weakens exact effects for every function merely to express a binding guarantee already established by absence of writes.
- Require a formal access covering the framed place whenever the actual writes through another parameter: rejected because the contract-read footprint separates that place at every call through the formal, so the condition only refused bindings that no accepted call could misuse.
- Require stubs to perform a dummy write: rejected because conformance would introduce a runtime state change solely to justify an erased frame guarantee, and the pure Stop body already preserves that state.
- Discharge frame equalities only for actuals that write nothing: rejected because Halo's reads-only host function writes its environment while leaving the stack unwritten, and it still could not restate the guarantee, since an entry clause is admitted only for written parameters.
- Runtime dictionaries or callable values for container behavior: rejected because the selected map and queue need direct-call specialization without runtime storage or dispatch.
- Checking actual rows for equality with the formal row: rejected because an actual that accesses only a declared subfield fits the caller's contract without dummy reads or a runtime adapter.
- An owned function-formal result required to be fresh: rejected because it depended on the removed history of owned values and excluded ordinary ownership-returning functions from the common callable boundary.
- An implication solver or search deciding that an actual's `requires` is weaker and its `ensures` stronger: rejected because automatic derivation is specification-fixed, deterministic and terminating, so a refinement admitted at a binding must be decided by a fixed finite check, not by a search whose success selects acceptance.
