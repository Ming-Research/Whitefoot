Decision: Decimal conversion lives in the checked Whitefoot module std::float_text and returns decimal digits separately from their text layout, because callers need different layouts for the same rounded value and ordinary caller-owned windows already express writing, instead of duplicating digit selection in each writer or extending the trusted host runtime with conversion routines.

Decision: Stage 1 selects exact 800-digit decimal arithmetic with a nonzero-discarded-tail flag for reading, shortest digit selection and significant-digit rounding, with Clinger's single-operation reading path for at most fifteen significant digits and decimal exponents from -22 through 22, because one exact representation serves all three operations and supplies the correctness baseline for later measured optimization, instead of introducing cached-power fast algorithms before a consumer requires their speed. The selected scope and alternatives are recorded in the [float-text investigation](../../../research/investigations/float-text/DESIGN.md#algorithms).

Decision: Shortest conversion selects the fewest digits that round back to the original binary64 value, then the nearest decimal value and an even coefficient on a tie, because this gives the operation an exact value contract independent of an approximate algorithm's output, instead of reproducing Redis's Grisu2 formatting in the standard library; product-specific formatting remains with its caller.

Decision: Reading consumes a whole decimal window and distinguishes syntax failure, nonzero overflow and nonzero underflow, while digit selection reports signed nonfinite cases and significant precision is one through seventeen, because callers must choose their own whitespace, hexadecimal and nonfinite spelling policies and the current consumers need at most seventeen digits, instead of folding those product policies or the Redis integral-value cutoff into the conversion operations. The existing integer writer supplies the caller's integral formatting path.
