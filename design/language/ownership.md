Decision: Ownership is single-owner values consumed by an explicit move, and a reference is a local name for a path rooted at a local or a parameter rather than a borrow that carries a permission marker and a region, because whether a callee may write through a reference parameter is already stated by that function's declared effect row and whether a reference is still usable is an ordinary checked fact about the path it names, so neither a lifetime solution nor an enumerated list of temporary-loan endpoints is needed, instead of shared and exclusive borrow modes held in lexical named or unnamed regions with individually specified loan endpoints.

Decision: All consumers use one conservative overlap relation on complete paths: separation requires different roots, different fields of one struct or one variant payload, or proved distinct indices or ranges; paths through different enum variants overlap, because a single relation lets validity, call interference and parallel permission share the same separation proof, instead of consumer-specific alias analyses. The [reference and effect design](https://github.com/mbbill/Whitefoot/blob/b3341e32ab8d69e2974227aee7146ac16eb2fe00/research/investigations/access-effects/CANDIDATE-X1.md#rule-3-reference-validity-is-a-fact) states this shared judgment; runtime-width partitions still need access to disjoint parts of one block.

Decision: Unknown-depth reference targets have subtree interference covers and distinct current-target identities, with ordinary finite suffix comparison only for accesses sharing a captured target, because covers must conservatively include every possible ancestor or descendant conflict while one current node's sibling fields remain disjoint, instead of treating a wildcard as an ordinary exact path step or proving separation between unrelated cursors from suffix spelling.

Decision: Every release action is derived from the value's type and runs no user code, and no writer declaration, attribute or binding attaches a callable finalizer to any leaving edge, because a user-defined release action would hide code and effects on every scope exit, and with one heap that no value names the derived release needs no store, provider or capability to run, instead of destructors or native finalizers selected by a value's origin.

Decision: There is no global mutable state, only immutable const items, because a function that reached a global directly could not be pure and every proof that rests on purity, the permission for two statements to overlap first among them, would collapse, while a global handed in as a parameter is no different from a value created at the program's root, and with no shared-memory threads there is nothing a global lock would guard, instead of a shared mutable static with an access discipline of its own.

Decision: An indexed position of a window is separated from the window's append slot or its free slots only where the state in which the two places are compared proves the index below the window's length, a place formed or referenced in that state being live by its own bounds obligation, a fact's place at a killing event by that event's entry state, and an index an effect row takes from another argument by the call's entry state, because an index at or beyond the length can name the very slot an append fills, instead of assuming every indexed position live; it is never separated from the window's last filled slot, because a row's `last` stands for every slot the callee's successive take-backs reach, not only the one at call entry, as the [one-argument rows investigation](../../research/investigations/one-argument-rows/DESIGN.md#the-last-filled-slot) records. The [readonly-field term investigation](../../research/investigations/readonly-field-terms/DESIGN.md#soundness-every-change-is-an-overlapping-write) records the probe that exposed the gap and the cases that pin the rule.

Rejected:
- General inferred borrow checking with implicit reborrows and inferred non-lexical lifetimes: rejected because a reference that only names a path has no extent to infer: it stops being usable exactly when a proper prefix of its path is written, moved out of, replaced or released, or when its root leaves scope.
- Keep all non-literal indices overlapping: rejected because insert, remove, heap adjustment and partition algorithms then need extra element movement or allocation to reach two elements already proved to occupy different slots.
- Confine index separation to the targets of a multi-place commit: rejected because the same proof must serve reference validity, calls and statement overlap; the two-place operation is the ordinary [exchange](https://github.com/mbbill/Whitefoot/blob/main/design/language/ownership/exchange.md).
- Treat every access to one allocation as a whole-allocation conflict: rejected because uneven recursive partitions and runtime-width rows need independent access to disjoint parts of one block.
- Range loans with origins transported through view moves: rejected because ordinary reference formation captures indices and endpoints once, while a range reference remains a parameter-only reference kind.
- Keep the overlap decision limited to exact finite paths: rejected because iterative owned-link descent requires finite covers of paths with unbounded runtime depth; this extends that decision's common overlap relation rather than adding a consumer-private alias relation.
- Assuming every indexed position live: rejected because a fact's place need not have been bounded where the event happens, and a requirement over an element not yet appended kept its fact across the append that created the element.
- Never separating an indexed position from the append slot: rejected because an appending call must be provable not to disturb a live reference or a fact about a filled slot, which is the reason the window parts exist.
- Treating an index an effect row takes from another argument as never live: rejected because a call whose requirement bounds that index proves it at entry exactly as it proves two indices distinct, and refusing it would reject aliasing calls whose positions the part definitions already separate.
- Separating an indexed position from the window's last filled slot where `i != r.len - 1` is proved at call entry: rejected because one `writes(r.last)` entry covers every `take_back` a body makes, so the separation would admit a call whose callee takes back the slot another argument reads.
