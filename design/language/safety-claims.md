Decision: The safety claims are stated on one page, `docs/safety-claims.md`, that names for each claim the specification rules it rests on and the conformance cases that check them, and a check in `make static` holds every citation to the specification and the manifest, so a rule must be defined, a case must exist, cite the rule and declare the verdict its column states, a rule no source verdict can tell apart names the manifest annotation that covers it and the test files that name the rule, where any does, and a claim names at least one rejecting and one accepting case, because a reader checking a claim needs the path from claim to rule to case in one place, and a page read by a check turns red when a rule or case it cites changes, instead of prose in the README and essays that cites rules nothing reads. The page is not the rule-to-ground ledger that the decision on the specification standing on its own refuses: it records which cases check which rules, each row is read by the check, and it adds no statement the specification does not make: a claim that is only a reading of several rules says so and cites them.

Decision: What is not claimed sits beside the claims as verbatim quotations of the specification rules that state each limit, namely general race conditions, termination, deadlock, resource availability and a fault in the trusted base, and the check requires each of the five limits to have its row and each quotation to occur in the rule it cites, because a claim shown without its limits reads as a stronger one and a quotation held to the specification cannot drift from it, instead of a paraphrase that can.

Decision: The cases a row names are a readable sample chosen by the page's author, each verified by the check to cite the row's rule, and not every case that cites it, because the manifest already lists all of them by rule and hundreds of identifiers per rule cannot be read, instead of generating the table from the manifest.

Decision: The trusted base is listed with the size of each part this repository owns and of the pinned LLVM release, counted by a method the page states and a command prints, and the figures are a snapshot that the check does not hold to the checkout, while the check requires only that the counting method still resolves to files, because the compiler's size changes with ordinary work and a figure held to it would turn unrelated changes red until someone updated a number that carries no claim, instead of a tolerance band or a list without sizes. This is a provisional choice that reopens if a stale figure misleads a reader.

Rejected:
- A `claims` field on each manifest case: rejected because it puts claim assignment into the conformance evidence and its schema, which only the specification's verdicts may change, and spreads one claim over thousands of manifest lines instead of one page.
- Generating the page from the manifest: rejected because it would list every case that cites a rule, which a reader cannot check, and which cases best illustrate a rule is a judgment the check should not make.
- A page with no check: rejected because it is the record nothing reads that the rule-to-ground ledger refusal describes, and a safety page that has drifted states a claim the specification no longer makes.
- Holding the trusted-base figures to the checkout within a tolerance: rejected because the figures carry no claim of their own, so a band would fail changes that did not touch the trusted base.
