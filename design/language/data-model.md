Decision: Struct-of-arrays is the taught default layout for bulk data while array-of-structs stays a genuine need, served by a storage shape whose element type is the struct itself, held by value under ordinary ownership, because struct-of-arrays is usually the faster layout and owned elements already serve the record-by-record case without a copy-struct mechanism the language does not have, instead of forbidding array-of-structs or keeping a separate flat heap-buffer type to hold records.

Decision: Moving owners between slots is an ownership relocation: every retained owner reaches exactly one destination and a moved-from slot is never read or dropped, because copying or losing an owner would violate single ownership, instead of treating compaction or removal shifts as metadata-only updates.

Decision: Full arrays, prefix windows, ring windows and runs of segments are four distinct storage shapes, and placement is a separate axis with no mandatory handle or indirection on dense values: each of the first three has a constant-capacity form that lives inline in its owner and a runtime-capacity form that lives only as Box content, and a run of segments, whose size is fixed only when it is built, lives only as Box content, because variable length, a head position and segment boundaries are not universal array metadata and only a size fixed at run time needs the heap, instead of one universal dynamic-array representation.

Decision: What a source function signature promises is its parameters' ownership classes together with its declared effect row, fixed independently of how parameters and results are represented, because a representation choice must not widen or narrow what a signature promises, instead of deriving access permission from representation or from a permission marker written on a reference.

Decision: A type's identity carries no region, store, or brand component, and no type anywhere names the store its storage came from, because there is one heap and a reference is a local name for a path that never escapes the function holding it, so no value carries a lifetime that a type would have to name, instead of region parameters as an axis of nominal identity reconciled by a region-erased structural equality before lowering.

Decision: Bool is a two-variant prelude enum using the same tag-only mechanism as user enums; primitives are unit and fixed-width integers and floats of 8, 16, 32 and 64 bits, because one mechanism then serves selection, equality and tag-width lowering, instead of a dedicated primitive boolean or address-width and 128-bit integers.

Decision: A single heap-owned value has its own cell type, the box, declared in the prelude as an opaque struct (`language/data-model/opaque-struct`), which is the only heap marker in the language, carries no measure and no store or region brand, and is the only place a runtime-capacity storage shape or a run of segments may live, because an ordinary scalar Box needs neither a window descriptor nor a nonempty-length proof at every read, while a shape with no compile-time size needs heap element storage for a positive physical extent; the runtime Slots Box keeps its descriptor inline under `compiler/storage-representation` without changing the logical content path, instead of representing a boxed value as a window of capacity one or branding the cell with the store it came from.

Decision: The heap cell's content is an ordinary field of the cell named `inner`, read as `b.inner`, written as `set b.inner = v;`, measured as `b.inner.len`, and reached through a reference to the cell as `cell^.inner`, while the only unbox is the ordinary move of that field, `let n = move b.inner;`, which consumes the cell and frees its owned allocation, because a cell is a value its owner holds and not a name for storage someone else owns, so reaching its content must not share the spelling that reads through a reference, and the name `inner` keeps the step distinct from the payload field `value` that the prelude's `Option` and `Result` variants carry, so a path through both spells `n.left.Some.value.inner.key` with one word per step, instead of a dereference form for the cell, under which `set deref(b) = v;` read as either the rebinding of a name or a write of the content.

Decision: Allocation never fails as a source-visible outcome and carries no result wrapper, exhaustion of the heap being a failure of the trusted base that terminates the program outside the language, and a program may declare that it uses no heap, in which case the heap cell, the runtime-capacity storage shapes, the run of segments and every capability built on them are unavailable to it, because a result wrapper on every allocation would put an error arm and its handling on every push and every node, virtual memory makes exhaustion a whole-program failure rather than a per-site outcome, and the domains that cannot tolerate exhaustion are the ones that forgo the heap entirely, instead of a fallible allocation returning its payload inside an error value, or an allocation that traps into a handler.

Decision: Full arrays admit owned elements and consuming conversions to and from prefix windows, while every mutating helper takes the storage as a reference parameter, declares in its effect row what it writes, and returns only outcomes or removed elements, because completed fixed storage needs no window metadata and an owned mutation boundary copies the entire inline capacity, instead of forcing a completed array through a partial-window state or returning a mutated storage value.

Decision: Ordinary enum slots remain the owning sparse-map baseline, because the matched growth and refusal witnesses do not isolate enough benefit to select compiler-known projected storage, instead of introducing projected sparse authority from an unseparated interface and layout cost.

Decision: Data-dependent occupancy is stored by the program in ordinary tags or options, because no window slot carries a compiler-maintained tag or can be observed empty, instead of per-slot occupancy metadata or vacancy type states.

Decision: Fieldless opaque structs retain a uniform layout ceiling independent of their linked representation, because native catalog sizes must not choose source behavior or the ceilings target qualification holds a layout to, while heap exhaustion remains outside source proof obligations, instead of link-selected layout ceilings or unavailable opaque layout queries.

Rejected:
- Store brands, providers, and region parameters carried inside types: rejected because one heap serves every allocation and a reference never outlives the function that formed it, so a store name in a type protects nothing.
- Compiler-maintained per-slot occupancy tags or a vacancy type state: rejected because a program that needs occupancy stores it as data it can read directly, and every other program would pay for the tag.
- Reference or slice values held in aggregates: rejected because a value that contains an interior pointer can no longer be relocated by copying its bytes.
- Reaching the cell's content with the reference dereference form, `deref(b)`: rejected because it gave one spelling to two different things, a value the program owns and a name for storage it does not, and it left `set deref(b) = v;` ambiguous between rebinding a name and writing the content.
- The content field names `value`, `item`, and `data`: rejected because each says nothing about the cell and `value` is already the payload field of the prelude's `Option` and `Result` variants, so one word would name two different steps of the same path.
- A destructuring unbox, `let Box(inner: n) = move b;`: rejected because the cell is an opaque struct and an opaque struct refuses destructuring so that a linear host handle cannot be taken apart instead of closed (`language/data-model/opaque-struct`), which leaves the ordinary move of the field as the one unbox.
