Decision: An ordinary requires held clause names reference parameters whose referents share one caller-held atomic statement and remain unchanged at its effect point, because a source read-pair or table-audit helper needs the same declarable observation relation as a linked exporter, instead of identifying privileged operations or requiring a direct lexical call ([comparison and witness](../../../research/investigations/consistent-snapshots/capture-export.md#existing-rules-and-the-missing-relation)).

Decision: The initial held clause belongs to a nonwaiting callable whose ordinary effect row contains no writes, because that boundary excludes a write through an unlisted borrowed parameter that could alias the caller-held state without adding negative origin facts, instead of admitting borrowed outputs through a new disjoint-from-all-held-states contract; writes to private owned and local storage keep their ordinary rules.

Decision: Only the referent regions named by the held requirement are protected against every write in the caller statement's complete block, because those regions must represent unchanged observations at its one effect point while unrelated state need not be frozen, instead of refusing every write to the rest of that statement's state.

Decision: Reference aliases and projections retain finite held-origin facts, a contracted body receives one symbolic caller origin, and forwarding checks those facts against the declared requirement, because ordinary references already establish lifetime and no escape while this additional structural fact supplies the shared observation point, instead of scalar-history tracking, recursive callee-body inspection or runtime hold tokens.

Decision: A function actual's required held-parameter set may be a subset of its formal's set, because a callable needing fewer protected inputs can satisfy the stronger caller boundary with the formal contract remaining authoritative, instead of refusing function-kind bindings or deciding refinement through an implication search.

Rejected:
- Operation-specific direct capture admission: rejected because it cannot be forwarded through the same ordinary callable contract and is inadmissible under the constitution's external-interaction principle without amending that principle.
- Ordinary read-only reference effects alone for the stronger held-observation promise: rejected because they admit an unheld private reference and do not protect the referents against writes elsewhere in the surrounding statement; ordinary borrowing remains safe for that weaker interface.
- Requiring the entire caller statement to be read-only: rejected because changing an unrelated held field does not change the protected observation.
