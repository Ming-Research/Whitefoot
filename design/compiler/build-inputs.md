Decision: The specification identity and parser grammar tables are derived from the active specification during Cargo construction and kept as build outputs, with the active path identifying the current specification and no version read from it, because separately maintained versions, status declarations and generated-table copies introduce synchronization work without another source of truth in the [test-system investigation](../../research/investigations/test-economy/redesign.md), instead of a duplicate Status field, manually committed parser tables and regeneration-comparison gates. Parser and diagnostic correctness still require behavioral tests; generation alone proves neither.

Decision: Compiler-independent specification-document integrity is checked directly from Markdown by the existing Python conformance tooling, because duplicate definitions and unresolved rule references need no compiler execution or native artifact, instead of building and running a Rust specification-checker binary and repeating same-source identity comparisons. Build-derived identity used by the compiler remains; auxiliary queries are retained only for an identified consumer.

Decision: The specification carries no version and an amendment adds no archive: the first line of `spec/kernel-spec.md` is `# Kernel Specification`, an amendment adds one entry at the top of `spec/log.md` and nothing numbered, and an entry's version is derived from its place in the log (the version its title names, as every entry through v0.160 does and the entry that starts a major version does, or else the next minor version after the entry below it), checked by `check-spec-archives.sh` and printed by `spec-version.sh`, because a version taken on a branch is a counter that every concurrent amendment writes at the same places (the title line, the archive of the outgoing version, the log heading) while its order is fixed only when an amendment merges, so each amendment that merged first made every other open one merge main, renumber, re-archive and run its checks again (112 of 307 merges of main in two weeks of 62 amendments were such collisions, [measured](../../research/investigations/spec-version-churn/README.md#measurement)), and the compiler's identity of the specification is the SHA-256 of its bytes, nothing read the version, and git holds every state of the specification, instead of a number assigned on the branch.

Rejected:
- Removing the grammar generator while retaining only a frozen table: rejected because grammar amendments still need a reproducible path from the normative productions to the parser's data.
- Treating fewer Rust test executables as proof of nonredundant coverage: rejected because packaging does not establish that assertions protect distinct properties.
- Keeping the number on the branch and renumbering by script: rejected because each collision would still need a merge of main and a new run of the checks, only the manual repairs would go, and the collisions grow with the number of open amendments.
- Assigning the number by a commit to main after each merge: rejected because it changes the specification's bytes after the gate passed on them, needs a workflow that pushes to main, and edits the log heading where the next branch inserts its entry.
- Writing a date or time into the title line, or naming archives by one: rejected because every branch edits the title line, so two branches collide as they do on a number, and an archive of the outgoing version needs the previous version, known only when the amendment merges.
- Naming an amendment by the date and title of its log entry with no derived number: rejected because the name is long, 14 of the first 63 entries share one date so the title must stay in the name, and the date is when the entry was written, so the name carries no order (4 of those 63 headings disagree with the log's order) and does not continue the 160 existing version names.
- Letting one amendment be in flight at a time: rejected because at the median 12 hours an amendment stays open that serializes to two a day against the 4.4 that merged, and a long amendment holds the rest back.
