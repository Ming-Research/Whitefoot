Decision: In each strongly connected component of the call graph among definitions that have a checked source signature and neither wait, are synthesized, hand calls out, carry a recursion budget nor contain a dispatch loop, a read-only `&T` or `&[T]` parameter that every member has and that every call inside the component passes on unchanged, as the caller's own parameter directly or through block parameters that receive only it, travels in one record: each member's body is an internal `wf__env_<name>` form that takes one `noalias readonly` pointer to that record in place of those parameters and loads each slot once before its first use in each block that uses it; a block parameter whose every incoming value is the same slot, directly or through other such block parameters, names that slot without a phi, so forwarding it between blocks causes no load, while a slot operand of a remaining phi is loaded at the end of its corresponding predecessor block; calls inside the component pass the caller's own pointer, and the member's public symbol keeps its ordinary signature and facts and becomes the entry from outside, which stores those parameters into a record in its own frame and calls the internal form, because every definition C or another fragment can name keeps the one callable ABI and the specification is unchanged, while a chain such as Snowghost's selector matcher, whose step passes 9 argument words and test 8 against x86-64's 6 integer argument registers, spends its per-call overhead on stack-passed arguments, argument preparation and spills around inner calls ([witness](../../research/investigations/recursive-shared-env/README.md)), instead of a source-level reference record or a different calling convention; loads stay in the blocks that use the slots because a member whose slots each serve several arms of a dispatch otherwise pays every load on every call, since the host does not sink a load used in several blocks: Snowghost's renderer `instr_matches` executed four entry loads on every call although its hot Class arm used only one slot ([Snowghost's renderer measurement](../../research/investigations/recursive-shared-env/README.md#renderer-attribution-and-load-placement-prediction)); each internal form declares, after the record pointer, the parameters that calls inside the component forward unchanged from the caller's own parameter, with classes present in every member first and the remaining classes next, each group ordered by its first member in program order and then that member's parameter index, omitting classes absent from the member without padding, then its remaining parameters in source order, because aligned positions of classes present in every member let those forwarded values stay in their argument registers across the component, while partial classes need not align, where the witness's test otherwise copied id and context into step's positions on every call for the sake of its rarely taken call of step, and no other definition sees the internal form.

Decision: A component uses the record only when its slots replace at least two argument words and some member passes more integer-class argument words than the selected target's argument registers hold (six on x86-64 System V, four on x86-64 Windows, eight on AArch64), because below that budget every argument already travels in a register and the record could only add loads, provisionally until the [measurement](../../research/investigations/recursive-shared-env/README.md#comparison) decides, instead of packing every qualifying group or every borrowed parameter.

Decision: Within a component that uses the record, the calls that close its cycles carry the call-site attribute `noinline`, namely the back edges of a depth-first walk of the component's calls in call-site order that starts at its first member in program order called from outside the component, or at its first member when none is, while every forward call stays inlinable, because the host's inline cost does not count that inlining one copy of a cycle into a member's rarely taken arm makes the member non-leaf and puts a callee-saved frame on every path through it: on Snowghost's witness the host inlined step, with compound inside, into the negation arm of test, which then pushed and popped six callee-saved registers, adjusted the stack and kept the record pointer in a callee-saved register on every call, 16.56 instructions per call, more than the whole 14.17 regression per top-level call of the table-free chain against the base compiler, while the record itself saved 1.22 ([attribution](../../research/investigations/recursive-shared-env/README.md#first-measurement)); a cycle can never be inlined away and an out-of-line call changes no meaning, and starting where the chain is entered keeps inlinable the edges each entry runs forward through, compound into test, and cuts the call that returns to an activation already on the walk, instead of leaving every in-group call to the host's inliner, marking every in-group call, or starting the walk at the first member in program order whatever calls it, which on the witness, where test is defined before step, would cut compound into test, the hot forward edge.

Decision: An internal entry is named `wf__<form>_<name>` by its form, which says which parameters a record carries and which calling convention it uses, and a call site chooses it in one place by the relation between caller and callee, naming the public symbol otherwise, because the record form and the split-part calling-convention entry are the same mechanism, a definition the compiler alone calls in a form no other definition sees, instead of a separate naming and selection path per form.

Rejected:
- Loading every slot once at entry: rejected because the host does not sink a load used in several dispatch blocks, so Snowghost's renderer `instr_matches` paid four entry loads on every call although the hot Class arm used only one slot ([Snowghost's renderer measurement](../../research/investigations/recursive-shared-env/README.md#renderer-attribution-and-load-placement-prediction)).
- A calling convention alone, `x86_regcallcc` or `preserve_nonecc`: rejected because regcall exists only on x86 and would need adapters for every linked C body sharing the callable ABI, while preserve_none clobbers the callee-saved registers the matcher keeps its state in and requires LLVM 19.
- A source-level record of references the writer passes: rejected because the owner chose the compiler route, which changes no accepted program; the language form stays a backlog candidate.
- Putting every borrowed parameter in the record whatever its words: rejected because a group whose arguments already fit the registers pays a load per slot for nothing.
- Admitting parameters written through: rejected because a pointer loaded from the record cannot carry the `noalias` that separates those writes from every other access, while a written parameter that stays an argument keeps it.
- A parameter some recursive edge passes as a different borrow, such as a narrowed range: rejected because one record slot holds one value for the whole activation chain.
- Marking every call inside the component `noinline`: rejected because the forward edges, compound into test on the witness, are where inlining pays and they close no cycle.
- Every outside caller building the record at its own call site: rejected because the public symbol must build it anyway for C and other fragments, and the host inlines that small entry into the callers it sees, which gives them the same code without a second call-site path.
