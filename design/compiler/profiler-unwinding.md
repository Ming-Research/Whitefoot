Decision: Every function the compiler emits carries LLVM's `uwtable` attribute, so that each one, including a leaf that LLVM would otherwise leave without a frame-description entry because it cannot unwind by exception, has unwind rules that a sampling profiler's DWARF unwinder can follow to its caller, because without them a hot leaf's samples lose their callers ([unwind experiment](../../research/experiments/unwind-resume/README.md#retained-source-run-observations)) at a measured cost of 208 bytes of `.eh_frame` in the witness, instead of emitting unwind tables only for functions that can unwind or leaving profiling to frame pointers, which the compiler does not keep.

Decision: The Linux LTO link passes `-z separate-code` to LLD, so that the executable code segment's virtual address equals its file offset, because perf 6.17's DWARF unwinder looked up unwind rules at an address 0x1000 off under LLD's default layout and recovered no caller in an LLD-linked C program, against every caller with `-z separate-code` or the default linker ([linker-layout result](../../research/experiments/unwind-resume/README.md#linker-layout-result)), at a cost of 992 bytes, 1.2 percent, in the witness executable, instead of LLD's default layout or a different linker, which would replace the one LLD the toolchain pins.

Rejected:
- Keeping frame pointers for profiling: rejected because it gives up a register in every function for a diagnostic need that unwind tables meet without changing emitted code.
- Documenting the profiler limitation for downstream projects without changing the link: rejected because a standard profiler then reports wrong callers for every LLD-linked Whitefoot program, and the fix costs under one page per executable.
