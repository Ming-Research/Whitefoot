Decision: Every function the compiler emits carries LLVM's `uwtable` attribute, so that each one, including a leaf that LLVM would otherwise leave without a frame-description entry because it cannot unwind by exception, has unwind rules that a sampling profiler's DWARF unwinder can follow to its caller, because without them a hot leaf's samples lose their callers ([unwind experiment](../../research/experiments/unwind-resume/README.md#retained-source-run-observations)) at a measured cost of 208 bytes of `.eh_frame` in the witness, instead of emitting unwind tables only for functions that can unwind or leaving profiling to frame pointers, which the compiler does not keep.

Decision: The Linux LTO link passes `-z separate-code` to LLD, so that the executable code segment's virtual address equals its file offset, because measured under LLD's default layout, perf 6.17 recovered no caller in an LLD-linked C program, while `-z separate-code` and the default linker recovered every caller ([linker-layout result](../../research/experiments/unwind-resume/README.md#linker-layout-result)); the inferred mechanism, that its DWARF unwinder looks up unwind rules at an address 0x1000 off, is not yet reproduced, at a cost of 992 bytes, 1.2 percent, in the witness executable, instead of LLD's default layout or a different linker, which would replace the one LLD the toolchain pins.

Rejected:
- Keeping frame pointers for profiling: rejected because it gives up a register in every function for a diagnostic need that unwind tables meet without changing emitted code.
- Documenting the profiler limitation for downstream projects without changing the link: rejected because perf 6.17 then recovers no caller above the resume frame of an LLD-linked program, as in the witness and the LLD-linked C control, while the fix cost 992 bytes in the witness executable.
