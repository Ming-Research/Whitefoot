Decision: A completion record belongs to the ordinary linked call's native activation and is found by address, with no global slot token or source capacity wait, because the call already owns the live request and borrowed backing until return, instead of a fixed global slot pool with generation-checked tokens and a refusal the submitter loops on.

Decision: A ring that is absent or refused at startup falls back silently to the blocking-helper adapter, while a target failure after an operation has been accepted ends the process as a fail-stop with no fallback and no writer-visible `IoError`, because before acceptance both engines answer the same request identically, whereas after acceptance ownership of the target operation has transferred, so falling back would duplicate it and ignoring the error would strand it, instead of degrading a post-acceptance failure to the adapter or to an `IoError`.

Decision: The native completion record remains 160 bytes, keeping larger operation-specific requests on the helper adapter, because enlarging a common record for one operation taxes every pending request, instead of a larger shared record or an additional accept-owned buffer.

Decision: When a native ring is ready and no helper count is written, the helper pool starts and stays at zero, with adapter requests serviced by a waiting caller, until a context other than the root starts or an operation with a deadline or a real cancellation watch reaches the adapter (compiler/waiting-contexts/bounded-waits), after which compiler/waiting-contexts hands every such request to helpers, because the [warm Linux many-file comparison](https://github.com/mbbill/Whitefoot/blob/b3341e32ab8d69e2974227aee7146ac16eb2fe00/research/investigations/io-model/RESULTS.md#workload-1-many-independent-files) found that helper handoff cost more than the adapter work it moved, instead of starting or growing a helper pool on that path; this is a default selected from that workload, not a claim that every native engine handles every transfer or that adapter operations never wait, and an explicit helper count still pins the pool.

Decision: Without a ready native ring and with no explicit helper count, helpers start at zero and grow to a provisional ceiling of eight when queued demand exceeds the pool and one-in-sixteen sampled operation waits reach about 20 microseconds, or for a peer-bound request without those tests, as every request is once a context other than the root starts (compiler/waiting-contexts), because the [macOS comparisons](https://github.com/mbbill/Whitefoot/blob/b3341e32ab8d69e2974227aee7146ac16eb2fe00/research/investigations/io-model/RESULTS.md#macos-runner-read-heavy) support avoiding needless handoff while allowing I/O width beyond CPU count, instead of one initial helper or a CPU-sized ceiling. Eight bounds the pool's growth on demand, not outstanding operations or optimal width; an explicit count pins the pool.

Decision: Read an opened descriptor's kind with one fstat on the reaping thread, because the [historical open-kind comparison](https://github.com/mbbill/Whitefoot/blob/b3341e32ab8d69e2974227aee7146ac16eb2fe00/research/investigations/io-model/RESULTS.md#open-kind-lookup-comparison) favored avoiding a second ring round trip on its many-file workload, instead of linking IORING_OP_STATX after the open.

Decision: Ordinary linked implementations call their required native engine through strong link references, because an absent engine cannot complete a submitted request, instead of a weak inline fallback for an unresolved native implementation.

Decision: Set TCP_NODELAY on every created or accepted TCP socket, because the [transport comparison](https://github.com/mbbill/Whitefoot/blob/b3341e32ab8d69e2974227aee7146ac16eb2fe00/research/investigations/io-model/SCHEDULER-FINDINGS.md#tcp-packet-policy-comparison) isolates the default packet policy's request/response throughput and tail-latency cost, instead of inheriting that policy.

Decision: Set SO_REUSEADDR on every listening socket on a POSIX host, before its bind, and no address option on Windows, because a POSIX bind refuses a port while connections a stopped server accepted wait out TIME_WAIT, a minute on Linux, so a restarted server could not listen ([rebinding a port](../../research/investigations/io-model/NETWORK.md#rebinding-a-port)), while on Linux and the BSDs the option still refuses a second listen on an address and port another socket listens on, and because Windows' plain bind already admits a port held only by connections, as observed there, and its SO_REUSEADDR would let one socket bind a port another holds, instead of no option on any host.

Decision: Create each io_uring ring without `IORING_SETUP_COOP_TASKRUN`, because that flag defers completion work until the submitting thread next enters the kernel, and a driver's role can pass to a spare thread while the submitting thread computes for seconds (compiler/waiting-contexts/bounded-waits), so its completions would wait on a thread that no longer reaps them ([analysis](../../research/investigations/driver-handoff/DESIGN.md#linux-task-work-choice)), instead of keeping the flag, whose task-run mode the [attribution experiment](https://github.com/mbbill/Whitefoot/blob/b3341e32ab8d69e2974227aee7146ac16eb2fe00/research/investigations/io-model/WAITS.md#experiment-4-attributing-the-gap-at-64-connections) found to cost part of the frame server's gap to the reference; with the driver-handoff steps firn kept its throughput within 3 percent and showed no p99 increase the comparison could resolve ([cost comparison](../../research/investigations/driver-handoff/DESIGN.md#result-ordinary-io-cost-of-steps-1-and-2-first-sample)).

Decision: Retain a reap budget of 64 completions, a 10-microsecond join spin, 64 io_uring submission entries and 2,048 completion entries, with each constant's ground beside its definition, because the [tuning record](https://github.com/mbbill/Whitefoot/blob/f94766e7ee252ffb4127cb6fde382360b2123834/research/investigations/io-model/RESULTS.md#grounds-for-the-retained-tuning-constants) distinguishes measured batching gains, bounded wait cost and queue-capacity needs, instead of defaults with no recorded grounds.

Decision: Windows completion wakeups track native waiters in an intrusive list under the wait lock, send one packet per unnotified waiter, re-post polled packets only while a notified cohort remains, and hold newcomers on the runtime condition until that cohort leaves the kernel, because the [notification replay](https://github.com/mbbill/Whitefoot/blob/b3341e32ab8d69e2974227aee7146ac16eb2fe00/research/investigations/io-model/SCHEDULER-FINDINGS.md#windows-notification-replay) shows how newcomers can consume older sleepers' packets, instead of unaddressed packets consumed by any arriving waiter.

Decision: Every io_uring submission, completion and entry mapping is advised `MADV_DONTFORK` when its ring is created, and a refused advice refuses the ring so the startup fallback above serves the program, because a forked child holding the parent's live mappings could read or advance a queue the parent's kernel ring still owns, instead of leaving rings inheritable and relying on child code never to touch them.

Decision: The native capsule witness on Linux x86-64 with glibc runs a snapshot child forked inside a hold only in a restricted capsule: the parent prepares an output allowlist, a private scratch arena and a result pipe outside the hold; the child resets signals by raw system calls, closes every descriptor outside the allowlist, runs one fixed native encoder over the captured state and the arena, and leaves by `exit_group`; the process registers no `pthread_atfork` handler, since glibc's fork would run it in the child before any reset and in the parent inside the hold; the parent reaps the child through a pidfd, or by `waitpid` when the pidfd cannot be opened or waited on after the child exists, since the job must still own its reaping, because the child copies a multithreaded process whose locks, allocator and compute lanes may be held by threads absent from it, instead of running ordinary runtime or Whitefoot code, stdio, atexit handlers or the allocator in the child.

Decision: A source snapshot export uses the restricted capsule with one fresh data pipe and its private bounded status channel, a generated type description and a runtime-owned encoder that never invokes user hash, comparison, release or other callbacks, because the existing native capsule establishes a child execution frontier but supplies neither typed traversal nor source ownership of output, instead of exposing its native encoder pointer or raw descriptors to Whitefoot ([phase-2 boundary](../../research/investigations/consistent-snapshots/capture-export.md)).

Decision: Preparation reserves descriptors, job control and all child traversal and encoding workspace before the hold, the held call makes one synchronous creation attempt, and parent activation follows outside the hold before source execution resumes, because allocation, descriptor setup and completion-driver access would enlarge the held frontier and inherited native state is not a child service, instead of building the output or starting a normal runtime task while holding the dataset.

Decision: The source export job uses its exclusively owned child identity with waitpid and preprepared data and status pipes, opening no pidfd after capture, because identity cannot be reused before its sole owner reaps it and data-pipe collection already supplies the necessary output progress, instead of adding a monitor descriptor whose creation follows the hold; the native capsule witness retains its separately scoped pidfd path.

Decision: Parent completion drains or discards the data pipe while the child can still write and confirms the owned waitpid reap before consuming the job, because waiting for exit before draining a full pipe deadlocks and a host wait failure does not remove the reaping obligation, instead of wrapping the capsule's finish call without an output collector or returning a failure that loses a live child.

Decision: The first source exporter targets Linux x86-64 with glibc and other compositions report an explicit target capability failure, because the capsule's signal, syscall and copied-runtime audit qualifies only that platform and does not prove the corresponding contract elsewhere, instead of rejecting otherwise valid source or silently using another snapshot algorithm.

Decision: A composition using the restricted exporter prepares signal exclusion at ordinary atomic entry and retries, restores the executor's mask before suspended acquisition, and activates all queued prepared jobs after releasing every target, because a forwarding wrapper may discover its reserve only inside the held block and a resumed acquisition may run on another executor, instead of discovering direct capture calls or performing signal and descriptor setup inside the hold.

Decision: Consuming snapshot completion is a closed helper-adapter request carrying the owned job and an abort flag, because draining a full pipe and confirming a reap can wait while service contexts must continue, instead of blocking the source executor or installing a user callback or a generic runtime thunk in the completion record.

Rejected:
- Running ordinary runtime or Whitefoot code in a snapshot child: rejected because the child inherits locks and allocator state held by threads that no longer exist in it, so any lock or allocation there can hang or corrupt.
- A fixed global slot pool with generation-checked tokens and a capacity wait: rejected because the native call activation already owns the request until return and the pool only added refusals nothing could act on.
- No address option on any host, so that a program's second bind of one port answers AddressInUse: rejected because it also refused a restarted server its port for TIME_WAIT's duration, while SO_REUSEADDR on POSIX keeps that answer for a second listen.
- SO_REUSEADDR on Windows too: rejected because Winsock's option lets a socket bind a port another socket holds, and Windows needs no option for the restart.
- SO_REUSEADDR only when the program or its environment asks for it: rejected because every server restarted on its port needs it, an environment setting would make a bind's answer depend on a setting no source names, which the earlier choice refused, and a parameter of tcp_listen would change the ordinary library's interface for a refusal no program relies on, a port held by connections a stopped server left.
