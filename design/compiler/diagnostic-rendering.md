Decision: A compiler stop is one record of labeled fields rendered without `Debug` text for any source rejection or capability stop; by default it prints as lean text -- a `file:line:column: error[RULE]: Kind` summary line, the source line marked under the span, then one `label: value` line per payload field -- and `--diagnostic-format json` prints the complete record, envelope and byte interval included, as one object per line, because the main reader is an agent in a compile-fix loop that reads text directly, recognizes that summary shape, and compares the quoted source unescaped at lower reading cost, while exact tooling needs the complete fields, instead of the stage payload's `Debug` text, JSON by default, or hand-written prose per kind. The text default is provisional until a writer trial compares compile rounds to a fix, and the [readable-diagnostics investigation](../../research/investigations/readable-diagnostics/DESIGN.md#default-format-text-with-json-on-request) holds the field inventory and measurements.

Decision: Each payload type lists its fields once, and each closed classification it names lists its variants, in the driver's diagnostic module by exhaustive destructuring that takes each label from the field name and each kind from the variant name, and a node a payload names travels with its coordinate from the checker that holds the tree, because a field or variant added to a payload then fails to compile until it is listed, a label cannot drift from its field, and no child-ordinal path, source ordinal or byte offset reaches the default text, instead of rendering from parsed `Debug` text, a serialization dependency, or keeping the resolved tree alive in the driver after a rejection.

Rejected:
- JSON as the default rendering: rejected because it escapes the source lines and prose the agent compares with its program, drops the marker, and costs more to read per record, while the lean text's labeled lines already parse by label.
- Repeating the envelope as labeled text lines under the summary line: rejected because the rule, kind and position are already in the summary line, and the category, stage and byte interval of a source rejection give a writer nothing to act on; JSON keeps them for tools.
- Parsing each payload's derived `Debug` output into a generic tree: rejected because `Debug` is not a stable format, three hand-written implementations already diverge from the derived shape, and a parsed node path still cannot be resolved without the tree.
- A serialization derive from an external crate: rejected because the compiler is one dependency-free crate built offline, and a proc-macro dependency set is a larger change than the field listing it replaces.
- Hand-written prose per rejection kind: rejected because about a hundred maintained sentences would restate fields and mechanical fixes the payload already carries exactly.
- Returning the resolved unit with every semantic failure so the driver can resolve node paths: rejected because it changes every failure variant and its test patterns, while the checker already holds the tree at the few sites that build a payload naming another node.
