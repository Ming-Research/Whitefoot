Decision: Every definition the compiler emits for a Whitefoot program carries LLVM's `inlinehint` attribute, while the compiler-owned C runtime keeps LLVM's defaults and LLVM still prices every call, because Whitefoot has no inline annotation and a writer cannot see where LLVM's size threshold falls, the hint is the level LLVM calibrates for C++ `inline` and Rust `#[inline]` functions rather than a number chosen to recover one program, and an attribute on the definition reaches the default, cached ThinLTO, fragment and full-LTO builds alike; the [inline-policy investigation](../../research/investigations/inline-policy/DESIGN.md#design) measured the standard library's hash-map removal, which a six-instruction shrink test had pushed past the threshold, recovered past its speed before that test, Halo's `fib` 10% faster, no cell slower, and text 0.75% larger for the hash-map bench and 5.3% for Halo, instead of leaving every Whitefoot definition at LLVM's ordinary threshold. A statically cold call site keeps its threshold of 45.

Rejected:
- A global `-inline-threshold` of 325: rejected because it also raises the C runtime's calls, growing the corpus's text by 7.3% where the hint grows it by 0.03%, and must reach every compile and LTO link as an LLVM command-line option.
- A threshold chosen from the witness, such as 400, 1,000 or 2,000: rejected because 400 recovered less of the witness than 325 and slowed draining a map, so the threshold's position is a cliff the next library change moves, and 1,000 and above more than doubled Halo's text.
- Compiler-selected call sites marked always-inline, such as a small callee called in a loop: rejected because it needs a size bound with no structural ground, as the withdrawn always-inline policy of compiler/storage-placement did, while LLVM already reads each site's loop frequency.
- A branch weight on the rarely taken shrink branch, or an inline hint or always-inline on the slowed function alone: rejected because LLVM still counts a cold branch's instructions in the cost, and the hint on one function moved the boundary one caller outward, so the removal's loop still paid a call.
