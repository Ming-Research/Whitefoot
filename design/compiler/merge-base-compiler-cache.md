Decision: The merge-base compiler that the paired performance comparison builds as its baseline is cached per main commit, under a key made of that commit and the toolchain (`rustc -vV`, the clang and C compiler versions, and the runner image), matched exactly, so a pull request on the same main commit and toolchain restores the binary instead of building it again, because a cold build takes about 110 s on hosted runners and every pull request on that main commit builds the same bytes, while a pull request run can restore only caches saved on its own ref or on main, so each push to main saves its commit's compiler once, instead of building it in every pull request run or sharing one cache across commits. Owner ruling on the baseline-compiler card, 2026-10-13, option A.

Decision: The cache stores the compiler binary, its checksum and the commit it was built from, and a restore is used only when the stored commit equals the merge base and the checksum verifies, because a restored Cargo target directory belongs to another commit and a prefix match would hand the comparison a different compiler, instead of restoring the build directory or matching keys by prefix.

Rejected:
- prefix restore keys over the Cargo target directory: rejected because a prefix match restores a different commit's build state under the merge-base build, so the baseline would not be the merge base's compiler.
- raising the baseline budget to 135 s instead of caching: rejected because it leaves every pull request paying the cold build and still fails when a runner image is slower; the owner ruled the baseline report-only rather than raised.
