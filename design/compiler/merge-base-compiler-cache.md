Decision: The merge-base compiler that the paired performance comparison builds as its baseline is cached per main commit, under a key made of that commit and the toolchain (`rustc -vV`, the clang and C compiler versions, and the runner image), matched exactly, so a pull request on the same main commit and toolchain restores the binary instead of building it again, because a cold build takes about 110 s on hosted runners and every pull request on that main commit builds the same bytes, while a pull request run can restore only caches saved on its own ref or on main, so each push to main saves its commit's compiler once, instead of building it in every pull request run or sharing one cache across commits.

Rejected:
- prefix restore keys over the Cargo target directory: rejected because a prefix match would return another commit's build state, and the key would then not name the bytes restored (inferred from the key scheme; not observed in a run).
- raising the baseline budget to 135 s instead of reporting it only: rejected because a fixed number must be raised again whenever a cold build drifts past it, while the owner ruled the baseline is the main line's own code that no pull request changes, so its overrun is reported and never fails a pull request (owner ruling on the baseline-budget card).
