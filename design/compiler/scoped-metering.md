Decision: The native scope table has 64 slots including a permanent default account, and owners and views carry a slot and a 64-bit generation inside the existing opaque host-value ABI, with a generation-exhausted slot unavailable rather than wrapped, because the owner selected finite capacity for the runtime-core pass and stale views must never observe a later occupant, instead of allocating scope metadata or changing the shared host-handle representation ([implementation boundary](../../research/investigations/scoped-metering/README.md#runtime-core-implementation-boundary)).

Decision: One lock governs scope generations, fixed ancestry, owner presence, activity, descendants and retirement, while per-thread single-writer scope counters occupy packed cache-line-aligned rows retained across thread exit and slot reuse; the existing process counter remains independent, and default-account pool charges use the pool's existing lock, because structured joins protect current-scope writers until leave and non-retaining observations need synchronized ancestry, while transient host signal threads cannot consume permanent writer rows, instead of padding every scope counter to a cache line, clearing another thread's counter at reuse or registering host callbacks as bounded runtime workers ([implementation boundary](../../research/investigations/scoped-metering/README.md#runtime-core-implementation-boundary)).

Decision: A context saves its logical scope at entry and leave before any suspension can publish it, drivers install that saved scope on resumption, and every compute callback installs its published frame's scope and restores the helping thread's previous one before completion, because a parked-away context may already have been resumed and freed when the previous driver returns and a helping thread may execute work from another context, instead of saving into a context after resumption returns or deriving compute attribution from the driver's current-context pointer ([implementation boundary](../../research/investigations/scoped-metering/README.md#runtime-core-implementation-boundary)).

Decision: Each independently allocated structure pins its fixed origin until its final accounting publication and release, with pins serialized by the lifecycle lock and open descendants pinning their ancestors, because a zero-byte allocation may grow after its invocation returns and a last free on another thread must finish publishing before the slot can retire, instead of treating a sampled zero as evidence that no origin remains ([origin implementation](../../research/investigations/scoped-metering/README.md#exact-origin-implementation)).

Decision: Emitted heap allocations use a 16-byte aligned origin prefix behind the existing take, retake and give interface for this pass, with requested payload bytes alone charged and resize retaining the original pin even at zero bytes, because the owner selected the prefix to implement exact origin while keeping replacement by per-scope arenas local to heap.c, instead of embedding the representation in emitted code; acceptance of its cost still awaits the prefix-versus-arena comparison ([origin implementation](../../research/investigations/scoped-metering/README.md#exact-origin-implementation)).

Decision: Concurrent-map cell arrays retain an origin independently of their table descriptors, and small-node chunks are aligned to their chunk extent so a node's address recovers the chunk's origin through reuse, swap, clear and drain, while individually pooled large nodes retain their own origin header, because detached reserve cells can be reused by a newly allocated descriptor from another scope and free lists may contain nodes allocated by other users, instead of relabeling reserves or adding an origin word to every small entry; the extra virtual reservation needed for chunk alignment and its allocation cost remain unmeasured ([origin implementation](../../research/investigations/scoped-metering/README.md#exact-origin-implementation)).

Decision: The thread-local KeySet spare cache retains only structures whose store and byte-arena origins are the permanent default account, because that cache has no program-visible owner or production eviction path and otherwise could prevent an explicit scope from ever closing after its last value was dropped, instead of retaining scoped storage indefinitely; map-owned and context-owned spares retain their origins until their owning structures release them ([origin implementation](../../research/investigations/scoped-metering/README.md#exact-origin-implementation)).
