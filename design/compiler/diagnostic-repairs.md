Decision: The words of every repair a rejection carries are the compiler's and live in one module, written for an agent that applies them as written: each alternative names one source change at the rejected construct, is selected by that construct, its position and, for a goal, its disposition and what the goal reads, and names the instance from the payload (the goal, residual, binding, argument or row), because the specification fixes which rejections carry a repair and what an alternative may direct but not its words [DIAG-1], and because every repair that compiled in one round in the probes of the [repair-wording investigation](../../research/investigations/repair-wording/DESIGN.md#2-disposition-and-literal-application) fitted the case in hand while the rejections without a concrete repair were the ones that cost the blind writer time; the second ground is provisional, from minimal probes and one writer, and reopens with the investigation's writer trial, instead of one sentence per rule for every position, disposition and instance.

Decision: A refuted goal's repair changes what reaches the construct (its operands or arguments, the returned value, or the statements and requirements that fix them) or the operation or clause that poses the goal; an unproved goal's repair offers the routes what it reads admits: a requirement on the enclosing function when it reads only parameters that no event on a path to it writes, which the flow state records per path and unites at each merge; for a goal over computed values or admitted element reads, a proved invariant with `use` steps, and a callee's `ensures` when a value the goal reads is one a call to a function outside the prelude returned, each stating the condition it needs, and a guard whose false edge is intended behavior, which declares in the row any read its condition makes through a reference; for a subscript a requirement forms, a requirement ahead of the one that forms the place and no guard; and for a value only its occurrence identifies, binding it with a `let` first; and for the `len` of a range an argument forms at the call, that length written as the difference of the range's endpoints [REF-4] with the routes over that difference: a guard when the difference is one binding, a width bound with the exact subtraction where the start is at most the end and then guarded when it is a subtraction, a range re-sliced from zero by that width when the goal equates such a subtraction, which has no difference-bound form [ENT-4], and copying into a `let` an endpoint that is not a binding, because establishing a refuted goal leaves the refuting facts in place, so both signs become derivable and the point contradictory [ENT-4], because a requirement over a parameter written before the goal no longer describes it there while a write on another path leaves it intact, because a callee's `ensures` bounds only what that callee returns and the prelude's contracts are not the writer's to change, because a clause is formed in the state the requirements written before it build and evaluates nothing [FN-8], because a condition naming an admitted element read establishes the same goal while no condition can name an occurrence-local value [ENT-3], and because the pinned pairs found the guard over a reference parameter's measure rejected by [EFF-2] until its read was declared, because a range formed at the call has the length its endpoints give it, so telling the writer that no fact names it hides the bound actually missing and steers the writer away from the exact difference that supplies it, while a `-wrap` width carries no relation to the endpoints [ENT-3], instead of asking to establish the fact for both dispositions or offering one set of routes for every goal.

Decision: Every repair is pinned in the pinned-sentence corpus by its rejected source together with a source for each alternative carried out as written, and each repaired source must be accepted with no judgment in its functions succeeding only because the state it is asked in is contradictory, because a sentence compared only with the compiler's own output is a fixed point that cannot see a repair fail when applied, while a repaired source written from the words is an independent oracle that survives rewording, and the contradiction check catches the dead code a guard around a refuted goal compiles to without running the program, instead of pinning the sentence alone or running each repaired program for an exit status.

Decision: An unproved subscript bound whose measure lost facts to writes on paths to it is asked again on a copy of its state with the cells those writes removed put back, and when they discharge it without a contradiction and every write is a call, the repair names each call with its line and the place its row writes and offers, where the callee leaves the length unchanged, narrowing the row entry that covers it or stating the length unchanged in the callee's `ensures`, beside the guard, because writers shown only the ordinary routes guarded such accesses, nine length facts in Snowghost's layout stage were lost this way and 19 of its unneeded guards repeated a fact that had survived ([layout friction](../../research/investigations/layout-friction/DESIGN.md#frequency)), while the copy settles that the named writes are the cause, so each alternative succeeds where the callee indeed leaves the length unchanged [DIAG-1], and no judgment that decides acceptance reads the copy, instead of leaving the calls unnamed, naming every earlier call whose row covers the measure, or walking the function again with those kills suppressed.

Rejected:
- Naming every earlier call whose row covers the measure, found from the source: rejected because the bound may never have held before the call, as when the index is read from storage, and narrowing that row would then change nothing.
- Walking the function again with the calls' kills of the measure suppressed: rejected because putting back the removed cells on a copy of the failing state asks the same question at the one failing site without a second walk.
- Classifying the `len` of a range formed at the call with the values only their occurrence identifies: rejected because REF-4 gives that length the difference of its endpoints, so the repair named a missing name where a bound on that difference was missing.
- One repair sentence per rule for both dispositions: rejected because every probed refuted goal given the establish repair was rejected again elsewhere or compiled to dead code, while the unproved goals given a requirement compiled in one round.
- Pinning only the repair sentence: rejected because the EFF-2 add-and-remove repair stayed pinned while applying it produced a row every call rejects [EFF-5].
- Offering a requirement whenever the goal reads only parameters: rejected because a parameter the body writes or consumes before the goal no longer holds its entry value there, so the requirement would not establish the goal.
- Deciding the requirement route from every write in the body: rejected because a parameter consumed by the call that asks the goal, as `free_empty` consumes its window, would lose the one route that works for it.
- Deciding it from every write the walk has applied before the judgment: rejected because a write in one arm of a conditional then removes the route from a sibling arm walked later, so the same program with its arms swapped gets a different repair.
- Offering a callee's `ensures` for every goal over computed values: rejected because with no call result among the values the goal reads, the route can never be carried out.
