Decision: Stop requests enter a growing FIFO in the runtime pool and complete the ordinary pending record under the queue lock, while the same lock removes a timed-out waiter without consuming a later request, because requests already observed between calls must retain their order and a finite overwrite queue would lose that history, instead of a bounded queue with silent drops; pool exhaustion uses the existing reported runtime-resource termination.

Decision: On Linux the invocation blocks SIGINT and SIGTERM before the floor starts its entry thread, every scheduler-created thread inherits those signals blocked, and one receiver thread unblocks them with their default dispositions while no listener exists and blocks them while reading an open signalfd through the shared file adapter, because a listener can open on any driver and pthread_sigmask changes only the calling thread, instead of attempting to block already-running peer threads when the listener opens; the receiver owns open and close commands, and the startup cost is one native thread per invocation, to revisit when a measured workload makes that cost material.

Decision: The POSIX receiver serializes observation through signalfd reads or kqueue signal events and Windows publishes from its console callback under a lock, with a close-generation condition holding close, logoff and shutdown callbacks until their listener closes, because the host may merge signals before observation and Windows ends the process when those callbacks return, instead of reconstructing sender order from missing host history or returning from a termination callback before the program can stop ([host constraints](../../../research/investigations/stop-signals/README.md#hosts)).
