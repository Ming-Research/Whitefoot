Decision: A runtime-capacity Slots Box has an inline length, capacity and payload-pointer descriptor and owns one element allocation, because measure reads then reach the owner directly and the payload extent excludes metadata, instead of a pointer to a header-first allocation or a separately allocated descriptor. This is a provisional representation choice, reopened by owner-transport or append measurements; the [inline-owner screen](../../research/experiments/container-representation/vector-library/RESULTS.md#inline-runtime-slots-owner-registered-descriptor-placement-discriminator) compared against a split descriptor with reallocation, not the header-first implementation, and established no paired speedup. Runtime Array and Ring Boxes retain their thin header-first owners pending evidence for their own operations.

Decision: Fixed-capacity shapes keep their elements and required measures inline, while runtime measure and element access follow the shape and its selected owner representation, because a fixed capacity needs no stored payload pointer and the runtime Slots descriptor locates elements separately from the thin Array and Ring headers while satisfying OP-9's layout ceilings, instead of one physical header containing unused words or a placement-specific source interface.

Decision: Represent Slots and Ring with a shape, element type and optional capacity, retaining separate Array forms and one measured identity per specification row, because shape and optional capacity encode the distinctions layout and measure classification consume without separately synchronized placement flags. Retire the region-bearing view, store, arena and extent types rather than leave them unconstructible, because no current source or runtime consumer owns their semantics, instead of one checked type per placement or dead exhaustive-match arms.

Decision: A range reference lowers to a nonowning element pointer and count, with selected element accesses retaining their complete typed suffix and length read from the reference kind, because neither capacity nor allocator provenance is needed by the admitted operations and the selected element type cannot supply the range's length. The dedicated range place feeds ordinary address, value, reference, store and measure lowering, instead of coercing its pointer/count pair into an owned descriptor or materializing the source container's metadata beside it.

Decision: Provisionally resize a full positive-extent runtime Slots payload with realloc, retaining fresh allocation, initialized-prefix memcpy and free for partial or zero-extent windows, because the full initialized extent can be resized without an obligatory separate copy when the allocator extends it in place, while partial windows need copy only their initialized prefix and STOR-7 permits relocation. The [ordinary-source comparison](../../research/experiments/container-representation/vector-library/RESULTS.md#ordinary-source-compilation-of-inline-slots-ownership) exposes the large full-growth copy cost, but the earlier resize/copy comparisons expose small-growth tradeoffs; this candidate must be measured across those cells before selection, instead of adopting a byte cutoff or claiming realloc is universally faster. A failed resize leaves the old owner and payload intact until the resource floor terminates execution.

Decision: Shift a contiguous Slots suffix with one overlap-safe memmove and retain the directional element walk for Ring, because Slots has one contiguous physical extent while a wrapped Ring does not, instead of requiring LLVM to recover a bulk transfer from each element-copy loop. Validate boundary, owning-element and zero-stride cases; the native-code criterion is one bulk move without a per-element loop, and API timings determine the performance result.

Decision: Ordinary target lowering substitutes zero only for the element-address operand of a step whose selected-target stride is zero, retaining logical indices, lengths and window coordinates in their other uses, because STOR-6 requires exact target-domain representations for the indices actually used in address formation while a zero-stride step has zero displacement for every admitted logical index, instead of rejecting representable zero-byte storage because its logical cardinality exceeds the signed address domain or weakening STOR-6 to permit unrepresentable address operands. The rule uses the checked target layout for the element of each step, including nested places, generated fill and cleanup walks, ranges and transfer-size calculations; an empty final field does not erase a nonzero-stride outer step.

Decision: A constant-capacity zero Array, Slots or Ring omits its nonexistent element's target alignment by representing the empty payload as a zero-length byte array, while Slots and Ring retain their ordinary descriptor words, because OP-9 repeats the element layout zero times and nested owners must be qualified against the representation actually emitted, instead of preserving a typed empty tail that can enlarge the header and stride beyond the calculated layout or rejecting an otherwise representable empty owner. Runtime Array and Ring tails remain typed because they can hold elements; runtime Slots uses its separately allocated element storage; a nonzero capacity of a zero-size element is a different case and keeps its ordinary coordinate rules.

Decision: A `Segments<T>` Box owner is one pointer to one header-first allocation holding the segment count, the count plus one element offsets beginning at zero, and then the elements at the first offset past the bounds that the element's alignment admits, recomputed from the count at each access, because this keeps the owner a thin pointer released by one free like runtime Array and Ring and a segment's range is two bound loads and one address step, instead of a separately allocated bounds array, which adds an allocation and release, or a stored element-offset word, which would replace a shift, an add and a mask per access with one load; this last choice is provisional, unmeasured, and reopens if a profile shows the offset computation on a hot path. The construction sums the lengths once and judges the size predicate with the language layout ceiling, so every qualified target returns the same result, instead of the actual target stride.

Rejected:
- Claiming the thin owner is universally faster than a fat descriptor: rejected because owner width, measure loads, allocation count, copying and linked layout have different costs, and the retained measurements do not isolate the general choice.
- Keeping a pointer to a separately allocated runtime Slots descriptor and a second element block: rejected because it adds a descriptor allocation, release and indirection to the inline owner's one payload allocation; the owner-transport tradeoff remains open to measurement.
- Depending on optional optimizer facts or LLVM dead-code elimination to erase a zero-stride address: rejected because qualification must hold for ordinary pre-optimization materialization and facts must not select target success.
- Replacing every logical index of a zero-byte element with zero: rejected because bounds, range lengths, window coordinates and source observations retain their original logical values.
- Retaining the high-alignment typed tail and rejecting nested zero-capacity owners under the existing language ceilings: rejected because no element is present to require that alignment, and the existing zero-capacity Array representation supplies a semantics-preserving omission without reducing container capability.
- Treating a zero-length typed LLVM array as alignment-free: rejected because its element still determines the LLVM ABI alignment, so header, stride and parent-object qualification can disagree with actual emission.
