Decision: Read bodyless prelude function records from the generated signature sequence with the generated optional generic header, and resolve ordinary opaque prelude declarations to their compiler-owned storage identities without contributing a second name candidate, because this preserves one declaration grammar and diagnostic order while TYPE-9 still owns layout and measure behavior the field list cannot express, instead of a handwritten parallel grammar, synthetic empty bodies or duplicate nominal registrations. Opacity is checked from the declaration before constructor lookup, so forbidden construction cannot become a missing-template compiler failure.

Decision: Keep the closed PRE-1 operation identities as compiler metadata: window parameters are recognized by prelude origin plus the specified W/X spelling, while the operand table records which operand and type component supplies each parameter; allocating operations seed allocation analysis and bound-ending operations select the required invalidation, because rows alone omit allocation and do not describe which element-reference bounds an operation ends. These selections are over the closed declaration domain and cannot be spoofed by a source declaration, instead of inventing writer-visible markers or attempting to infer every property from read/write paths. Ordinary source parameters with the same spelling remain ordinary generics.

Decision: Emit the twenty compiler-owned PRE-1 operations as shared ordinary out-of-line bodies, one per materialized instance, with a complete dispatch inventory and an explicit unsupported stop at body construction if an implementation is missing, because checked calls already carry the source obligations and shared bodies avoid duplicating generic window arithmetic at every call. Post-check inline expansion could reuse those same obligations, but is not selected without evidence that its specialization benefit outweighs duplication, instead of treating expansion as a second semantic checker or treating the dispatch list as an unimplemented-row list. Capability stops occur after source checking and do not become source rejections or undefined linker symbols.

Decision: Window operations retain one checked shape and logical-coordinate interface, with suffix transfer following the representation decision in [storage-representation](storage-representation.md); proved-empty release frees only the owned storage and emits no element release, because wrapped rings require their logical coordinates and an empty linear window has no element the compiler is allowed to drop, instead of making the transfer implementation a source permission or retaining the retired implicit empty-linear-window scope release.

Decision: Require a nonempty caller-provided source-record sequence before the public compilation path injects prelude declarations, while retaining the complete internal bundle for resource ceilings and the lower-level transport's existing envelope-checking use, because PROG-2 binds the invocation's source identity and PRE-1 declarations have no writer source event, instead of allowing compiler-owned prelude storage to turn an absent source unit into a valid invocation. A present record proceeds to ordinary source checks even if it contains no declarations; absence is an invocation failure without a source-language rule.
