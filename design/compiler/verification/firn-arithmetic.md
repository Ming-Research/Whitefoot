Decision: Firn's string and hash floating increments use one software x87 implementation in `extended`, with separate command reply oracles and binary64 sorted-set scores kept separate, because the two increment commands require the same selected precision and rounding while differing in validation order, and the canonical representation distinguishes signed infinities and NaN without exposing its private finite-only formatter ([integration grounds](../../../research/investigations/firn/DESIGN.md#one-x87-implementation)), instead of maintaining two arithmetic representations for the same command-level operation or using the host's varying `long double` format.
