Decision: Every payload string that names a source construct names it in its canonical source spelling through the one checker renderer for that kind of construct: a resolved place as the place expression the caller would write, with a reference parameter followed by `^`, fields and payload steps by name and each index by the value it captured; a function or type instance as a call or declaration writes it, with its type and const arguments; and a literal value as its FORM-5 literal, because the main reader is an agent that repairs the source it wrote and cannot map an internal binding number, field ordinal, instance symbol or bit pattern back to it, instead of printing the checker's identities or `Debug` values, or special-casing each rejection that happened to leak one.

Decision: EFF-2's `expected_row` removes covered entries from the exhibited row for an acyclic function, and for a recursive call component identified by source declarations rather than generic instance identities it closes captured formal-rooted argument projections with common-prefix widening in each category, removes entries the resulting bodies do not exhibit, and names every component boundary that must change, because [the recursive repair pairs](../../compiler/src/driver/pinned_repairs/recursive_effects.rs) witness that substituting a newly suggested row otherwise exhibits a deeper path on every repair round, and DIAG-1 requires the directed edits to satisfy EFF-2's two-way covering, instead of treating the current body contribution as unchanged by recursive substitution. Every proposed row retains EFF-1 canonical order and removes covered entries; acceptance still compares the original structural body effects against written callee rows, and acyclic repair text stays unchanged.

Decision: Acyclic EFF-2 repairs preserve separate uncovered entries rather than merging one parameter's entries into a wider write, because every pair the canonical row leaves on one parameter either overlaps whatever its positions are, which EFF-5 does not compare, or depends on positions that each call's own proof decides, instead of widening caller kills and reference invalidations to avoid a call-site proof. The [one-argument rows investigation](../../research/investigations/one-argument-rows/DESIGN.md#the-rule) states the EFF-5 and EFF-1 change that removes the need for that merge; recursive widening instead addresses repeated row substitution, which that change did not address.

Rejected:
- Listing the exhibited set as the suggested row: rejected because it can pair an entry with a write at or above its path, as the counter example `reads(stats.count), writes(stats.count)` did, which EFF-1 refuses at the declaration.
- Merging acyclic entries of one parameter into one `writes` of their common path to avoid EFF-5 separation: rejected because the merged write can cover storage the body never writes, which widens every caller's kills and reference invalidations beyond what the body does, and because whether two indexed positions select one element depends on the values a call supplies, which EFF-5 asks the call site to prove.
- Rendering a computed index as an invented expression: rejected because the checker captures the value's identity and not the argument's text, so any expression it printed could name a different value; it renders as `?`.
