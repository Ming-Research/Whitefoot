Decision: Every payload string that names a source construct names it in its canonical source spelling through the one checker renderer for that kind of construct: a resolved place as the place expression the caller would write, with a reference parameter under `deref`, fields and payload steps by name and each index by the value it captured; a function or type instance as a call or declaration writes it, with its type and const arguments; and a literal value as its FORM-5 literal, because the main reader is an agent that repairs the source it wrote and cannot map an internal binding number, field ordinal, instance symbol or bit pattern back to it, instead of printing the checker's identities or `Debug` values, or special-casing each rejection that happened to leak one.

Decision: A suggested repair is one the language admits wherever it is applied: EFF-2's `expected_row` is the exhibited row without the entries another of its entries covers, a read or write at or below an exhibited write's path and a read below another exhibited read, so every entry is a path the body accesses, EFF-1 admits the row as written, EFF-2 admits it for the body, and `missing` names exact entries, because an agent applies a suggestion literally and a suggestion that fails at the declaration or at every call costs compile rounds and teaches nothing, while every pair such a row leaves on one parameter either overlaps whatever its positions are, which EFF-5 does not compare, or depends on positions that each call's own proof decides, instead of printing the raw exhibited set or merging entries into a wider write. The [one-argument rows investigation](../../research/investigations/one-argument-rows/DESIGN.md#the-rule) states the EFF-5 and EFF-1 change that removes the need for the merge.

Rejected:
- Listing the exhibited set as the suggested row: rejected because it can pair an entry with a write at or above its path, as the counter example `reads(stats.count), writes(stats.count)` did, which EFF-1 refuses at the declaration.
- Merging entries of one parameter into one `writes` of their common path: rejected because the merged write can cover storage the body never writes, which widens every caller's kills and reference invalidations beyond what the body does, and because whether two indexed positions select one element depends on the values a call supplies, which EFF-5 asks the call site to prove.
- Rendering a computed index as an invented expression: rejected because the checker captures the value's identity and not the argument's text, so any expression it printed could name a different value; it renders as `?`.
