Decision: Ordinary shared states use one lock unit per object: a map object is held by entries or whole, and an ordinary scalar or aggregate state by its one lock. Atomic values use the capability-selected operation in the [atomic-value decision](state-locks/atomic-value-placement.md). This is because a map is only ever a state [TYPE-9] and state that changes apart lives in separate objects, so a statement's holds are its targets and need no layout derived from a state's fields. This is instead of lock units derived from the state's declaration, one for each keyed-table field and one for the other fields, which the map's placement removes.

Decision: Every lock a statement takes follows one order: targets of different types by a static total order of their types, targets of one type by their objects' identities at run time, and within a map its entries in the sorted key order (compiler/waiting-contexts/concurrent-map). The order of types is primitive types in [TYPE-1] order, then prelude nominals in [PRE-1] order, then source and host-module nominals by module path then name, bytewise, then type arguments left to right, each type recursively in this order and each const by numeric value. Targets of one type are taken together as a group, sorted by identity. A use of an ordinary target takes its type group together with every earlier group not yet taken; an atomic-value operation takes every remaining ordinary group before performing its state operation. Each group is acquired at its first such trigger on the path. A group with an entry or key-set target, and every group the guard reads, is taken before the guard together with every group before it. The reasons: every wait is then for a lock after every lock the waiter holds, so no cycle of waits forms; identities are known only at run time, which is why one type's targets are taken together; a map's take reads its header keys, which the statement reads when it begins and its block may write or release; and, on a path with no earlier atomic-value operation, a target reached only on a conditional tail, firn's log after a key's entry, is taken only on the path that reaches it ([locking](../../../research/investigations/shared-state/DESIGN.md#locking-order-taking-and-release)). The name rather than the declaration position orders source and host-module types so that every compiled fragment computes the same order (compiler/incremental-compilation). This is instead of ordering by identity alone with every target taken when the statement begins, which holds the log through every logged write's whole block, or levels declared in types (language/waiting/shared-objects).

Decision: Targets of one statement that name one object are held once. A whole hold absorbs entry holds, an exclusive hold absorbs a shared one, and the entries of several targets are held together, sorted without repeats, each binding finding its entry in the merged hold. This is because the checker treats such targets as possibly one storage [SHARE-2], and a second lock on an object the statement holds would wait on itself. This is instead of refusing such statements, which needs handle identities no static rule has, or failing at run time, which the language has none of.

Decision: A statement releases every object it took when its block ends by any edge, because every taking then precedes every release, which is two-phase locking, so each execution equals one in which the statements on a state run one after another, each with the whole state to itself, instead of releasing a unit once the block no longer uses it, which two-phase locking also allows after the last taking and which waits for a workload whose holds show it to matter.

Decision: A statement whose guard reads false registers a watch, kept in its frame, on each object the guard read while it still holds it, then releases every object it took and parks; a write to an entry wakes the watches of that entry's whole map, and a write to an ordinary object notifies the oldest of its watches whose wake test holds in the state the write leaves (the next decisions), because a write that takes such a unit after the release finds the watch, so no wake is lost, a watch whose test is false there has a false guard there, and how often a guard is evaluated is not observable [SHARE-3], so a wake that finds the guard still false costs time and never correctness, instead of a list of watchers for each entry, which must survive the table's moves to larger tables and waits for a program whose blocking pops show the cost, or of waking every watch of a written object, which at N = 50 on the guard-fairness probe woke 29.9 watches per take, 29.0 of them to find their guard still false ([results](../../../research/investigations/guard-fairness/DESIGN.md#8-results)).

Decision: Lowering derives for each object target a wake test, a condition over that object's state that the guard implies, by splitting the guard over `band`, `bor` and `bnot` and keeping each comparison of an integer, `Bool` or tag-only enum scalar reached from the state through fields with a constant, a local the registration captures, or another such scalar of the same object, every other part, a comparison over another target included, becoming true, and at most four atoms kept, later conjuncts dropped and an oversized disjunction becoming true, because a guard writes no state [SHARE-2] and the test reads only the object's state and values fixed while the watch is registered, so a write that leaves the test false leaves the guard false, and evaluating a consequence of the guard needs no specification change [SHARE-3], instead of having the releaser run each waiter's guard, or freezing other targets' atoms at their registration values ([design study](../../../research/investigations/guard-fairness/DESIGN.md#wake-only-guards-that-may-hold-design-study)).

Decision: A write to an ordinary object evaluates each distinct wake test once and notifies only the oldest watch whose test holds, ordered by its statement's first registration and then its context's identity, because a watch whose test is false has a false guard and needs no attempt, while waking every watch whose test holds still woke 26 watches per take at N = 50 and ran at 0.91 to 0.92 of baseline against 0.69 to 0.70 for one notification ([results](../../../research/investigations/guard-fairness/DESIGN.md#8-results)), and which waiting statement attempts first is a scheduling choice [WAIT-2] that changes neither source acceptance nor the progress the specification promises, instead of waking every watch whose test holds.

Decision: A notification given to a watch whose statement has waited longer than the runtime's age threshold (WF_GUARD_TURN_AGE_NS, provisionally 1,000,000 ns) reserves the object's next attempt for it, so that an ordinary newcomer cannot take the object while the reservation lives, and a younger watch's notification leaves newcomers free to overtake it, because the reservation bounds how long a guard that stays true waits, the N = 50 probe's longest wait falling from 524 to 534 ms at baseline to 1.31 to 1.34 ms, while a turn on every wake cost firn's limiter-script engine 7.5 to 47 times its throughput ([engine comparison](../../../research/investigations/guard-fairness/DESIGN.md#result-on-firns-engine-turns-are-far-worse)), instead of turns on every wake or no reservation. The threshold is provisional: 1 ms is a hypothesis that short contention keeps throughput while long waits get an attempt, compared with no other value; at N = 2 the candidate cost 5 to 6 percent over baseline, and its p99 wait at N = 8 and 50 is about 1 ms, both attributed to the threshold's turn by inference only, since the measured arms share the turn, the registration clock sample, the holds accounting, the refusal check and the circular queue, and no arm separates them ([results](../../../research/investigations/guard-fairness/DESIGN.md#8-results)); it is reopened when a workload's measured tail latency or firn's engine comparison with wake tests shows the threshold's cost.

Decision: A live reservation refuses only a statement that holds no object, whether it asks for one object or for the first of a type group, which then parks holding none of the group, and admits a statement already holding an object earlier in the lock order, a statement holding a table's entries and a cancellation firing's state update, because the reserved retry takes its objects in the lock order and may need an earlier object or entry that such a holder keeps, so refusing the holder would leave each waiting for the other, a holder of entries keeps its driver and cannot park, and a firing is the write that makes guards such as `available || fired` true, so it must not wait for the guards it wakes ([reservation lifetime](../../../research/investigations/guard-fairness/DESIGN.md#reservation-lifetime-and-progress-obligations)), instead of refusing every statement but the reservation's owner.

Decision: a live reservation never delays a claim (compiler/waiting-contexts), which an unlock grants whether or not the parked statements include one the reservation admits, while a waiting claim refuses the reservation's owner as it refuses every other statement that parks, which then waits in the queue the reservation's wakes reach first, because a claim's owner holds a table's entries or an earlier object that the reserved retry may need before it can take this one, so a claim behind the reservation would leave each waiting for the other, while the owner refused by a claim parks, freeing its driver, and is handed the object after at most WF_SHARED_HANDOFF vain wakes, as without claims ([integration](../../../research/investigations/shared-take-fairness/DESIGN.md#integration-with-guard-reservations)), instead of claims that wait for the reservation's retry, or a reservation that the claims' owners cannot overtake.

Decision: A notified retry whose guard reads false, or that succeeds without writing the object, passes the notification to the next watch after it whose test holds and whose statement began waiting no later than the notifying write's clock sample, a successful write starts a new sweep from the oldest watch whose test holds, and a write while another context owns the notification marks that owner to sweep again after its release when the write made true the test of a watch older than the owner or begun after that sample, because a watch whose test a write made true would otherwise lose that write's wake when an attempt before it wrote nothing, the owner's pass reaches neither of those watches, and the sample keeps statements that began waiting after the write, whose guards read false on the written state, from extending a sweep without a further write, instead of waking every remaining watch whose test holds at once or letting each write restart the sweep ahead of the watches the owner's pass has still to reach ([reservation lifetime](../../../research/investigations/guard-fairness/DESIGN.md#reservation-lifetime-and-progress-obligations)).

Decision: A multi-object retry notified for a second object while it owns a first object's notification keeps the first, and the second object's notification continues to that object's next watch whose test holds, because the owner ends its notification only by releasing the first object, and replacing it would leave that release with no notification to end, instead of moving the context's notification to the second object ([reservation lifetime](../../../research/investigations/guard-fairness/DESIGN.md#reservation-lifetime-and-progress-obligations)).

Decision: Once a sweep has passed through every watch it reaches, the object's ordinary acquisition queue advances before another sweep begins, because a statement without a guard, or one whose guard stays true, must eventually proceed [WAIT-2], instead of letting sweeps follow one another while their reservations refuse the queue.

Decision: A release passes whether its statement's block or guard may write the object, from the checker's per-target write effects, which include the writes a called function's row declares, and a release that may have written nothing starts no sweep, because a statement that writes nothing leaves every guard's answer as it was, while releasing every object as written, as lowering did, made each read-only block's release wake watchers for nothing ([design study](../../../research/investigations/guard-fairness/DESIGN.md#wake-only-guards-that-may-hold-design-study)), instead of a sweep on every release.

Decision: An ordinary object's watch links sit in buckets, one per distinct test, each a ring in age and context-identity order whose newest link carries the bucket's place in the object's chain of buckets, and each link names its test, which the watching frame keeps unchanged while the link is registered, because a write then evaluates one test per bucket and finds the oldest watch whose test holds as the oldest head among the buckets whose test holds, with no allocation, and a new statement's link is placed in constant time, instead of one list of every watch in age order, which would evaluate every watch's test, or a copy of each test in its link, which would add the test's 104 bytes to every link; the watch record grows from 152 to 248 bytes for three more pointers per link, and a notification passed on searches each bucket from its oldest link ([implementation](../../../research/investigations/guard-fairness/DESIGN.md#7-implementation)).

Decision: The shared acquisition queue stores only its tail, whose next link is its head, because one pointer leaves room for the reservation within the fixed shared header while retaining constant-time insertion and removal, instead of enlarging the header for a separate head pointer.

Decision: the claims' circular queue lives in the claimants' own stack records, and its tail shares the header's one reservation slot, told apart by the address's low bit, the tail record keeping the reservation while claims wait and handing it back with the last grant, and the claims' turn with the parked queue is a byte in the header's padding, because the header already fills the 64 bytes before WF_SHARED_STATE_OFFSET, on which emitted code and the cancellation state's address depend, and both are read only under the object's lock, so one tag test is all the slot adds to an admission ([representation](../../../research/investigations/shared-take-fairness/DESIGN.md#representation)), instead of growing the header and moving every object's state, a global table of claims keyed by object behind a lock of its own, or narrowing the handle or holder count to make room.

Decision: An entry the statement's guard reads is locked alone, never read beside other readers, because a shared read of an absent key holds no cell, so an insert of that key could end before the guard's watch exists and the guard would wait for a write that already happened, instead of registering the watch before the guard's first evaluation, which every statement with a guard would pay for whether it waits or not.

Decision: A `swap` of two maps exchanges their entries and leaves each map where it is, so a handle's object stays the map it named. This is because a statement that has read a handle orders and waits by that object's identity, and a map replaced by another object would let it lock entries of a map no handle names. This is instead of exchanging the objects' states by address.

Decision: Under a whole hold a read of an absent key reads a shared `None` and allocates nothing, a write materializes the key's cell, and a cell left `None` is given back when the hold is released, as the header's keys are, because a block that probes many keys and writes few would otherwise fill the table with empty cells, instead of materializing on every read or keeping empty cells until the table is released.

Decision: A map borrow materializes its selection only when its root may be written in the context executing it: a path at or under a path the row writes, or an atomic binding its statement writes through, with a captured place read-only in a split chunk when the body's footprint writes no overlapping path; otherwise selection reads the stable index and an absent key's shared immutable `None`, changing neither the table nor its shared hold records, because readers under a read-only whole-map hold or in split chunks may run concurrently and must not mutate the table, instead of always materializing on borrow or making hold descriptors thread-safe for concurrent readers. The checker retains the formation's current write permission, resolved places and state roots; lowering refines them from the completed atomic statement and split body's write footprint, and a read selection over a key set uses a private frame descriptor rather than a table hold.

Decision: Lazy type groups retain their taken state in one naturally aligned word, while eager groups and direct single-entry targets need no taken flag, because under the former uniform-alignment requirement a one-bit address forced the function frame into one aggregate and preserved entry copies in LLVM ([Firn comparison](../../../research/investigations/shared-state/DESIGN.md#firn-entry-path-ir-comparison)), instead of per-target Boolean frame slots. Mixed-alignment independent allocations remove that reason for ordinary positive-sized roots; the existing word representation remains pending a comparison with one Boolean per lazy group, reopened when flag storage or its generated code is material in a consumer. No current performance advantage for the word follows from the earlier comparison. Group descriptors and existing hold records also use natural eight-byte alignment.

Decision: Cancellation sources, watches and SharedRead views retain one ordinary shared unit, with the public Bool protected by that unit and an atomic host-wait mirror published during its held transition, because guards need stable state and register-before-release watches while find-at-fire host waits must remain outside that lock, instead of registering host waits under the cancellation unit. A never-firing watch retains the permanent private unfired shared unit, whose runtime reference keeps it live; host waits translate that unit to the existing no-watch sentinel, because ordinary shared release then applies to every handle without allocating a never state per call or adding host-wait registration. Firing uses the same bounded acquisition and handoff as atomic statements, through the native waiting start/wait/finish boundary, whose shared-acquisition response retries wait after a wake before finishing.

Decision: `whitefootc --lock-ledger` reports each atomic statement's ordered target groups, their source bindings and state type, whether acquisition occurs before the guard, on every body path, on some body paths or never, and the first-use sites and later groups that cause earlier groups to be taken, because a writer otherwise cannot see that an early state read or a preceding type group extends a hold. Lowering records its actual acquisition requests and classifies their placement on its emitted control-flow graph, retaining the report as module comments for the opt-in developer channel, instead of a warning on early use, which is often intended, or a separate source analysis that could disagree with the acquired groups. The path classification describes emitted control flow without proving branch feasibility or call termination; it changes neither acceptance nor acquisition placement.

Rejected:
- Oldest-only handoff that woke every watch below the age threshold, with or without an age-ordered wait queue: rejected because the N = 50 probe measured 1.61 and, with the ordered queue, 1.629/1.631 times baseline runtime against the 1.10 limit, with valid twins and passing fairness ([ordered-queue results](../../../research/investigations/guard-fairness/DESIGN.md#ordered-queue-results)).
- The releaser running each waiter's guard: rejected because it makes one opaque call on a cold record per watch under the object lock, estimated at 2.5-7.5 us per write at N = 50, the size of the cost being removed, shares no evaluation between equal guards, and must still wake a guard over an object the releaser does not hold ([design study](../../../research/investigations/guard-fairness/DESIGN.md#wake-only-guards-that-may-hold-design-study)).
- Freezing another target's atoms at their registration values: rejected because a guard `band(a, b)` registered with both false skips the write that sets b, whose test reads a's frozen false value, and then the write that sets a, whose test reads b's, so its wake is lost ([hard cases](../../../research/investigations/guard-fairness/DESIGN.md#2-hard-cases)).
- Age-bounded turns granted in bulk: rejected because the N = 50 probe measured 40.2-47.8 ms maximum waits against approximately 3.3 ms bounds and 10.34-10.49 times baseline runtime; every write still wakes all watchers, and a turn spent before guard evaluation can end in another false retry ([measured results and attribution limits](../../../research/investigations/guard-fairness/DESIGN.md#age-bounded-turns-results)).
- Strict turns on every guard wake: rejected because firn's limiter-script engine lost 7.5 times throughput at 8 connections and 47 times at 50, while p99 at 50 rose from about 1.6 ms to about 52 ms ([engine comparison](../../../research/investigations/guard-fairness/DESIGN.md#result-on-firns-engine-turns-are-far-worse)); the subsequent age-bounded candidate also failed its probe criteria.
- A table with header entries taken at its first use in the block: rejected because the take reads the keys' bytes and key sets, and a block that wrote a key's bytes before that use had the take lock the entry under the bytes it wrote, and one that released them had the take read released memory, which an adversarial program met as a fault; refusing every write and release of a key's storage inside the block was the other repair, and it would refuse blocks the language admits for a lowering's timing.
- A table replaced by storing the new table's address, the old table freed when the write releases it: rejected because a statement that read the address before the write waits at the old table's gate and then locks its entries, which `map_resets.wf` would answer with entries that no longer reach the state.
- A twin of a statement's block, its counted loops, matches and key computations, run before the hold to collect the keys the block reaches (the replaced node compiler/waiting-contexts/held-keys): rejected because a statement now names its entries in its header, so its keys are values when it begins and nothing need run early.
- Always materializing a borrowed table entry: rejected because a borrow under a read-only whole-map hold permits concurrent readers, so materializing cells or changing its hold descriptors would mutate shared storage without exclusion.
- Making table hold descriptors thread-safe for concurrent readers: rejected because a read needs only the stable index and immutable `None`, so synchronized descriptor mutation adds coordination to an operation that requires none.
- Replaced state-field lock layout: rejected because each map is now an object of its own and targets directly determine the holds.
- Replaced grant-based acquisition: rejected because several objects require a global type and identity order.
- Local-table pending holds: rejected because TYPE-9 admits maps only as shared-object states.
- Replacing a map by assigning a map value: rejected because TYPE-9 admits no such expression; map swap is the exchange.
