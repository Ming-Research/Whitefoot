Decision: Each shared object is one lock unit: a map object is held by entries or whole, and any other object by its one lock. This is because a map is only ever a state [TYPE-9] and state that changes apart lives in separate objects, so a statement's holds are its targets and need no layout derived from a state's fields. This is instead of lock units derived from the state's declaration, one for each keyed-table field and one for the other fields, which the map's placement removes.

Decision: Every lock a statement takes follows one order: targets of different types by a static total order of their types, targets of one type by their objects' identities at run time, and within a map its entries in the sorted key order (compiler/waiting-contexts/concurrent-map). The order of types is primitive types in [TYPE-1] order, then prelude nominals in [PRE-1] order, then source and host-module nominals by module path then name, bytewise, then type arguments left to right, each type recursively in this order and each const by numeric value. Targets of one type are taken together as a group, sorted by identity. A group is taken at the first use of any of its targets on the path, together with every group before it not yet taken. A group with an entry or key-set target, and every group the guard reads, is taken before the guard together with every group before it. The reasons: every wait is then for a lock after every lock the waiter holds, so no cycle of waits forms; identities are known only at run time, which is why one type's targets are taken together; a map's take reads its header keys, which the statement reads when it begins and its block may write or release; and a target reached only on a conditional tail, firn's log after a key's entry, is taken only on the path that reaches it ([locking](../../../research/investigations/shared-state/DESIGN.md#locking-order-taking-and-release)). The name rather than the declaration position orders source and host-module types so that every compiled fragment computes the same order (compiler/incremental-compilation). This is instead of ordering by identity alone with every target taken when the statement begins, which holds the log through every logged write's whole block, or levels declared in types (language/waiting/shared-objects).

Decision: Targets of one statement that name one object are held once. A whole hold absorbs entry holds, an exclusive hold absorbs a shared one, and the entries of several targets are held together, sorted without repeats, each binding finding its entry in the merged hold. This is because the checker treats such targets as possibly one storage [SHARE-2], and a second lock on an object the statement holds would wait on itself. This is instead of refusing such statements, which needs handle identities no static rule has, or failing at run time, which the language has none of.

Decision: A statement releases every object it took when its block ends by any edge, because every taking then precedes every release, which is two-phase locking, so each execution equals one in which the statements on a state run one after another, each with the whole state to itself, instead of releasing a unit once the block no longer uses it, which two-phase locking also allows after the last taking and which waits for a workload whose holds show it to matter.

Decision: Proposed with wake tests (the next decision): a statement whose guard reads false registers a watch, kept in its frame, on each object the guard read while it still holds it, then releases every object it took and parks; a write to an entry wakes the watches of that entry's whole map, and a write to an ordinary object notifies only watches whose wake test holds in the state the write leaves, because a write that takes such a unit after the release finds the watch, so no wake is lost, a watch whose test is false there has a false guard there, and how often a guard is evaluated is not observable [SHARE-3], so a wake that finds the guard still false costs time and never correctness, instead of a list of watchers for each entry, which must survive the table's moves to larger tables and waits for a program whose blocking pops show the cost, or of every watch of a written object, the approved form this replaces, whose wakes after a write that left every guard false the design study attributes most of the probe's remaining cost to ([design study](../../../research/investigations/guard-fairness/DESIGN.md#wake-only-guards-that-may-hold-design-study)).

Decision: Proposed for design A: lowering derives for each object target a wake test, a condition over that object's state that the guard implies, by splitting the guard over `band`, `bor` and `bnot` and keeping each comparison of an integer, `Bool` or tag-only enum scalar reached from the state through fields with a constant, a local the registration captures, or another such scalar of the same object, every other part, a comparison over another target included, becoming true and at most four atoms kept, later conjuncts dropped and an oversized disjunction becoming true; a write evaluates each distinct test once and notifies the oldest watch whose test holds, reserving its next attempt when that watch has waited longer than WF_GUARD_TURN_AGE_NS (provisionally 1,000,000 ns) and otherwise leaving newcomers free to overtake it; a notified retry that reads false or succeeds without writing passes the notification to the next watch whose test holds inside the write's clock cutoff, and a successful write starts a new sweep; a release passes whether its statement's block or guard may write the object, and one that writes nothing starts no sweep, because a guard writes no state [SHARE-2] and its test reads only the object's state and values fixed while the watch is registered, so a write that leaves the test false leaves the guard false, and evaluating consequences of the guard and choosing which waiter attempts first need no specification change [SHARE-3, WAIT-2], instead of waking every watch below the threshold, as step B did, having the releaser run each guard, or freezing other targets' atoms at their registration values ([design study](../../../research/investigations/guard-fairness/DESIGN.md#wake-only-guards-that-may-hold-design-study), [implementation](../../../research/investigations/guard-fairness/DESIGN.md#7-implementation)). Step B's other rules stand: earlier-object holders, table-entry holders and cancellation-state updates remain exempt from a reservation, and an ordinary newcomer cannot bypass a live one; a multi-object retry notified for a second object keeps its first notification, and the second object's continues to its next watch whose test holds, because replacing the original owner would lose its release obligation; an exhausted sweep admits ordinary acquisition progress before another sweep, because an unguarded or persistently enabled statement must eventually proceed [WAIT-2]. This changes runtime scheduling, not source acceptance or the specification's progress guarantee.

Decision: Proposed with wake tests: an ordinary object's watch links sit in buckets, one per distinct test, each a ring in age and context-identity order whose newest link carries the bucket's place in the object's chain of buckets, and each link names its test, which the watching frame keeps unchanged while the link is registered, because a write then evaluates one test per bucket and finds the oldest watch whose test holds as the oldest head among the buckets whose test holds, with no allocation, and a new statement's link is placed in constant time, instead of one age-ordered list with a reservation anchor, which would evaluate every watch's test, or a copy of each test in its link, which would add the test's 104 bytes to every link; the watch record grows from 152 to 248 bytes for three more pointers per link, and a notification passed on searches each bucket from its oldest link, without the anchor ([implementation](../../../research/investigations/guard-fairness/DESIGN.md#7-implementation)).

Decision: The shared acquisition queue stores only its tail, whose next link is its head, because one pointer leaves room for the fairness state within the fixed shared header while retaining constant-time insertion and removal, instead of enlarging the header for a separate head pointer.

Decision: An entry the statement's guard reads is locked alone, never read beside other readers, because a shared read of an absent key holds no cell, so an insert of that key could end before the guard's watch exists and the guard would wait for a write that already happened, instead of registering the watch before the guard's first evaluation, which every statement with a guard would pay for whether it waits or not.

Decision: A `swap` of two maps exchanges their entries and leaves each map where it is, so a handle's object stays the map it named. This is because a statement that has read a handle orders and waits by that object's identity, and a map replaced by another object would let it lock entries of a map no handle names. This is instead of exchanging the objects' states by address.

Decision: Under a whole hold a read of an absent key reads a shared `None` and allocates nothing, a write materializes the key's cell, and a cell left `None` is given back when the hold is released, as the header's keys are, because a block that probes many keys and writes few would otherwise fill the table with empty cells, instead of materializing on every read or keeping empty cells until the table is released.

Decision: A map borrow materializes its selection only when its root may be written in the context executing it: a path at or under a path the row writes, or an atomic binding its statement writes through, with a captured place read-only in a split chunk when the body's footprint writes no overlapping path; otherwise selection reads the stable index and an absent key's shared immutable `None`, changing neither the table nor its shared hold records, because readers under a read-only whole-map hold or in split chunks may run concurrently and must not mutate the table, instead of always materializing on borrow or making hold descriptors thread-safe for concurrent readers. The checker retains the formation's current write permission, resolved places and state roots; lowering refines them from the completed atomic statement and split body's write footprint, and a read selection over a key set uses a private frame descriptor rather than a table hold.

Decision: Lazy type groups retain their taken state in one naturally aligned word, while eager groups and direct single-entry targets need no taken flag, because under the former uniform-alignment requirement a one-bit address forced the function frame into one aggregate and preserved entry copies in LLVM ([Firn comparison](../../../research/investigations/shared-state/DESIGN.md#firn-entry-path-ir-comparison)), instead of per-target Boolean frame slots. Mixed-alignment independent allocations remove that reason for ordinary positive-sized roots; the existing word representation remains pending a comparison with one Boolean per lazy group, reopened when flag storage or its generated code is material in a consumer. No current performance advantage for the word follows from the earlier comparison. Group descriptors and existing hold records also use natural eight-byte alignment.

Decision: Cancellation sources, watches and SharedRead views retain one ordinary shared unit, with the public Bool protected by that unit and an atomic host-wait mirror published during its held transition, because guards need stable state and register-before-release watches while find-at-fire host waits must remain outside that lock, instead of registering host waits under the cancellation unit. A never-firing watch retains the permanent private unfired shared unit, whose runtime reference keeps it live; host waits translate that unit to the existing no-watch sentinel, because ordinary shared release then applies to every handle without allocating a never state per call or adding host-wait registration. Firing uses the same bounded acquisition and handoff as atomic statements, through the native waiting start/wait/finish boundary, whose shared-acquisition response retries wait after a wake before finishing.

Rejected:
- Oldest-only handoff with every watch woken below the threshold (step B), with or without an age-ordered wait queue: rejected because the N = 50 probe measured 1.61 and, with the ordered queue, 1.629/1.631 times baseline runtime against the 1.10 limit, with valid twins and passing fairness ([ordered-queue results](../../../research/investigations/guard-fairness/DESIGN.md#ordered-queue-results)).
- The releaser running each waiter's guard: rejected because it makes one opaque call on a cold record per watch under the object lock, estimated at 2.5-7.5 us per write at N = 50, the size of the cost being removed, shares no evaluation between equal guards, and must still wake a guard over an object the releaser does not hold ([design study](../../../research/investigations/guard-fairness/DESIGN.md#wake-only-guards-that-may-hold-design-study)).
- Freezing another target's atoms at their registration values: rejected because a guard `band(a, b)` registered with both false skips the write that sets b, whose test reads a's frozen false value, and then the write that sets a, whose test reads b's, so its wake is lost ([hard cases](../../../research/investigations/guard-fairness/DESIGN.md#2-hard-cases)).
- Age-bounded turns granted in bulk: rejected because the N = 50 probe measured 40.2-47.8 ms maximum waits against approximately 3.3 ms bounds and 10.34-10.49 times baseline runtime; every write still wakes all watchers, and a turn spent before guard evaluation can end in another false retry ([measured results and attribution limits](../../../research/investigations/guard-fairness/DESIGN.md#age-bounded-turns-results)).
- Strict turns on every guard wake: rejected because firn's limiter-script engine lost 7.5 times throughput at 8 connections and 47 times at 50, while p99 at 50 rose from about 1.6 ms to about 52 ms ([engine comparison](../../../research/investigations/guard-fairness/DESIGN.md#result-on-firns-engine-turns-are-far-worse)); the subsequent age-bounded candidate also failed its probe criteria.
- A table with header entries taken at its first use in the block: rejected because the take reads the keys' bytes and key sets, and a block that wrote a key's bytes before that use had the take lock the entry under the bytes it wrote, and one that released them had the take read released memory, which an adversarial program met as a fault; refusing every write and release of a key's storage inside the block was the other repair, and it would refuse blocks the language admits for a lowering's timing.
- A table replaced by storing the new table's address, the old table freed when the write releases it: rejected because a statement that read the address before the write waits at the old table's gate and then locks its entries, which `map_resets.wf` would answer with entries that no longer reach the state.
- A twin of a statement's block, its counted loops, matches and key computations, run before the hold to collect the keys the block reaches (the replaced node compiler/waiting-contexts/held-keys): rejected because a statement now names its entries in its header, so its keys are values when it begins and nothing need run early.
- Always materializing a borrowed table entry: rejected because a borrow under a read-only whole-map hold permits concurrent readers, so materializing cells or changing its hold descriptors would mutate shared storage without exclusion.
- Making table hold descriptors thread-safe for concurrent readers: rejected because a read needs only the stable index and immutable `None`, so synchronized descriptor mutation adds coordination to an operation that requires none.
- Replaced state-field lock layout: rejected because each map is now an object of its own and targets directly determine the holds.
- Replaced grant-based acquisition: rejected because several objects require a global type and identity order.
- Local-table pending holds: rejected because TYPE-9 admits maps only as shared-object states.
- Replacing a map by assigning a map value: rejected because TYPE-9 admits no such expression; map swap is the exchange.
