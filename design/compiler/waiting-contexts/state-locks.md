Decision: A shared state's lock units are each of its keyed-table fields, or the state itself when it is a table, whose entries are locked by key or the table whole, and one unit for all its other fields, ordered by the declaration order of their first fields, because the layout then follows from the state's declaration alone, which every module lowering a statement on that state reads alike, and the fields statements change together keep one lock as the object did, instead of a lock for each field, under which a block touching every field takes several locks where it took one; a finer layout chosen from how blocks use the fields may use the whole program, because an entry's composition lowers its whole closure (compiler/incremental-compilation), and must follow from the declaration alone again if composition stops doing so ([layout](../../../research/investigations/shared-state/DESIGN.md#the-layout-is-chosen-in-lowering)).

Decision: Lowering takes each unit the header grants and the guard or block reaches before the first use of it, a table whole from its whole binding and by its entries from its entry bindings, a unit before every later one, the units its guard reads before the guard, and each table with header entries before the guard and the block, that table's header entries in one step, sorted and without repeats, because every wait is then for a lock that comes after every lock the waiter holds, so no cycle of waits forms, and because a table's take reads its header keys' bytes and key sets, which the statement reads when it begins [SHARE-2] and which its block may write or release, while a unit reached only on a conditional tail, firn's log after a key's entry, is taken only on the path that reaches it ([locking](../../../research/investigations/shared-state/DESIGN.md#locking-order-taking-and-release)), instead of taking every unit at the statement's start, which would hold the log through every logged write's whole block, or taking a table with header entries at its first use, where a block that first wrote or released a key's bytes had the take read what it wrote or released.

Decision: A statement releases every unit it took when its block ends by any edge, because every taking then precedes every release, which is two-phase locking, so each execution equals one in which the statements on a state run one after another, each with the whole state to itself, instead of releasing a unit once the block no longer uses it, which two-phase locking also allows after the last taking and which waits for a workload whose holds show it to matter.

Decision: A statement whose guard reads false registers a watch, kept in its frame, on each unit the guard read while it still holds the unit, then releases every unit it took and parks, every write to an entry waking the watches of that entry's whole table, because a write that takes such a unit after the release finds the watch, so no wake is lost, and how often a guard is evaluated is not observable [SHARE-3], so a wake that finds the guard still false costs time and never correctness, instead of a list of watchers for each entry, which must survive the table's moves to larger tables and waits for a program whose blocking pops show the cost.

Decision: An entry the statement's guard reads is locked alone, never read beside other readers, because a shared read of an absent key holds no cell, so an insert of that key could end before the guard's watch exists and the guard would wait for a write that already happened, instead of registering the watch before the guard's first evaluation, which every statement with a guard would pay for whether it waits or not.

Decision: A write over a table, or a `swap` of tables, exchanges the tables' entries and leaves each table where it is, so the address a state stores for a table never changes, because a statement on another unit of the state reads that address before it takes the table's lock, and a table replaced by its address would let such a statement lock entries of a table no longer the state's, instead of storing the new table's address under the old table's whole lock, which a statement that read the old address has already passed.

Decision: Under a whole hold a read of an absent key reads a shared `None` and allocates nothing, a write materializes the key's cell, and a cell left `None` is given back when the hold is released, as the header's keys are, because a block that probes many keys and writes few would otherwise fill the table with empty cells, instead of materializing on every read or keeping empty cells until the table is released.

Decision: Local table writes retain their selected cells in the table's pending hold until replacement, release or publication as shared state, publication settling that hold before another context can reach the table, because borrowed entries must survive further selections and index growth, and local writes left `None` must not become persistent entries, instead of freeing an empty cell at each selection, which invalidates a still-live entries reference, or letting the first shared acquisition settle a local hold, which races when two contexts acquire different entries first.

Decision: A keyed-table borrow materializes its selection only when its root may be written: owned local storage, a parameter path the row writes or an ancestor of such a path, or an atomic binding its statement writes through; otherwise selection reads the stable index and an absent key's shared immutable `None`, changing neither the table nor its shared hold records, because readers under a shared outer entry hold may run concurrently and must not mutate the nested table, instead of always materializing on borrow or making hold descriptors thread-safe for concurrent readers. The checker retains the formation's current write permission and atomic sources; lowering refines those sources from the completed statement, and a read selection over a key set uses a private frame descriptor rather than a table hold.

Rejected:
- A table with header entries taken at its first use in the block: rejected because the take reads the keys' bytes and key sets, and a block that wrote a key's bytes before that use had the take lock the entry under the bytes it wrote, and one that released them had the take read released memory, which an adversarial program met as a fault; refusing every write and release of a key's storage inside the block was the other repair, and it would refuse blocks the language admits for a lowering's timing.
- A table replaced by storing the new table's address, the old table freed when the write releases it: rejected because a statement that read the address before the write waits at the old table's gate and then locks its entries, which `keyed_table_resets.wf` would answer with entries that no longer reach the state.
- A twin of a statement's block, its counted loops, matches and key computations, run before the hold to collect the keys the block reaches (the replaced node compiler/waiting-contexts/held-keys): rejected because a statement now names its entries in its header, so its keys are values when it begins and nothing need run early.
- Always materializing a borrowed table entry: rejected because a borrow under a shared outer entry hold permits concurrent readers, so materializing cells or changing the nested table's hold descriptors would mutate shared storage without exclusion.
- Making table hold descriptors thread-safe for concurrent readers: rejected because a read needs only the stable index and immutable `None`, so synchronized descriptor mutation adds coordination to an operation that requires none.
