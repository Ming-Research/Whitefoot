Decision: A pool that `WF_IO_HELPERS` pins grows by one helper when none is free to take an operation with a deadline or a real cancellation watch, and the waiting thread of a pool pinned at zero leaves such an operation to that helper, because [PRE-2] produces the operation's outcome once its deadline is reached, which the thread inside the operation cannot bring about, instead of keeping the pinned count exactly, under which a pool pinned at zero ran the operation on the waiting thread and waited past the deadline.

Decision: A watched wait uses the per-driver list of the [context-cancellation decision](../../language/system-interface/context-cancellation.md), selects its completion reason on the owning driver, and stores that reason in the native record's file-open diagnostic word, because file opens take no cancellation watch so the request kinds are disjoint and the existing 160-byte record and helper/ring cancellation marker suffice, instead of enlarging every record or reserving a second monotonic-clock value for cancellation.

Decision: A real watch routes a pending socket accept, receive or send through the native ring or a helper that observes its bound rather than the driver's descriptor-only readiness poll, because the driver's wake epoch lets it request cancellation on those routes and Windows helper socket waits recheck that request between polls capped at 50 ms, while the driver's descriptor-only readiness poll cannot observe a firing, instead of leaving a fired source waiting for unrelated socket readiness; a never watch takes the ordinary route after one pointer comparison ([prototype mechanism](../../../research/investigations/context-cancellation/README.md#the-mechanism-under-every-shape)).

Rejected:
- One timer thread for the whole program: rejected because every expiry would cross to the driver that owns the waiting context, whose own loop already wakes at the earliest instant it is given while it runs no context, and an idle driver's borrow services the deadlines of one that is running a context; a single driver whose thread computes is the open case the driver-handoff work addresses ([study](../../../research/investigations/driver-handoff/DESIGN.md)).
- A linked timeout on each ring entry: rejected because the readiness and helper routes need the driver's bound anyway, so the ring would carry a second mechanism for the same deadline.
- Polling for readiness before each blocking helper call: rejected because a standard stream shared with other processes can be ready at the poll and empty at the call, which then blocks past the deadline.
- Keeping a pinned helper count exact for an operation with a deadline: rejected because a pool pinned at zero then runs the operation on the thread that must end it, which waits past the deadline [PRE-2] rules out.
- An idle driver reaping a computing driver's ring during its borrow: rejected because it adds a second server for ring work, with ring entry and host calls under the borrowed token and a publication path that wakes contexts on the borrowed driver, and still leaves whole-role reassignment to serve the ring when every driver computes ([study](../../../research/investigations/ring-assist/DESIGN.md#a-the-borrowing-idle-driver-also-reaps-the-busy-ring)).
- A shared reaper thread for every driver's ring: rejected because every completion would then cross threads and lose the wake by the record's address on the publishing driver, which took the compiled server from 0.64 to 0.94 of the hand-written shape at 64 connections ([study](../../../research/investigations/ring-assist/DESIGN.md#b-completions-reaped-by-a-thread-other-than-the-submitting-driver)).
- Judging a driver stale by the time since it last reaped its ring: rejected because a loaded driver reaps only once every 64 resumptions, so 64 ordinary runs of 20 to 50 microseconds leave 1.3 to 3 ms between reaps with completions nearly always pending, and the trigger would fire throughout ordinary I/O ([study](../../../research/investigations/ring-assist/DESIGN.md#5-recommendation)).
