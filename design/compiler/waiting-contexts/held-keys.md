Decision: The keys a statement holding a map's state will reach are computed by a twin of its block, the counted loops and matches that contain a statement on an entry, the `let`s their keys, bounds and scrutinees read, and each such statement with an empty block, which lowering runs before the hold through the ordinary lowering of statements, because the twin then follows the block's own matches over the block's own values and collects at least the keys the block reaches, and the runtime stops a program whose block reaches a key the twin did not collect ([holding only the entries](../../../research/investigations/concurrent-map/DESIGN.md#holding-only-the-entries-a-statement-reaches)), instead of running the block twice, which a block that runs once forbids, or locking each entry as the block reaches it.

Decision: A twin is answered only when the block names the held state solely as an entry's target, no edge leaves the block, no general loop contains an entry statement, and nothing a kept expression reads is written, released, consumed or addressed in the block or written by the function's row, and every other statement holds the whole map, because each condition errs toward holding more, which is always correct, and the conditions are decided from the checked statements alone, instead of a general slice of the block with its own account of what each statement may change.

Decision: A kept expression owes nothing the twin might lack: its integer operations and conversions answer for every operand, its calls have no `requires` and reach no function without a body other than a pure one, and a range it forms is narrowed to its source's bounds when the twin is lowered, because the twin drops the block's statements that reach no entry and with them the guards those obligations were proved under, a branch that leaves by `give` or never returns, so that a key formed after such a guard was formed out of bounds and a call that read the wall clock answered differently the second time, while narrowing changes nothing wherever the block itself forms the range, instead of keeping every statement a kept expression's proof depends on, which the checked program does not record.

Decision: A kept call is not evaluated before an object statement that precedes it in the block, because a call that never returns would otherwise stop the statement before that object statement's effect, which the block would have made, instead of leaving the order of a hang and an effect to the twin.
