Decision: On the supported hosted targets an atomic-value operation forces every remaining ordinary target group to be acquired, then performs its sequentially consistent operation before any group releases, because the operation's instant is a valid effect point for all the statement's writes only within that interval, instead of leaving a later target group to be acquired after the operation ([placement proof](../../../../research/investigations/sequence-take/DESIGN.md#33-what-a-fetch-and-add-inside-the-hold-is-consistent-with)).

Decision: Atomic-value targets use no state lock on the supported hardware-atomic targets and a path without an operation performs no access to their state word, while statements without such a target retain their existing lowering, because the checked one-operation rule licenses the lock-free operation and conditional logging must pay for the shared word only when used, instead of acquiring the atomic value as an ordinary target or adding accounting to every statement ([lowering scope](../../../../research/investigations/sequence-take/DESIGN.md#56-v-a-shared-atomic-value-held-by-an-atomic-statement-without-exclusion-recommended)).

Decision: A statement whose only targets are atomic values performs the existing local wait-pass check before any target is acquired, then its operation uses one atomic instruction without a state lock on supported hardware-atomic targets, because immediately answered waits must yield to ready contexts under WAIT-2 using the ordinary acquisition path's counter, threshold, driver token and suspension point, instead of omitting progress accounting or introducing another scheduling policy ([scheduling boundary](../../../../research/investigations/sequence-take/DESIGN.md#scheduling-progress-at-the-direct-statement-boundary)).

Decision: The atomic word occupies the state in the ordinary shared allocation, and handle retention follows the existing proved-handle-lifetime rule at the parent waiting-contexts node, because an unchanged handle place keeps the object alive without a count update while a block allowed to release that handle must preserve the state through its exit, instead of a separate allocation or dropping necessary lifetime protection ([lifetime boundary](../../../../research/investigations/sequence-take/DESIGN.md#integration-boundaries-found-in-the-current-base)).

Decision: Addition uses one fetch-and-add and a saturation store on the full path, loads clamp the raw word and raises clamp their returned old value to 2^63, because at most 128 hosted executors can each have one increment of at most 2^32 awaiting its clamp so the representation never wraps and every observable value stays in the specified domain, instead of a compare-and-swap addition loop or exposing a transient value above saturation ([representation bound](../../../../research/investigations/sequence-take/DESIGN.md#integration-boundaries-found-in-the-current-base)).

Decision: An ordinary-access lowering of an atomic value is selected only by a target guaranteeing one execution thread, never by the invocation's driver count, because a hosted one-driver configuration can still have two executing threads and the source already declares a waiting atomic statement, instead of treating the driver count as an atomic capability ([target boundary](../../../../research/investigations/sequence-take/DESIGN.md#integration-boundaries-found-in-the-current-base)).
