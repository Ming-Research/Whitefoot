Decision: Emit a loop whose header ends in a `match` over a nominal enum, whose other blocks are entered only from that header and leave only by returning or by jumping back to it, as an enclosing function that calls a dispatch function once and returns its result, plus one function per arm; every edge back to the header becomes a guaranteed tail call of the dispatch function, which computes the header and transfers to the selected arm through a per-loop handler table indexed by the tag, because the [E0 measurement](../../research/experiments/match-dispatch/RESULTS.md#verdicts-under-the-recorded-criteria) put per-opcode functions chained by tail calls 15-21% below one function with one switch in the forms Whitefoot can express, the gain coming from register allocation within each arm, and the guaranteed self-tail transfer already reaches the backend as exactly this loop; the split concerns a loop, whichever source spelling produced it, and leaves compiler/self-tail-lowering's refusal of LLVM `musttail` for self recursion in place, since the parts are distinct functions whose transfers need the inter-function convention a self transfer does not, instead of keeping one function with one switch, threading the dispatch through computed goto inside one function, which measured no better than the switch once a checked interpreter's state is live, or requiring a source marker for an interpreter loop.

Decision: Every part takes one parameter list in one order, the destination of a result returned through memory, the header's register-carried parameters, the header values the arms read, the register values from before the loop that the loop reads and the frame pointer, and the dispatch function is always inlined, because a guaranteed tail call requires identical prototypes and inlining the dispatch function into each arm gives every arm its own indirect transfer, instead of per-part prototypes or one shared out-of-line dispatcher.

Decision: The parts use the calling convention without callee-saved registers where a build-time probe finds that the assembler `whitefootc` runs accepts it with a guaranteed tail call, and the C convention otherwise; when the parts' parameters need more argument registers than the convention can pass through the parts' own transfer, a guaranteed tail call through a table-loaded address, on the target, as [measured](../../research/experiments/match-dispatch/RESULTS.md#argument-registers) with clang 19 and 20, which leaves 11 of `preserve_none`'s 12 integer argument registers on x86-64 outside Windows because the loaded address needs one, the values the loop cannot change (values from before the loop, hoisted values and passed-through header parameters) move into slots of the enclosing frame, the ones the fewest arms read first, an arm reading a value also through a projection that emission replaces by it or a pin slot that holds it, which the enclosing function stores before the loop and each part loads, while a hoisted value or one from before the loop that no part reads is no part's parameter; a loop that still does not fit, or whose parts would take a parameter of another kind than a pointer, an integer, a float or a range's pointer and count, is emitted whole; and the handler table's address is a further parameter where a register is left for it, because the convention keeps the passed values in registers without saving them in every part but LLVM 18, still a supported host compiler, lacks it, [E0](../../research/experiments/match-dispatch/RESULTS.md#verdicts-under-the-recorded-criteria) measured a part passing one parameter on the stack 8% slower and two 43% slower, worse than the whole-function switch, while a value that never changes costs only a load where it is read, a cost not yet measured on a loop that needs the frame, and the table address formed in every arm cost two instructions per dispatch, which on the measured core issued in the dispatch's slack (a cycle-neutral, 10% instruction-count change), instead of requiring an LLVM with the convention, passing the excess on the stack, spilling values that change on every dispatch, or forming the table's address in each arm.

Decision: The enclosing function owns the frame and passes it to every part, and a frame slot that exactly one part uses and the enclosing function never uses is that part's own allocation while a frame address the loop reads is derived again in every part, because storage a value keeps across parts must outlive them in the enclosing activation, while a part's own temporary left in the shared frame cannot be removed by the host: the `match` scrutinee's copy then cost a stored and reloaded cell on every dispatch and made the WF interpreter's loop kernel 12% slower than whole-function emission in a single probe launch, while with that slot part-local the kernel [measured 15% faster](../../research/experiments/match-dispatch/RESULTS.md#stage-2-the-whitefoot-interpreter-under-the-compilers-lowering), instead of passing each slot pointer separately or sharing every slot.

Decision: Provisionally, a function is emitted whole when it waits, is a recursion-budget variant or a sequential clone, has overlap groups, is compiler-synthesized, or has a context or shared-record prelude, and the handler table holds function addresses indexed by the dense tag, because no current consumer needs those forms split and each needs its own frame or prelude treatment, and the [E0 criterion](../../research/investigations/match-dispatch/DESIGN.md#e0-lowering-shapes-in-c) for storing a handler offset in place of the tag was not met; reopen the first when a consumer's dispatch loop has such a form and the second when the wasm interpreter measures the handler offset again.

Decision: When the loop is entered by one edge, the enclosing function computes once, and passes to the parts, what the loop cannot change: a read-only reference parameter, read in the header directly or through a header parameter that every back edge passes through unchanged, looking through joins whose incoming values are all one value, and that the entering edge sets to it, has the header's box-referent projections and container measures through it computed before the loop, an arm's projection of the same box naming the hoisted one; a passed-through reference that the loop uses only to project its box's referent, to hand on unchanged to itself, or to hand to callees that cannot replace its box (below), has that projection computed once; a passed-through parameter left with no other use is no part's parameter, a join that still names it receiving a frozen poison value it never reads; and a parameter holding the same pointer as a function parameter carries that parameter's checked reference facts, because a read-only reference's referent and a box the loop never replaces cannot change during the call [EFF-2, EFF-5] while the parts, being separate functions, reloaded them on every dispatch where the whole-function loop had them hoisted, and removing those reloads brought the WF interpreter to [1.00-1.13x of the C tail-call form](../../research/experiments/match-dispatch/RESULTS.md#stage-2-the-whitefoot-interpreter-under-the-compilers-lowering), instead of leaving loop-invariant loads in every part, which the host cannot move across the parts, or passing every reference whatever the loop still reads of it.

Decision: A passed-through reference whose box the loop keeps stays pinned when the loop also hands it to non-waiting callees whose every declared write lies below that box's content, each part then handing such a callee a slot of its own that holds the hoisted projection, because such a callee cannot replace the box [EFF-1, EFF-5] and a reference does not outlive its call [REF-3], while the stage-3 wasm interpreter, whose handlers must live in helper functions, otherwise reloaded the stack box's pointer on every dispatch, a dependent load among the eighteen instructions its `I32Add` handler executes, whose removal [raised its CoreMark score 3.8%](../../research/experiments/match-dispatch/RESULTS.md#v2d-the-stack-box-kept-across-helper-calls), instead of refusing to pin a reference handed to any callee or reading callees' bodies, which would make the lowering depend on implementations rather than checked boundaries.

Decision: When the header's `match` reads the element a register-carried header parameter indexes in a `Slots` run reached by an address the loop cannot change, and the arms read that element through its address, the parts carry the element's address beside the index in the parameter that held it as a header value: the enclosing function forms it from the entering index; an edge back to the header whose index is the received index plus a constant, seen through joins whose every incoming value is the index, passes the received address moved by that many elements; every other edge forms the address from the run, as the header did, so the parts receive the run's address only where an arm has such an edge; and the header uses the address it receives, because the header formed the next element's address from the next index with a move, a shift and two additions on x86-64 that the moved address replaces, which on the stage-3 wasm interpreter [raised the CoreMark score 13.0% on the 14900K](../../research/experiments/match-dispatch/RESULTS.md#a-and-b-on-the-14900k), while an edge whose step the lowering cannot see gains nothing from the received address, and forming those edges' addresses from the run [returned Halo's Lua interpreter to its times before the cursor, with CoreMark 2.4% above moving the address on every edge](../../research/experiments/match-dispatch/RESULTS.md#edges-by-their-step), instead of forming the element's address from the index in the header, carrying the address in place of the index, or moving the received address by the index's change on every edge.

Decision: `whitefootc --dispatch-ledger` prints, for every loop around a `match` over a nominal enum other than one inside the loop of an earlier such `match`, whether it was split and otherwise the first condition it failed, read from comment lines the emitter places in the module, because a writer who wants the split cannot otherwise tell a near miss, such as a bounds test placed before the `match`, from success, while whether a loop splits depends on the target and the toolchain, instead of a source marker that rejects an unsplit loop, which would make acceptance depend on the host, or a notice printed on every build, which Whitefoot's diagnostics, reserved for rejections, have no place for.

Rejected:
- One function with one `switch` for an interpreter loop: rejected because E0 measured it 15-21% slower than per-opcode functions in the forms Whitefoot can express.
- Computed goto within one function: rejected because it matched per-opcode functions only in an unchecked form with little live state and fell back to the switch's cost with a checked interpreter's state.
- Addressing an element whose offset is a checked sum of a value the part has from its entry and another value from a pointer to the entry value's element, which the part's prelude derives once: rejected because on the stage-3 wasm interpreter with an accumulator register it cut retired instructions 3.3% but [raised the CoreMark score 0.9%](../../research/experiments/match-dispatch/RESULTS.md#frame-slots-addressed-from-a-derived-pointer), below the 2% criterion set for it, so it is not adopted now; the branch `claude/derived-addresses` keeps the implementation, and the question reopens when another interpreter, such as Halo's `regs[base + a]` frames, or an x86-64 measurement shows a gain of at least 2%.
- Carrying the matched element's address in place of the index, each part recovering the index from it and a comparison of the index moved by one element with the run's length becoming a comparison of the moved address with the run's end address, which the parts receive: rejected because on the 14900K it [scored 1.6% below the address beside the index](../../research/experiments/match-dispatch/RESULTS.md#a-and-b-on-the-14900k), below it in every pair: the end address takes the index's register, a branch arm recovers the index on every dispatch, and a sequential arm saves one instruction; the branch `claude/stage3-cursor-instead` keeps the implementation.
- Moving the received address by the index's change on every edge back to the header: rejected because on Halo's Lua interpreter, whose arms take the next index from helpers, it made the `loop` kernel [5.7% slower](../../research/experiments/match-dispatch/RESULTS.md#the-register-pressure-candidate-and-the-code-cursor-on-halo) than forming the address from the run: a subtraction more on each such edge, with nothing saved.
- A source marker requiring the split: rejected because whether a loop splits depends on the target's argument registers and the toolchain's conventions, so the same program would be accepted on one host and rejected on another.
