Decision: Emit a loop whose header ends in a `match` over a nominal enum, whose other blocks are entered only from that header and leave only by returning or by jumping back to it, as an enclosing function that calls a dispatch function once and returns its result, plus one function per arm; every edge back to the header becomes a guaranteed tail call of the dispatch function, which computes the header and transfers to the selected arm through a per-loop handler table indexed by the tag, because the [E0 measurement](../../research/experiments/match-dispatch/RESULTS.md#verdicts-under-the-recorded-criteria) put per-opcode functions chained by tail calls 15-21% below one function with one switch in the forms Whitefoot can express, the gain coming from register allocation within each arm, and the guaranteed self-tail transfer already reaches the backend as exactly this loop, instead of keeping one function with one switch, threading the dispatch through computed goto inside one function, which measured no better than the switch once a checked interpreter's state is live, or requiring a source marker for an interpreter loop.

Decision: Every part takes one parameter list in one order, the destination of a result returned through memory, the header's register-carried parameters, the header values the arms read, the register values from before the loop that the loop reads and the frame pointer, under the calling convention without callee-saved registers, and the dispatch function is always inlined, because a guaranteed tail call requires identical prototypes, the convention keeps the passed values in registers across the chain instead of saving them in every part, and inlining the dispatch function into each arm gives every arm its own indirect transfer, instead of per-part prototypes, the C convention, which [E0](../../research/experiments/match-dispatch/RESULTS.md#verdicts-under-the-recorded-criteria) measured 8% slower with one parameter beyond the argument registers and 43% slower with two, or one shared out-of-line dispatcher.

Decision: The enclosing function owns the frame and passes it to every part, and a frame slot that exactly one part uses and the enclosing function never uses is that part's own allocation, because storage a value keeps across parts must outlive them in the enclosing activation, while a part's own temporary left in the shared frame cannot be removed by the host: the `match` scrutinee's copy then cost a stored and reloaded cell on every dispatch and made the WF interpreter's loop kernel 12% slower than whole-function emission in a probe, while with that slot part-local the kernel [measured 15% faster](../../research/experiments/match-dispatch/RESULTS.md#stage-2-the-whitefoot-interpreter-under-the-compilers-lowering), instead of passing each slot pointer separately or sharing every slot.

Decision: Provisionally, a function is emitted whole when it waits, is a recursion-budget variant or a sequential clone, has overlap groups, is compiler-synthesized, or has a context or shared-record prelude, and the handler table holds function addresses indexed by the dense tag, because no current consumer needs those forms split and each needs its own frame or prelude treatment, and the [E0 criterion](../../research/investigations/match-dispatch/DESIGN.md#e0-lowering-shapes-in-c) for storing a handler offset in place of the tag was not met; reopen the first when a consumer's dispatch loop has such a form and the second when the wasm interpreter measures the handler offset again.

Rejected:
- One function with one `switch` for an interpreter loop: rejected because E0 measured it 15-21% slower than per-opcode functions in the forms Whitefoot can express.
- Computed goto within one function: rejected because it matched per-opcode functions only in an unchecked form with little live state and fell back to the switch's cost with a checked interpreter's state.
