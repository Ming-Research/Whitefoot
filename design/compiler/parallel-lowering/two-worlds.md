Decision: A --par module has overlapped and byte-identical sequential lowerings for the entry-reachable functions that can reach a handed-out call, with the default world chosen once at bootstrap by whether a pool was requested and neither world calling into the other, because joining a handed-out result removes tail position and can prevent tail-recursion elimination, instead of one lowering with a per-task demand switch.

Decision: The clone set is the functions reachable from the entry that can reach a hand-out, derived from the call graph and the permission table, because only those functions have a lowering that differs between the two worlds, instead of cloning every function or marking clones by name.

Decision: `--par-sequential-refusal` enters the callee's existing sequential clone when a compute offer is refused, keeping the ordinary signatures, joins, and result ABI, adding no hidden parameters or runtime depth counters, and declining the compute offers beneath the clone it enters, because refusal reuses the failed-acquisition edge every offer already has and so adds none of the per-task demand query whose contention cost was rejected, instead of a runtime demand signal read on each call.

Decision: Under --par, each ordinary cyclic call-graph component gets one budget variant per member behind its ordinary signature and result ABI; each call entering the component obtains its initial budget once, intra-component calls and callbacks decrement it, and exhaustion enters the sequential clone, because the [recursion-budget comparison](https://github.com/mbbill/Whitefoot/blob/b3341e32ab8d69e2974227aee7146ac16eb2fe00/research/investigations/compute-runtime/RESULTS.md#recursion-budget-comparison) supports a single compare and branch per node above the cut with none below, instead of N cloned parallel levels or a global nesting bound. Components with a synthesized loop, a waiting member or no sequential clone are excluded with a --par-ledger reason and make the offers they reach without a budget; this is offer selection after checking. A waiting member is excluded because it is a resumable frame entered by a transfer, with no ordinary signature for a variant to stand behind.

Decision: The initial recursion budget is floor(log2(64 times the lane count)) capped at 24, using one lane without a pool and zero from a scheduler-less weak stub; --par-recursive-frontier auto|N|off selects that default, a fixed N in 1..32, or no variant family, because the [depth and width comparison](https://github.com/mbbill/Whitefoot/blob/b3341e32ab8d69e2974227aee7146ac16eb2fe00/research/investigations/compute-runtime/RESULTS.md#recursion-budget-comparison) finds that the best fixed depth changes with worker width, instead of one compile-time depth for all pools.

Decision: A handed-out call claims its lane before constructing a lane-owned frame, leaving no frame on refusal, because caller-entry allocation charges every recursive activation for an offer it may not make and can exhaust the caller's stack, instead of placing task frames in the caller's activation.

Decision: A synthesized range split snapshots the thin pointer value of a promoted `Box` owner into its splitter and chunk frames and reconstructs only borrowed local owner storage inside the chunk, while inline affine aggregates retain their addressed capture and the source scope remains the sole owner responsible for return or release, because PAR-2 has already excluded whole-owner replacement and consumption across independent iterations and carrying the parent owner-slot address made every worker repeatedly reload live caller-stack storage in the records kernel that regressed at both measured parallel widths, instead of copying inline affine aggregates, duplicating cleanup authority, or carrying the parent owner-slot address through every task.

Decision: For promoted `Box<Array<T>>` captures only, provisionally refine the preceding pointer snapshot into a distinct borrowed element-base pointer and reconstruct the original allocation-base pointer at chunk entry using the target-derived header offset, preserving one-word frames and source-owned cleanup, because the [completed compiler experiment](https://github.com/mbbill/Whitefoot/blob/b3341e32ab8d69e2974227aee7146ac16eb2fe00/research/investigations/access-effects/parallel-array-captures.md#general-compiler-candidate-and-result) met its prospectively fixed correctness, hosted-CI and three-width performance criterion while retaining a null-control suspect and byte-identical optimized record chunks that leave causality unresolved, so the evidence supports this bounded capture family without changing the source Box ABI or claiming a general storage-layout result, instead of globally changing Box representation, carrying an additional pointer, or adding a larger use-directed projection pass.

Decision: Rescue a synthesized loop whose original capture frame exceeds the fixed lane-frame bound by selecting captures from runtime uses in its completed chunk, tracing block-parameter forwarding backward from ordinary instructions, calls, cleanup and returns, because the sparse-frontier receiver is independently permitted yet its complete scope needs 352 bytes against the existing 256-byte bound; retaining only needed inputs can admit that useful map while preserving the established interface and helper order of already-fitting loops, instead of changing every fitting task's transport and code placement, enlarging every lane frame, asking writers to outline phase helpers, or reconstructing source effects in a second analysis. Generated capture reconstruction is a dependency rather than a use; unused forwarding and reconstruction may disappear without deleting source operations or changing ownership. Preserve value identities while allocating aggregate storage only for definitions still present in the existing flow graph, because removed capture definitions retain type metadata but need no backing. [The capture investigation](../../../research/investigations/compute-model/DESIGN.md#needed-loop-captures) records the consumer, the repeated fitting-records performance signal, the bounded policy and its qualification criteria.

Decision: Reuse an oversized loop candidate by transferring its completed ordinary CFG into the parent, preserving nested synthesis and remapping runtime and scheduling metadata while rebinding generated capture roots to the original storage, because discarding and rebuilding nested refused candidates repeats construction exponentially and an ordinary helper call would add runtime overhead to refusal, instead of retrying source lowering, caching context-dependent refusal decisions, or outlining the fallback behind a new call. Originally wide frames reserve their enclosing helpers only after the reduced frame fits, avoiding discarded reservations and a function-ordinal relocation pass.

Decision: After needed-capture selection, rescue a synthesized range split whose conservative estimate still exceeds the lane bound when the shared selected-target calculation proves its transported signature fits, because a used small aggregate can otherwise be charged the entire slot despite its fitting representation in the [target-fitting investigation](../../../research/investigations/compute-model/DESIGN.md#selected-target-loop-frame-fitting), instead of duplicating layout arithmetic or enlarging every lane. Preserve the existing path for conservatively fitting frames and reuse the completed ordinary CFG once on a real refusal, because exact fitting must not change their capture interfaces or add splitter overhead to fallback.

Rejected:
- A per-task demand signal selecting a sequential subtree: rejected because its contended read-modify-writes charge fine-grain calls for a scheduling query, whereas bootstrap selection runs once per process.
- N private layers of parallel functions before sequential clones: rejected because the measured best depth varies with worker width and the [budget variant](https://github.com/mbbill/Whitefoot/blob/b3341e32ab8d69e2974227aee7146ac16eb2fe00/research/investigations/compute-runtime/RESULTS.md#recursion-budget-comparison) reaches the cut without N copies of each body.
- A general capture projection or interprocedural dead-argument optimizer: rejected because following existing runtime operands removes the demonstrated lexical-scope obstruction without introducing new storage representation or source-call semantics.
- Replacing unused value types with tombstones or renumbering the complete chunk: rejected because the existing flow graph identifies actual definitions while preserving stable value identities and storage for every remaining ordinary definition, even when unused.
- Accepting every candidate and leaving refusal to the emitter: rejected because a truly oversized loop would retain recursive splitting despite being unable to hand out work.
- Deciding exact fit before needed-capture selection: rejected because that changes the existing rescue policy's transport and helper order without serving the demonstrated post-pruning obstruction.
- A budget-carrying frame variant for a waiting component, whose ramp takes the budget and transfers into the sequential clone once it is spent: rejected because it needs a second resumable-frame signature and a spent-budget transfer to bound an offer depth that no measurement has asked for, while the offers such a recursion reaches are ordinary calls that join inside the ordinary function making them; reconsider when a measured waiting recursion shows offer cost at depth.
- Withdrawing the offers a waiting recursion reaches: rejected because they are permitted ordinary calls whose lane frames fit and whose joins complete inside the ordinary function that makes them, so the caller's frame form gives no ground to refuse them.
- Excluding only components with a synthesized loop or no sequential clone: rejected because a waiting recursion that reaches an offer meets both conditions and was selected for a family the emitter cannot build, which stopped every --par build of such a program, `tests/programs/wfgrep.wf` among them, with an invalid-IR backend failure.
