Decision: LLVM emission builds a structured module of function headers, blocks, entry allocations, attributes, named type definitions and their transitive dependencies, attribute-group uses, symbol definitions and references before rendering text, recording each emitted block's actual exit label and deriving link fragments from that same model, because the [current emitter](../../research/investigations/compiler-architecture/DESIGN.md#p42-structured-emission) predicts split blocks separately from their construction, patches finished text and parses it again to recover ownership and dependencies, instead of byte-offset insertion, a second exit-label classifier or reparsing the compiler's own LLVM. Textual LLVM remains the output and fragment ownership, ABI, target qualification and deterministic output order remain unchanged.

Decision: Integer match has an explicit typed IR switch terminator carrying mathematical constant targets and an optional remaining target, and emission uses one LLVM switch over the once-evaluated scrutinee, because its constants are sparse values of the source integer width rather than enum ordinals and complete coverage needs only an unreachable default, instead of an equality-test chain or reinterpretation as an enum discriminant.

Decision: Identical external declarations share one structured module declaration during registration and composition, while inconsistent declarations stop emission, because independent function builders can reach the same runtime ABI and fragments must retain its one authoritative declaration, instead of printing duplicates, overwriting conflicting signatures or filtering rendered LLVM text.

Decision: Compose canonical computation into a --par module from recorded entity and dependency graphs with explicit symbol renaming, typed declarations, aliases, globals, attributes and collision checks, retaining address-only handler roots and shared runtime override identities, because [the canonical emission analysis](https://github.com/Ming-Research/Whitefoot/blob/73aaab85a92479ada6bf57fa996e17b163e019ed/research/investigations/par-demand/DESIGN.md#canonical-sequential-lowering-before-loop-synthesis) requires the ordinary emitter's complete dependency closure and the [handler mechanism](../../research/investigations/par-default/DESIGN.md#handler-mechanism) binds constructors to final renamed arm identities, instead of discovering dependencies by reparsing LLVM text, cloning only function bodies or merging same-named mutable state from different worlds.

Rejected:
- Adopting an LLVM library as part of this change: rejected because the missing contract is between this compiler's emission and fragment construction, and an external IR dependency adds integration work without being required to record it.
- A second optimization IR in the emitter: rejected because lowering already owns the typed control-flow graph; the emission model only records the target structure and dependencies needed for correct printing and partitioning.
- Treating stored handler addresses as absent from computation reachability: rejected because a split-world constructor can be the only root of a canonical dispatch family, so call-edge-only import can omit a live code target.
