Decision: The trusted base's termination on heap exhaustion [STOR-8] and this compiler's own termination on stack exhaustion write one fixed record naming only the exhausted resource class and no source construct, rule, function, address, depth, or size, with neither its bytes nor the exit status fixed by the language, while an unavailable compute worker or task slot is a refused offer and never an exhausted resource, because the absence of those fields is what distinguishes the record from a language trap record, and because the heap half of the old decision is now the language's own, allocation being total in the source and its exhaustion terminating the program from the trusted base outside the language, which leaves this node the record's fields, the stack half, and the boundary against refused offers, instead of a language-level trap or a record whose fields a reader could take for a proof failure.

Decision: The entry runs on a stack the runtime sizes, every generated function carries the selected backend's stack-probing attribute, and a fault below a thread's stack keeps the host's own disposition, because native probing contains guard-crossing frames without a software stack-limit check in every prologue, adding no probe instructions to small frames while large frames incur the required probe work, and leaves reporting to a signal disposition, instead of a stack-pointer check in every prologue.

Decision: On Darwin, a fourth once-per-process capability probe asks the resolved clang to compile a tiny function with a live large frame and `"probe-stack"="__chkstk_darwin"`; successful compilation selects that helper, rejection selects `"probe-stack"="inline-asm"` with `"stack-probe-size"="4096"`, and every generated definition and fragment retains the selected method, because the [bundled-toolchain study](../../research/investigations/bundled-toolchain/DESIGN.md#qualification-run) qualifies upstream 22.1.8's inline containment and Apple's maintained helper on arm64 macOS 15, while vendor strings do not establish the actual consumer's supported method, instead of inferring support from vendor/version strings, forcing either method on every Darwin compiler or suppressing probing. Non-Darwin target methods remain unchanged; a probe answer selects a method, not a new qualification of other architectures, LLVM versions or link modes.

Decision: The stack ledger's numbers come from a completed host compilation of the emitted module, its frame sizes read back with `-fstack-usage` and its call graph from the same compilation's assembly, plus a fixed per-architecture correction for the return address that report omits, because nowhere earlier has the numbers, a non-leaf's real cost being the ABI frame record and the spills the register allocator chose, and the uncorrected report once over-promised recursion depth by a factor of two on x86-64, the dangerous direction for a writer who believes it, instead of a frame estimate accumulated during target qualification or the uncorrected report.

Decision: The handle factory starts with 4096 descriptor credits on Windows and, on POSIX, the host limit capped at 2^20 before subtracting a reserve of 64 with a floor of zero; acquisition and explicit close update that capacity through an ordinary factory passed as a reference parameter whose declared row writes it, because scanning a possible million-entry descriptor table costs one host call per entry, the reserve leaves room for runtime descriptors, and the call-site pairwise check [EFF-5] already serializes the accounting, since no second path to the factory may be live at a call that writes it and no adjacent statement touching it may overlap [PAR-1], instead of a descriptor-table scan, an uncapped limit, or atomic permit credits; available capacity does not guarantee that a host acquisition succeeds.

Rejected:
- A stack-pointer comparison against a per-thread limit in every generated prologue: rejected because the check spends the headroom it guards, while native probing contains guard-crossing frames without that per-function check.
- Selecting Darwin's probe method from a vendor string or marketing version: rejected because those strings do not establish whether the resolved consumer can lower the helper; compiling a live large frame exercises that property directly.
- Retaining `__chkstk_darwin` for every Darwin consumer: rejected because upstream LLVM 22.1.8's AArch64 backend rejects the method; a future upgrade or patch needs its own qualification and is unnecessary for the qualified inline path.
- Requiring inline probing on every Apple compiler now: rejected because the maintained Apple helper passed the comparison, while Apple's inline method has not been qualified across its declared support matrix.
- Disabling stack probing to compile with upstream LLVM: rejected because an unprobed frame can cross the guard region and corrupt another mapping, and the qualification's ablated large frame must retain the host fault with no exhaustion record.
- Writing a Whitefoot Darwin probe helper: rejected because upstream AArch64 rejects helper methods before link resolution, and a custom helper would add unqualified pre-prologue register, unwind and deployment contracts without replacing that unsupported invocation.
- Spelling inline probing as `inline` or setting only `stack-probe-size`: rejected because upstream AArch64 accepts only `inline-asm` as a non-Windows method, and the interval attribute alone does not enable probing.
- Keeping the heap half as this node's own decision, that exhausting the heap the runtime supplies ends the process by a defined abort: rejected because [STOR-8] now states in the language that allocation is total in the source, that no allocating operation carries a `Result`, and that exhaustion terminates the program from the trusted base outside the language, so a compiler node restating it would own a language rule; what this node still owns is the record those terminations write.
