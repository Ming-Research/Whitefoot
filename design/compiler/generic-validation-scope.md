Decision: Symbolic validation, selector preflight and concrete checking use views over one structurally keyed, grow-only type and function inventory within a check, while symbolic entailment remains limited to the postcondition components of canonical generic bodies and, transitively, the callee components that contain a postcondition, and executable reachability selects lowering only, because retaining identities removes the [rollback and structural type mirror](../../research/investigations/compiler-architecture/DESIGN.md#p23-one-inventory-without-rollback) that currently force repeated construction, instead of discarding scratch identities and replaying bodies to reconstruct them. Bodies and analyses are reused only when their substitution, checking context and consumed callee claims agree; symbolic and concrete judgments remain distinct and every required source check remains mandatory. A callee component without a postcondition publishes no summary, so a judged body never reads its symbolic analysis, while a nongeneric one is analyzed again in the concrete phase; analyzing such components symbolically held about 36% of the proof work in Halo's `pkg::vm` check, as the [compile-speed record](../../research/investigations/compile-speed/DESIGN.md#candidates-and-selection) counts, instead of analyzing every component the canonical bodies reach.

Decision: A symbolic instance that is not a canonical generic body, and whose every argument is a distinct symbolic parameter of the kind, and for a const parameter the written integer type, its declaration's canonical instance has in that position, forms only its contract, admits the schema clauses the canonical instance admits, and takes the canonical instance's body disposition, invariant outcomes and postcondition proofs, while the postcondition schedule orders it after the canonical instance or into its component, instead of checking and analyzing its body again, because such an instance differs from the canonical one only by a one-to-one renaming of symbolic parameters, the specification checks a generic body once at its own symbolic instance, and a caller reads only the callee's contract and summary; an edge to the canonical instance keeps every component conjoining the outcomes of the same declarations, because an instance reaches a renaming of a declaration exactly when the canonical instance reaches that declaration. Checking those bodies again took 95% of the body-check time in Halo's `pkg::vm` check, where each interpreter helper was instantiated at about 85 symbolic shapes, as the [compile-speed record](../../research/investigations/compile-speed/DESIGN.md#candidates-and-selection) measures, and analyzing them again had made each helper be analyzed about forty times and exhausted 12 GB, as its [attribution](../../research/investigations/compile-speed/DESIGN.md#renamed-symbolic-instances) records. A symbolic instance whose arguments are distinct symbolic parameters of other kinds than the canonical instance's takes the body disposition, invariant outcomes and postcondition proofs of an instance of the same declaration, argument kinds and const parameters' written integer types already analyzed in an earlier postcondition component, or of the first such instance of its own level, after that analysis; a substitution that repeats a parameter or supplies a non-symbolic argument is checked and analyzed as before; a const parameter's written type bounds its symbolic value, which the analysis reads, so instances whose const arguments differ in type are not renamings of one another.

Decision: Symbolic publication starts from each canonical generic instance and admits every clause expressible at its selected shape, including measured results and exit-only clauses whose result type remains symbolic, because a generic caller needs its callees' verified summaries just as a concrete caller does. A compiler-owned window parameter alone waits until an operand supplies its shape, even if that shape's element or capacity is still symbolic; allocation layout queries likewise distinguish known results, known oversized ceilings and unresolved parameters, instead of deferring every obligation or clause merely because its enclosing function is generic. Each inhabited concrete instance still receives its own ordinary check.

Decision: Operand-directed generics use a fixed declaration table identifying which operand supplies each parameter and which type component it selects, with a type-only place walk followed by ordinary argument checking and existing deferred signature materialization, because the chosen window defines its element type and using a mismatched value argument to infer it would change the intended instance. The inventory walk includes newly materialized signatures, instead of adding a second ownership-sensitive type inference pass or keeping anonymous per-call signatures that lowering cannot resolve.

Decision: Keep written TYPE-9 placement checking distinct from post-substitution inline-storage checking: an explicit runtime-capacity shape must occupy the direct Box type argument, and formed own parameters and nominal fields or payloads are checked again for inline storage, because generic indirection can introduce a forbidden representation without writing that shape at the storage site. Reference parameters do not store their referent, and compiler-owned boxed row clauses receive only their specified implicit content projection, instead of using either written syntax or formed types alone to enforce both boundaries.

Decision: FN-4 refinement reuses S4/MSR-4/AUTO in isolated declaration-local queries with distinct entry, exit, result and routed-payload identities, retaining the premise and goal occurrences and each query's own derivation inventory, because implication needs the ordinary fixed proof families but its hypothetical premises must not become callable-body facts. Bound calls separately retain the actual executable target and instantiated formal acceptance/publication boundary; stronger actual clauses are visible only through the verified refinement of that boundary, instead of clause-set equality, identity sharing between independent queries or recovering the caller contract from the executable FunctionId.

Rejected:
- Replaced scratch-inventory decision and refusal of all nongeneric analysis reuse: rejected because the shared grow-only inventory retains identity across validation and concrete views; reuse still requires equal checking inputs, rather than assuming equal identity proves equal analysis.
- Reusing an analysis solely because its function id is unchanged: rejected because symbolic context and consumed callee claims can differ even for a shared declaration or instance.
- Excluding every nongeneric function from validation: rejected because a judged generic body can discharge an obligation only through a reachable callee's published postcondition.
- A second declaration-contract implication solver: rejected because S4/MSR-4/AUTO already fixes the admitted proof family; query-local identities permit reuse without sharing hypothetical premises with callable bodies.
- Enumerating every operand-directed instance over every shape named by a unit: rejected because multi-window operations create an unused cross product, while the ordinary body checker already discovers the selected operand types.
