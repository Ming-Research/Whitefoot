Decision: The command-line compiler offers one explicit formatting request, `--format` over the sources `--check` takes or over a module graph, which replaces every source whose bytes differ from its FORM-2 rendering and writes nothing when any input fails, while checking and compilation keep rejecting non-canonical input unchanged, because canonical bytes are fixed by the derivation the compiler already renders and a FORM-2 rejection names only the first differing gap and lists the others as changes the writer applies by hand, so a writer without the request repairs layout gap by gap, instead of formatting during acceptance or leaving formatting to a script outside the compiler.

Decision: The bytes the formatting request writes come from one library function that stops after grammar derivation and finalization, and the FORM-2 judgment shares its layout derivation while walking the derivation on its own, with a corpus test asserting for every corpus file that the judgment accepts it exactly when its rendering equals its bytes, because two layout derivations could drift and a formatter that ran semantic checking would refuse a program whose remaining faults are semantic, instead of a formatting path with a layout derivation of its own or formatting only accepted programs.

Decision: Graph formatting forms the module program the way `--check --graph` does, because only the graph and its package records name the source records to format, and any failure other than a source record's own lexical or grammar rejection is reported by rerunning the ordinary module loading on the original bytes, so the writer sees the diagnostic `--check` gives, instead of a second package walk that tolerates graph rule failures or diagnostics positioned in a rendering that was never written.

Rejected:
- Formatting during `--check` or compilation: rejected because FORM-1 makes non-canonical input a hard error so that the bytes a writer keeps are the bytes the compiler judged, and silently accepting other bytes would make acceptance depend on a rewrite the writer never saw.
- A formatter script in Whitefoot-kit or in each downstream project: rejected because it would reimplement the FORM-2 rendering outside the compiler and drift from it.
- Writing the canonical bytes to standard output instead of in place: rejected because a module program has many sources and the writer's next step is always to keep the canonical bytes, so in-place replacement with all-or-nothing writes serves that use without a multi-file output format.
