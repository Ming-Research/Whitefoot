# Origin transport

How a goal meets the facts proved about the expressions its bindings were defined from.

### decision goal-origin-expansion
A goal's disposition identifies value trees whose currently valid `let` origin expansions agree, in a finite query view that publishes no new flow fact.
- rejected: an agent proposed expanding only the submitted goal, publishing only facts known at the `let`, or keeping a runtime guard as another spelling of a proved proposition; the owner rejected it, because the parity and Boolean witnesses need proof both ways and after the binding.

### decision origin-links-ordinary-kills
Origin transport uses the existing live definition links, ordinary kills and intersection at joins, with shared expansion identities and one term view per existing Boolean tree.
- rejected: an agent proposed keeping an equivalence after it is killed; the owner rejected it, because a computed binding may outlive the storage value it read.
- rejected: an agent proposed enumerating partial expansions; the owner rejected it, because independent substitution choices would multiply the trees.
