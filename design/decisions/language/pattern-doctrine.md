# Pattern doctrine

How the language guides writers toward program architectures, and when a restriction on writers holds.

### decision writers-are-taught-a-closed-catalog
The language teaches writers a closed catalog of program architectures instead of fitting whatever architecture a writer brings.
- rejected: an agent proposed leaving program architecture unconstrained; the owner rejected it, because the writers are agents with no installed base to appease, so a closed catalog can be required as long as it stays complete, models every task and is efficient.

### decision a-restriction-needs-a-usable-alternative
A restriction on writers stands only with an alternative they can reach and evidence of its writing and run-time costs; a gap in the catalog is a finding to investigate.
- rejected: an agent proposed using the catalog as enforcement, a gap in it licensing a new rejection rule or an unrelated architecture; the owner rejected it, because patterns alone cannot meet the writer objective, and a restriction needs an alternative writers can use.

### decision guidance-yields-to-faster-safe-code
A guidance restriction is revised when it excludes a faster implementation that meets the safety and development-feasibility requirements.
- rejected: an agent proposed keeping guidance after its measured benefit is gone; the owner rejected it, because the constitution's performance objective outranks any one guidance mechanism.
