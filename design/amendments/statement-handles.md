Replaces the decision beginning "A shared object is one block of the context runtime's pool holding a header" with the one below, since a statement reached through a handle its caller lends no longer counts one of its own.

Decision: A shared object is one block of the context runtime's pool holding a header (handle count, lock word, holder count, parked and watching contexts) and then the state, an atomic statement on an object or a map counts a handle of its own before it acquires and releases it after it unlocks on every edge that leaves its block unless it reaches the handle through a reference parameter whose declared row writes nothing below it, and a handle's release drops the state and returns the block when it was the last, because the runtime every build links never calls the program's allocator [STOR-8] and a block may move or release the handle it was reached through, while a handle a caller lends for the call stays live until the statement completes, and the pair of updates on one count every driver's statements share took firn's depth-16 `SET`, `GET` and `INCR` on two drivers from 1.71 to 2.12, 1.71 to 1.89 and 1.63 to 2.00 million a second at the most ([stage (c)](../../research/investigations/concurrent-map/DESIGN.md#stage-c-firns-keyspace-on-the-shared-map)), instead of allocating objects with the program's heap, refusing a block that touches its target place, or counting a handle in every statement.
