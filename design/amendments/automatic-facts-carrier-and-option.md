Node: language/checks-and-proofs/automatic-facts

Decision: A value initializer's `give d;` edge delivers the receiver's equality to d when d is a bare integer term whose support survives the edge, and to d's value when d is an integer literal or integer-typed named constant, in addition to substituting the receiver for d in the relations that mention d, because `give length;` otherwise loses exactly the bound that `let bound = length; give bound;` delivers, so writers rewrote value initializers as duplicated returning branches, as the [writer-lost-facts probes](../../research/investigations/writer-lost-facts/DESIGN.md#shape-3-an-expression-form-if) show, instead of delivering only relations that already mention d and forming no image for a literal.

Decision: A local own Result or Option with an integer payload carries conditional evidence for its current success payload, `Ok` or `Some`, through ordinary binding, copying, moving, replacement and value delivery, its failure variant `Err` or `None` contributing a contradictory success context, and success selection or a forwarded-return judgment reads that evidence under its guard, because the matched examples in research/investigations/result-proof-transport/DESIGN.md lose the same verified relation merely by naming or propagating its value, and an Option is the same two-variant shape as a Result with a unit error, which writers adopted only to keep a payload bound, as the [writer-lost-facts probes](../../research/investigations/writer-lost-facts/DESIGN.md#shape-4-option-results) show, instead of a closed set of direct-call source shapes that forces writers to reconstruct equivalent values, or Result-only evidence that forces the unit-error detour. This replaces the node's decision beginning "A local own Result with an integer payload carries conditional evidence", which it extends to Option unchanged otherwise.

Rejected:
- Delivering the receiver equality by closure without the substitution: rejected because the closure has no rule carrying a disequality through an equality, so relations delivered today would be lost.
- A success route for every enum with one integer-payload variant: rejected because Option is the one reported consumer and, like Result, has one fixed success and one fixed failure variant.
