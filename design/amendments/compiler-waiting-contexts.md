Decision: A statement that finds its object held spins for a bounded time and then parks its context, an unlock wakes the first parked statement to try again, which keeps its place at the queue's head if it misses again, and the unlock after two such vain wakes hands it the object, because a holder's block cannot wait, so a holder is always running and finishes within its block's compute, while handing every parked statement the object left it held by a context no driver was running and made 97 percent of the Redis subset's pipelined acquires park on two drivers, against 0.6 percent with retries ([Experiment 7](../../research/investigations/io-model/SHARED.md#the-acquire-without-a-convoy-results)), and the bound keeps a statement from being overtaken without end, which [SHARE-3]'s promise that a statement whose guard stays true takes effect rules out ([handoff](../../research/investigations/io-model/SHARED.md#progress-while-a-guard-waits)), instead of a first-come handoff that keeps strict arrival order or retries without a bound.

Decision: A context start lowers to a synthesized wrapper that makes the call and releases its result, whose frame and argument block the new context's arena holds, with a join before every exit of the starting activation that suspends the starting frame until the activation's contexts have finished and no path that runs the call inline, and the compiler starts one for every marked waiting call and for every unmarked call the permission covers whose callee may reach an atomic statement with a guard, which a fixed point over the checked bodies finds, because [SHARE-3] requires such a call to execute as a context while its guard waits and the marker is erased proof syntax, while an unmarked call that reaches no guard keeps running in order, so a program without guards starts no context it did not mark ([design](../../research/investigations/io-model/SHARED.md#progress-while-a-guard-waits)), and running the call inline would wait for it, instead of reusing the compute lanes, which refuse an offer by running it on the caller, starting every call the permission covers, or promoting a call to a context only when its guard first waits.

Decision: A bound waiting `let` lowers to a start whose wrapper returns the call's result into a slot of the starting frame and a join of that one context before the first later statement of the `let`'s block that may leave the block or that names the binding in an expression, set target or statement it holds, or whose resolved footprint reaches the binding, and otherwise at the block's end, because every read, write, release and reference formation of the binding names it, so the join precedes every use, while [SHARE-3] lets the starter wait for the call nowhere earlier, so a loop, a match or an atomic statement that names nothing the call holds proceeds alongside it ([design](../../research/investigations/io-model/SHARED.md#progress-while-a-guard-waits)), instead of joining at the next statement, which serializes a gather, joining inside the using statement on the path that reaches the use, which leaves later code a joined and an unjoined path to merge, or joining before every statement whose overlap footprint is refused or not resolved.

Rejected:
- Replaced decision beginning "A statement that finds its object held spins for a bounded time and then parks its context, and an unlock wakes": rejected because a statement it woke could miss the object at every retry, and [SHARE-3] now promises that a statement whose guard stays true takes effect; the retry stays and gains a bound.
- Replaced decision beginning "A context start lowers to a synthesized wrapper": rejected because its policy started only marked calls, so an unmarked call whose guard waits for a later statement of its starter held that starter, which [SHARE-3] rules out; the lowering stays and the set of calls it starts grows.
- Replaced decision beginning "A marked waiting `let` lowers to a start": rejected because it joined before every statement whose overlap footprint was refused or not resolved, a loop, a match, an atomic statement or a read through a Box among them, so a starter waited for a context whose guard only that statement would make true, which [SHARE-3] rules out.
- Starting every call the permission covers as a context: rejected because a program without guards would then start contexts it never marked, a change of cost with no change of meaning; reopen if a measurement shows that starting them is free.
- Promoting a call to a context when its guard first waits: rejected because every call site that might need it would carry both an inline and a started continuation, while which callees may reach a guard is known once the bodies are checked.
