Node: language/ownership/reference-validity

Decision: A reference names a path that starts at a local variable, a parameter, or a named constant and continues through fields (a heap cell's content being its field `inner`), an explicit reference step written with `->`, an index, a range, or the payload of an enum variant, and the reference variable is not storage of its own, so forming a reference to a reference variable is refused and extending a reference names the longer path rather than pointing at the reference, because a name for a path holds no address a program could copy or alias and can always be formed again, instead of a pointer value with an identity of its own.

Decision: Reference access in ordinary and proof places uses `p->field`, `p->[index]` or standalone `p->`, including payload and range selections, while Box `.inner` and effect selectors retain their meanings, because the [arrow comparison](../../research/investigations/contract-surface/OWNERSHIP.md#recommendation-awaiting-ruling) preserves explicit indirection and forward path composition with arrow member selection, provisionally accepting the unfamiliar standalone form for that uniformity, instead of `deref(place)`, `.*`, automatic projection, or a separate whole-referent spelling; each path has one spelling.
