Node: language/ownership/reference-validity

Decision: A reference names a path that starts at a local variable, a parameter, or a named constant and continues through fields (a heap cell's content being its field `inner`), an explicit reference step written with prefix `*` or a `->` selector, an index, a range, or the payload of an enum variant, and the reference variable is not storage of its own, so forming a reference to a reference variable is refused and extending a reference names the longer path rather than pointing at the reference, because a name for a path holds no address a program could copy or alias and can always be formed again, instead of a pointer value with an identity of its own.

Decision: Reference access in ordinary and proof places uses `p->field` or `p->[index]`, including payload and range selections, and `*p` for the whole referent, while Box `.inner` and effect selectors retain their meanings, because the [arrow comparison](../../research/investigations/contract-surface/OWNERSHIP.md#observations-and-comparison) keeps explicit indirection and compact member access without the unfinished appearance of standalone `p->`, provisionally preferring that readability over a uniform postfix step, instead of `deref(place)`, `.*`, standalone `p->`, or automatic projection; each path has one spelling.
