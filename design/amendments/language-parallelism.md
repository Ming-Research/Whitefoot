Node: language/parallelism

Decision: A program means its sequential execution, and an implementation may execute an expression statement whose callee waits alongside the statements after it, as a context of its own that completes before the activation leaves by any edge, exactly when every parameter of the callee is a value parameter and its result can be dropped, because the call then shares no storage with those statements other than shared objects, which both reach only through atomic statements whose order is already an input of the execution [SHARE-3], so running it early changes only when its host effects and its atomic statements take effect, which host-effect order and that input already leave open [HOST-1], and one path-disjointness judgment then authorizes every concurrency the implementation adds ([design](../../research/investigations/io-model/WAITS.md#the-program-means-its-sequential-execution)), instead of a marker that starts a context and promises that it progresses while its starter waits.

Rejected:
- Replaced decision beginning "A program means its sequential execution, and an implementation may execute an expression statement": rejected because its reason, that the call shares no storage with the statements after it, no longer holds once a handle to one shared object can be passed to the call and kept by its starter; the choice stands with the reason restated.
- A marker whose meaning is that a context must start, with a guarantee that it progresses while another context waits: rejected because a sequential execution of the same program already conforms, including one in which a statement waits for good on a guard that only a later context's statement would make true, as a peer that never answers leaves a receive waiting, so the guarantee would add a second meaning and tie the language to one implementation; the runtime's drivers give that progress as a property of this compiler.
