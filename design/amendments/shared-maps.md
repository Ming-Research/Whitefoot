Node: language/waiting/shared-objects/shared-maps

Decision: State that many contexts reach by key is a shared map held through `SharedMap<V>` handles, keyed by byte strings, whose entry under a key is an `Option<V>` reached only inside a keyed statement `atomic e = &m[key] { ... }` that holds that one entry exclusively and takes effect at one point, statements on one key taking effect in one order and statements on different keys waiting for none of each other, because a keyspace behind one `Shared` object serializes every client of a server on one lock while one statement form serves every single-key command with no library function and no callback ([design](../../../../research/investigations/concurrent-map/DESIGN.md#stage-b-the-language-surface-stated-before-building)), instead of a library map behind a `Shared` object or a family of map operations taking a callback.

Decision: A key is a `&[u8]` the runtime hashes and compares, because the runtime would otherwise call the writer's hash and equality under a cell's lock in the middle of a probe, and the index's correctness would then rest on a protocol no admission checks, while byte strings are what a server's keys are and a key is named as a range of its input without building one, instead of a key of any type with a `HashMapKey` binding or integer keys only.

Decision: A whole-map statement `atomic s = &m { ... }` holds every entry, binds `&SharedMapState<V>`, the map's state, which `shared_map_count` counts exactly, and reaches entries inside its block through `atomic e = &s^[key] { ... }`, which waits for nothing and counts as no call, because commands over several keys (`MSET`, `DEL` and `EXISTS` of several) and an exact count need one point for all of them, and every keyed statement pays one store on its own thread's cache line to be excluded, instead of a statement over a list of keys taken in an order the runtime fixes, which needs a type for a list of keys and a binding over several entries and is deferred until a workload shows the whole-map statement's exclusion costing.

Decision: The block of a keyed or whole-map statement contains no call to a waiting function, and of atomic statements only those on a `Shared` object, with no guard, and in a whole-map block those on its own entries, because entries and maps are then always taken before objects and an object's holder takes nothing, so no cycle of waits can form, while an append-only record of a change is made in the same step as the change; a guard there would wait while the entry is held, instead of admitting guarded statements and a deadlock no rule excludes.

Decision: Provisionally, every keyed statement holds its entry exclusively whether its block reads or writes, because a block runs once and cannot be run again after a torn read of a value larger than a word, so the index's lock-free read serves no statement yet, instead of a read-only form running beside others; reopened by a workload whose readers of one key contend, such as the benchmark's `LRANGE` tests.

Decision: The handle is `SharedMap<V>` and its state `SharedMapState<V>`, because `SharedMap` parallels `Shared<T>` for the one-object case and a prelude name always displaces a source declaration of the same spelling [PRE-1], so the state takes a spelling no program is likely to declare: the first name, `Keyed`, displaced a declaration in firn, instead of `Keyed<V>`, or `ConcurrentMap` or `ShardedMap`, which name an implementation.

Rejected:
- A key of any type with a `HashMapKey` binding: rejected because the runtime would call writer code under a cell's lock in the middle of a probe.
- A map sharded into `Shared` objects, each a lock and a table: rejected because the index the runtime keeps reads without locking and locks one entry per write, which led or tied every measured cell against the fastest comparators ([measured](../../../../research/investigations/concurrent-map/DESIGN.md#measured)), while shards serialize unrelated keys that share a shard.
- An object statement with a guard inside a keyed or whole-map block: rejected because it would wait for its guard while the entry or map stays held, which no rule could keep from deadlocking.
