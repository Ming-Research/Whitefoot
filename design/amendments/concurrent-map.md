Node: compiler/waiting-contexts/concurrent-map

Decision: The runtime keeps one concurrent hash index in C, linked into every program, with 16-byte cells of a key word and a value probed linearly, a writer locking its key's cell by one compare-and-swap on the key word's top bit and a reader of a word-sized value taking no lock, because a Whitefoot statement's block runs once with its entry held, which a lock gives and an optimistic update that may run twice does not, and this layout led or tied every cell of the fourth duel against growt, DashMap and the other comparators ([cell design](../../../research/investigations/concurrent-map/DESIGN.md#the-cell-design), [measured](../../../research/investigations/concurrent-map/DESIGN.md#measured)), instead of cache-line buckets with a ticket lock, which lost nine cells of the first duel, or an index written in Whitefoot, which the owner placed in the trusted runtime.

Decision: A table moves once half its cells are used, one writer making the next table and writers that meet the move copying blocks into it, a writer checking for a move after it locks its cell and a mover publishing the move before it reads a cell, all sequentially consistent, and each user publishes the table it works in so that a moved table is freed once no user is in it and the newest freed table's cells are kept for the next move to their size, because the mover then only reads the old table, which took single-thread `grow` from about 9.5 to 12.6 million a second, and a map whose size holds steady moves between warm tables, 12 ms against 111 ms for 2^22 cells at four threads ([cell design](../../../research/investigations/concurrent-map/DESIGN.md#the-cell-design)), instead of marking every cell moved or rebuilding under a global lock.

Decision: A map of entries keeps each key's bytes and a slot for its `Option<V>` in a node from the map's per-user chunks, with the key's hash in the cell's key word and the node's address in its value word, and a probe compares full keys only after it has locked a cell of the same hash, because a node is then freed only under its cell's lock and no probe reads a freed node, and a move copies addresses, so an entry stays where a statement's binding names it, instead of storing keys in the cells, which would make a cell's size depend on the key.

Decision: A writer that finds an entry's key absent claims the first removed cell its probe passed, or else the empty cell that ended the probe, marks the claim pending and keeps it only after reading the rest of the key's run of cells, giving way to a cell of the key found there and to an earlier pending claim of the same hash and waiting out a later one, because a removed cell otherwise stays until the table moves, so a key missed again and again left a removed cell per miss in front of the next probe (`SPOP` on an emptied key in firn fell from 53,000 to 8,000 a second over five rounds of 40,000, and answered about 159,000 in every round with reuse), while a reused cell can lie behind another writer's claim of the same key, which a claim that looked only ahead of itself missed ([stage (c)](../../../research/investigations/concurrent-map/DESIGN.md#stage-c-firns-keyspace-on-the-shared-map)), instead of keeping an emptied key's cell and node as an entry whose slot is empty until the next move, which changes when nodes are freed and holds a node per distinct missed key.

Decision: A program's drivers are a map's users, numbered by driver, a driver thread keeps the one entry its running statement has locked, and a statement that finds its entry or map held waits in the runtime without parking, because a statement holding an entry or a map never suspends, its block containing no call to a waiting function, so it ends on the driver it began on, and a holder always runs to its block's end, instead of a user per context or parking with the key word's second bit marking waiters, which comes with bounded overtaking for entries ([todo](../../../docs/todo.md)).

Decision: An object statement inside a keyed or whole-map block takes its object by spinning, and when an unlock has handed the object to a parked context that has not yet resumed, takes that hold back, the context asking again from the head of the queue when it resumes, because the statement's driver must keep running the block that holds an entry, and the context handed the object may wait in that very driver's queue, so spinning for it would never end, instead of parking inside the block, which would leave the entry held while other contexts on the same driver spin for it; the take-back can deny a parked statement the object each time it is handed over while such statements keep arriving, which weakens the handoff bound of compiler/waiting-contexts for objects also reached from map blocks, to be closed with bounded overtaking for entries ([todo](../../../docs/todo.md)).

Decision: The index takes its small blocks from the context runtime's pool and maps cell arrays of 2 MiB or more, and entry chunks, from the host itself, advising huge pages, because the runtime every build links never calls the program's allocator [STOR-8] and a random probe in a large table otherwise pays a page walk on most accesses, 127 against 105 million uniform reads a second at four threads ([cell design](../../../research/investigations/concurrent-map/DESIGN.md#the-cell-design)), instead of the program's allocator or 4 KiB pages.

Rejected:
- Cache-line buckets of three keys with a ticket lock doubling as the read version: rejected because a branch on the matching slot mispredicted on most lookups and the buckets held 2^20 keys in 41.9 bytes a key against growt's 32.4, and the first duel led one cell, tied eight and lost nine ([first design](../../../research/investigations/concurrent-map/DESIGN.md#the-first-design-and-why-it-was-replaced)).
- A writer that yields the processor while its key is locked: rejected because one-key `update` at four threads stayed between 6 and 16 million a second against about 24 with a doubling pause count ([cell design](../../../research/investigations/concurrent-map/DESIGN.md#the-cell-design)).
- An emptied key's cell and node kept as an entry with an empty slot until the next move: rejected because a node would then be freed by the mover rather than under its cell's lock, and every distinct missed key would hold a node until the next move.
- A claim of a removed cell that looks for another claim of its key only between itself and the next empty cell: rejected because a writer that passed a cell before it was removed claims a cell after it, so two writers of one key held two cells, which a churn of six keys sharing one starting cell caught in each of seven runs ([stage (c)](../../../research/investigations/concurrent-map/DESIGN.md#stage-c-firns-keyspace-on-the-shared-map)).
- Every writer that crosses the threshold allocating its own next table: rejected because at four threads each cleared a fresh 128 MiB table on this host, 1.4 to 2.3 s each ([fresh memory](../../../research/investigations/concurrent-map/DESIGN.md#this-hosts-fresh-memory)).
