Node: language/parallelism/loop-permission

Decision: A counted loop admits at most one accumulator from a fixed associative set and enclosing accesses through one proved constant-coefficient affine element map per resolved root, an access being any write, read or borrowed argument whose place is at or below the mapped element through fields, payloads, cell contents, further subscripts and ranges, or through disjoint subranges of an adjacent stride partition with invariant runtime stride and base, consuming retained source proofs, because everything below one element is storage that element alone owns, aggregates holding only owned values and a cell having one owner, so a loop that writes a field of its own item, hands its item to a writing helper or fills a buffer its item owns is as independent as one that replaces the whole item ([segmented storage](../../../research/investigations/segmented-storage/DESIGN.md#selected-design)), instead of arbitrary scatter, unbounded multi-accumulator reductions, restricting writes to element maps, or an element family of direct subscripts only. Whole-source access to mapped or assigned storage and incompatible maps on overlapping storage deny permission. This replaces the node's decision beginning "A counted loop admits at most one accumulator".

Rejected:
- An element family of direct subscripts only: rejected because a loop that writes one field of its own element, `set a^[i].n = i`, or passes its element to a writing helper was denied although it writes only element i, which made Snowghost's layout prototype keep per-item results in separate arrays.
- Admitting field paths and element borrows but not paths through an element's cells: rejected because buffers owned by their items are common in a renderer, and a cell's single owner already separates them.
