Decision: Halo represents configured CJSON methods as heap closures with a reserved no-prototype sentinel and checked closed captures of the builtin ID and full configuration index, because extracted methods need heap-traced function identity, captures keep binding data with the closure through collection and handle reuse, and separate instance data preserves every host-function ID and the entire configuration-index width, instead of packing instance bits into the prototype word or keeping binding records in a VM registry whose lifetime can diverge from recycled closure handles. This is provisional against an explicit native heap-closure variant: the [closure binding assessment](../../research/experiments/halo-luacodecs/README.md#closure-binding-assessment) identifies it as viable and reopens the choice when another stateful native library needs a different payload or native execution needs Lua callbacks; instance configuration reclamation remains incomplete.
