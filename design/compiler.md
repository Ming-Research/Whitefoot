Decision: The compiler remains one safe-Rust research crate with private evolving interfaces, while compiler-version-private persistent query results retain checked work across invocations through the same semantic path and ordinary final native linking, because the [modular-compilation design](../research/investigations/modular-compilation/DESIGN.md) supplies a concrete consumer for retained verification and optimized objects without requiring a stable artifact ABI or independent proof replay, instead of repeating all semantic work before splitting LLVM output or constructing a product-grade artifact protocol before a consumer exists.

Decision: Acceptance and proof discharge follow the specification's numbered rules alone, through one semantic path, and a mechanism's domain is defined by a rule and never by a program: every acceptance or discharge names the rule it applies and, on failure, the first missing fact or first failed premise, so a mechanism that can only answer matched or not matched is a recognizer whatever pattern it matches, while lowering may select a faster form by a recognized shape provided every shape has a correct lowering and the selection changes no acceptance or proof, because a capability implemented by recognizing a particular program is a special case the language does not define, silent about the next program and about what is missing, and a second acceptance path would let tests and corpora define the language in place of the specification, instead of pattern matchers whose domain is the corpus in hand or a second acceptance mode.

Decision: Valid specified source that the compiler has not implemented stops as an explicit unsupported capability and is never reported as invalid source, because a compiler gap reported as a language rejection rewrites the language from the implementation side, instead of misreporting unsupported source as invalid.

Decision: A rejection names the numbered rule it violates and the location, one compiler executable rejects the same source the same way every time, and no acceptance path depends on a timeout, fuel, a work budget, heuristic early failure, or hash-iteration order, while the order in which violations at distinct nodes are reported is not part of the language, a node's own violations being reported in rule-definition order, because a writer acts on a rule and a location, acceptance that depends on time, budget, or iteration order is acceptance by accident, and two correct checkers may legitimately meet different first violations, instead of a portable first-error order or budgeted checking.

Decision: The runtime every compiled program links, the compute scheduler, the completion runtime, and the exhaustion floor, is plain C reviewed by hand and lies outside the crate's safe-Rust guarantee, because it is target code that speaks the host's threads, rings, and ports directly, and this research compiler and its runtime will be replaced by self-hosted ones, so a checked runtime language or a confinement policy now is work that buys nothing while ordinary engineering quality stays required, instead of a memory-safety-checked runtime language or a stated unsafe-confinement policy.

Decision: The mandatory source-positioned obligations that the ownership and parallel-permission judgments consume, the index and range separations [OWN-7] asks for and both sign goals of a counted loop's retained range images [PAR-2], are submitted to the existing flow ProofContext at the source node that owns them, and their successful derivations are retained as ordinary roots of the same derivation ledger every other discharge uses, because the specification now fixes what those proofs say and what must be retained but not which checker component runs them or where their results live, and one ledger is what lets the permission consumer read a proof the ownership consumer has already discharged, instead of a second range solver in the structural checker, a target-side overlap test, or a permission-private record of retained results.

Decision: A WF body and a linked body with the same ordinary signature use one callable ABI and the same permission path, with native engines confined to implementation inside that call, because choosing a native implementation cannot change source acceptance, effect overlap or reference validity [REF-2], instead of qualification tables, special system-call emission, suspension summaries or early source-reference invalidation.

Rejected:
- A source acceptance tripwire maintained by a hand-checked native qualification version: rejected because ordinary declarations and link-selected implementations have no separate system domain to qualify.
- A source staged-loop permission selected by a native operation or suspension classification: rejected because ordinary call and loan boundaries must apply equally to source and linked bodies.
- A product-grade checked-artifact toolchain with stable crate boundaries, serialized artifacts, and replay: rejected because it multiplied crates and gates before a resolver or backend existed and imposed protocols that had no consumer.
- Hardening the frontend against hostile input and re-verifying a previous stage's result inside the trusted path: rejected because this compiler exists to iterate the language and will be replaced by a self-hosted one, so defense in depth here is work that buys nothing, while ordinary engineering quality stays required for fast iteration.
- Superseded system-inventory states kept reachable behind compile-time switches so that a differential test can show an earlier program's module unchanged: rejected because the compiler implements exactly one specification, the active one, so a switch that reconstructs a superseded inventory has no consumer and only adds code paths to maintain.
- The proof tier's first elision mechanism, a base64 recognizer as its sole authority, matching the 3:4 capacity relation and the i+=3/o+=4 induction: rejected because it proved all 27 base64 sites and refused every hostile variant correctly and still had to be replaced the same day by obligations derived from the body, since its domain was one program, it could not say what was missing when a site did not match, and no rule of the specification corresponded to it.
- Keeping the retired adjacent-range image algorithm as a compiler-selected proof family: rejected because PAR-2 now defines that family in the specification; the compiler still chooses the shared proof context and retained-evidence representation.
- Preserving callee-result view tracking: rejected because references cannot be returned under REF-3; incoming reference origins now follow REF-1 and EFF-5, with the representation owned by compiler/checker-facts.
- Replaced first compiler decision beginning "The compiler is a research instrument for iterating the language": rejected because its artifact boundary does not yet distinguish the requested version-private persistent results from the refused product protocol; its safe-Rust crate, research purpose, private interfaces and refusal of stable artifact/replay/release infrastructure remain in force.
- A separate incremental checker beside the clean checker: rejected because cache state must affect reused computation, not which semantic rules decide acceptance.
