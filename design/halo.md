Decision: Halo is a Lua 5.1 engine written in Whitefoot with an embedding interface, its own package in `lib/halo` that firn binds, because Redis scripts are written against Lua 5.1 and firn's deployment needs `EVAL`, and an engine in Whitefoot keeps the script runtime under the language's guarantees ([purpose](../research/investigations/halo/DESIGN.md#purpose)), instead of embedding a native Lua engine through a host binding.

Decision: Halo's source never names Redis: firn supplies `redis.call`, `KEYS`, `ARGV`, the reply conversions and the script cache, and the codecs Redis scripts use live as general packages in `lib/json` and `lib/msgpack`, bound by Halo's `cjson` and `cmsgpack` libraries, because the engine and the codecs are to stand as projects of their own apart from firn, instead of an interpreter specialized to Redis.
