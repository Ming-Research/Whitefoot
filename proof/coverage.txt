# The model's sentence coverage of the specification, checked by
# `lake exe coverage` in this directory on every change to the specification
# or the model.
#
# `rule ID` covers a rule: every line of its text must be marked as modeled by
# a `-- spec ID HASH` comment above the Lean definition that formalizes it, or
# be listed here as `outside ID HASH reason`. `family P` requires every rule
# whose ID starts with `P-` to have a `rule` or a `skip ID reason` entry, so a
# new rule in a covered family is classified before it merges. HASH is the
# 64-bit FNV-1a hash of the line's bytes in hexadecimal; blank lines and
# code-fence lines carry none. `lake exe coverage --show ID` prints a rule's
# lines with their hashes and dispositions. `WhitefootProof.lean` must import
# every source file under `WhitefootProof/`, so that each mark sits in a module
# that is built and whose declarations the axiom check reads.
#
# A change that edits a covered line changes its hash: the check then names
# the line, and the change updates the model, its proofs and this list.
